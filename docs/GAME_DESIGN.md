# ElondiaRPG 遊戲設計 v0.2

> 狀態：第一個可遊玩版本已實作（Vue 3 網頁版）。數值仍為提案，見文末「待決定事項」。

## 1. 核心概念

玩家透過 **UI 介面**（按鈕、清單、地圖）決定行動，**遊戲引擎**負責所有數值運算與判定。每次行動、事件或戰鬥結束後，引擎輸出一份**結構化報告**，再交給 **AI 敘事器**寫成小說式的事件經過。

```
┌──────────┐  玩家操作   ┌────────────┐  報告 JSON   ┌────────────┐  敘事文字   ┌──────────┐
│  UI 介面  │ ──────────▶ │  遊戲引擎   │ ───────────▶ │  AI 敘事器  │ ──────────▶ │ 日誌/閱讀 │
└──────────┘             │ (唯一真相)  │              │ + 世界書注入 │             └──────────┘
      ▲                  └────────────┘              └────────────┘
      └──────────── 狀態更新（金錢、HP、物品、親密值…）───┘
```

### 設計原則

1. **引擎是唯一真相。** 擲骰、傷害、金錢、經驗、親密值都由引擎決定並寫進報告。AI 只描寫，不改數字、不改結果、不新增物品。
2. **報告即事件紀錄。** 每個動作都產生一份報告，並透過 `commitReport` 把 `changes` 套用到遊戲狀態。存檔直接保存狀態本身（含亂數種子與所有報告），不靠重播報告來還原。
3. **AI 失敗不影響遊戲。** 敘事生成失敗或玩家關閉 AI 時，仍可用報告本身（時間軸＋結果）顯示一份簡易戰報，遊戲照常進行。
4. **世界書是設定來源，不是執行邏輯。** 世界書原本為 SillyTavern 聊天角色扮演設計（讓 AI 自己追蹤狀態欄、親密值）。在本遊戲中，這些規則改由引擎實作，世界書只負責提供敘事用的背景知識。

## 2. 遊戲迴圈

```
城鎮（公會 / 商店 / 旅店 / 酒館）
  ├─ 接取委託 ──▶ 移動（旅行報告）──▶ 冒險區域（探索 / 戰鬥報告）──▶ 返回交付（任務報告）
  ├─ 購物、休息、學習技能（交易 / 休息報告）
  └─ 與 NPC 互動（社交報告，影響親密值）
```

時間以「遊戲日」推進。旅行、任務、休息都會消耗天數，食宿與補給會消耗金錢，讓世界書的路程與物價產生實際意義。

## 3. 系統對照（世界書 → 引擎）

| 世界書條目 | 引擎中的實作 | 資料檔 |
|---|---|---|
| 區域地理地標相對位置、世界地圖 | 地點圖＋路線天數，旅行時計算耗時與遭遇 | `data/world/geography.json` |
| 力量體系／等級成長規則 | 等級 1–20、五個生命層級、魔法環階／武技境界／信仰階位 | `data/rules/progression.json` |
| 冒險者公會等級制度 | 公會階級 F–S、接任務限制、晉升條件 | 同上 |
| 技能規則／技能獲取 | 技能品質上限受生命層級限制；升級三選一 | 同上 |
| 職業體系規則 | 10 個職業及其力量來源 | 同上 |
| 分階段親密值規則 | 每個 NPC 一個 -100～100 的隱藏數值，引擎計算、AI 只呈現態度 | 同上 |
| 角色扮演指導（四層判斷） | 引擎先算出「實力差 → 立場 → 性格 → 親密值」後的態度，寫進報告 `attitude` 欄位 | 同上 |
| 價格參考-貨幣／食宿／任務報酬 | 以銅幣為單位的價格表；報酬範圍 ±50% 隨機 | `data/rules/economy.json` |
| 其餘價格參考、種族、神祇、巨龍、區域細節 | 不需引擎邏輯，作為敘事背景注入 | `data/worldbook/elondia.worldbook.json` |

### 3.1 戰鬥（已實作）

**逐回合手動操作，戰鬥結束後才產生戰報。** 規則在 `src/engine/combat.ts`，數值在 `data/rules/combat.json`、`skills.json`、`enemies.json`。

- 先攻：`1d20 + 熟練加值` 決定行動順序。
- 輪到隊員（主角與 NPC 隊友）時由玩家選擇：攻擊、技能、防禦（AC +4 一回合）、撤退（`1d20 + 熟練` ≥ 12，全隊脫離）。
- 命中：`1d20 + 攻擊加值 ≥ 目標 AC`；骰出 20 為爆擊（傷害骰加倍），骰出 1 為大失敗。
- 敵人由簡單 AI 控制：隨機選目標，40% 機率使用技能，HP 低於 1/4 時可能逃跑。
- 狀態：中毒（回合開始受傷）、纏繞（跳過回合）、鼓舞（命中 +2）、破綻、防禦。
- 戰後：經驗值由全隊平分，倒下的隊員以 1 HP 歸隊；戰敗會損失 10% 金錢。NPC 隊友會依並肩獲勝、被主角治療、自己倒下等事件調整親密值。
- 升級時從符合生命層級品質上限的技能中隨機給三個選項，玩家在「隊伍」頁三選一。

### 3.1.1 隊伍與 NPC 招募（已實作）

- 酒館可招募 NPC（`data/world/npcs.json`），隊伍上限 4 人。
- NPC 帶有性格描述與隱性親密值；報告中的 `attitude` = 實力差基準態度 + 親密值階段，`personality` 交給 AI 演繹。

### 3.2 旅行（已實作）

- 以 `geography.json` 的路線圖做最短路徑；`days` 為 `[最少, 最多]`，實際天數在區間內以半天為單位擲出。
- 官道每人每天 15 銅（食宿），其他路段每人每天 1 份乾糧，沒乾糧會挨餓扣 HP；海路每人每段 50 銅船資。
- `mode` 決定旅途事件的機率與種類（天候檢定、遭遇行商等）。目前旅途事件都不是戰鬥；遭遇戰需要中斷旅程，之後再做。

### 3.3 城鎮（已實作）

旅店（HP/MP 回滿）、雜貨店（乾糧）、酒館（招募）、冒險者公會（委託）。公會會為 7 天路程內的冒險區域各發一個「清剿 N 次」的委託；只清剿 1 次的委託取冒險區域難度下限，2 次以上取上限。接取規則依世界書：同級或更低，組隊時可接高一級。

## 4. 報告格式

完整定義見 [`schemas/report.schema.json`](../schemas/report.schema.json)，範例見 [`examples/reports/`](../examples/reports/)。

| 欄位 | 用途 |
|---|---|
| `kind` | `travel` / `combat` / `action` / `event` / `quest` / `rest` / `trade` / `social` |
| `time` | 開始與結束的遊戲時間（第幾天、幾點） |
| `location` | 地點 id、目的地、細部場景、天氣 |
| `party` / `others` | 事件前後的角色快照（HP 為 `[前, 後, 上限]`）、NPC 性格與態度 |
| `timeline` | 依序的關鍵節拍：誰、做了什麼、擲骰、結果、效果 |
| `outcome` | 總結果＋一句話摘要 |
| `changes` | 所有狀態變化：金錢、經驗、升級、技能、物品、親密值、聲望、劇情旗標 |
| `narration` | 給 AI 的敘事指示：視角、長度、語氣、重點、玩家意圖 |
| `lore_keys` | 用來挑選世界書條目的關鍵字 |

## 5. AI 敘事管線

```
報告 JSON
  │
  ├─ 1. 挑選世界書條目
  │     - constant 條目中屬於「世界觀／種族／神祇」的固定注入
  │     - 其餘條目：lore_keys + 報告中出現的地名、NPC 名，比對條目的 key 陣列
  │     - 依 order 排序並裁切到 token 上限
  │
  ├─ 2. 組合提示詞
  │     system：敘事器角色、文風（世界書「視角和文風條目」）、硬性規則
  │     user：  世界書片段 + 報告 JSON + 輸出要求
  │
  ├─ 3. 呼叫模型（串流顯示）
  │
  └─ 4. 輸出檢查（可選）
        - 比對文中是否出現報告沒有的物品、金額、死亡等
        - 不符時重寫或標註
```

### 敘事器硬性規則（草稿）

- 報告中的結果、數值、物品、死亡與否不可更改；不可新增報告沒有的戰利品或傷亡。
- 親密值不可寫出數字，只能透過語氣、動作與距離感呈現（世界書規定為隱性規則）。
- 擲骰與 DC 不出現在正文中，改以描寫呈現（例如爆擊 = 精準致命的一擊）。
- 依 `narration.pov` 決定視角，預設第二人稱「你」；玩家名稱用 `{{user}}` 代入。
- 只輸出正文（可附一行摘要），不輸出世界書原本要求的 `<thinking>`、狀態欄等聊天用模組——這些資訊已由 UI 顯示。

### 世界書條目的處理建議

| 條目 | 建議 |
|---|---|
| 核心：格式規範、高人指點版 COT | **不注入。** 這是聊天角色卡用的輸出格式與思考鏈，與本遊戲的「引擎管數值、UI 顯示狀態」衝突。 |
| 分階段親密值、冒險者公會、力量體系、技能、職業、等級成長 | **改為引擎邏輯**，注入時只放精簡版讓 AI 理解稱號與境界名稱。 |
| 角色扮演指導 | 前兩層（實力差、立場）由引擎計算；後兩層（性格、親密值）以 `attitude`＋`personality` 交給 AI 演繹。 |
| 視角和文風條目 | 保留，但把寫死的玩家名「沈頤」改為 `{{user}}`。 |
| 敘事傾向與事件觸發機制 | 若保留，應由**引擎**的事件產生器實作「引力值」與觸發機率，AI 只負責描寫被選中的事件。 |
| 區域、種族、神祇、巨龍、價格參考 | 保留為關鍵字觸發的背景知識。 |

### 5.1 AI 服務（已實作）

玩家在「設定」頁自行輸入 API key，key 只存在瀏覽器的 localStorage，請求直接從瀏覽器送出（`src/narrator/providers.ts`）。支援四種格式：

| 格式 | SDK | 備註 |
|---|---|---|
| Anthropic（Claude） | `@anthropic-ai/sdk` | 預設 `claude-opus-5-5`；支援的模型自動開啟伺服器端拒絕備援（`fallbacks: "default"`） |
| OpenAI | `openai` | |
| Google Gemini | `@google/genai` | |
| OpenAI 相容格式 | `openai`（自訂 Base URL） | 內建 OpenRouter、DeepSeek、Ollama、LM Studio 預設網址；本機服務可不填 key |

各家 SDK 都是用到時才載入。「載入模型清單」會向服務查詢可用模型，也可以當作連線測試。成人向世界書條目預設不注入，需在設定中手動開啟。

## 6. 專案結構

```
assets/map/           世界地圖
data/worldbook/       原始世界書（SillyTavern 格式，保持原樣以便回頭用酒館編輯）
data/world/           地理資料、可招募 NPC
data/rules/           等級、經濟、戰鬥、技能、敵人
schemas/              報告格式（JSON Schema）
examples/reports/     範例報告
docs/                 設計文件
src/engine/           遊戲引擎（純 TypeScript，不依賴 Vue）
src/narrator/         世界書挑選、提示詞、AI 服務
src/stores/           Pinia：遊戲狀態與存檔、設定
src/components/       Vue 介面
src/__tests__/        Vitest 測試（含報告格式驗證）
```

## 7. 待決定事項

已決定：網頁版（Vue 3）、玩家自備 API key、逐回合手動戰鬥＋戰後戰報、可招募 NPC 隊友。

1. **數值平衡**：目前的 HP、傷害、經驗值公式都是提案。等級 1 的法師單獨對上一隻巨鼠也可能輸，開局可能偏難。
2. **旅途遭遇戰**：需要「中斷旅程 → 戰鬥 → 繼續旅程」的流程。
3. **NPC 來源**：目前是預先寫好的 6 位；之後是否讓 AI 在事件中生成 NPC，再由引擎登錄？
4. **戰鬥中使用道具**、裝備系統、商店。
5. **其他區域的敵人與遭遇表**：目前只有中央平原的三個冒險區域有遭遇表。
6. **世界書資料不一致**：見 [`WORLD_NOTES.md`](WORLD_NOTES.md)。
