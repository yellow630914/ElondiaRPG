# 介面語言（繁體／簡體中文）

> 上層：[README](README.md)。程式：`src/i18n/uiScript.ts`；設定：`stores/settings.ts` 的 `uiLanguage`。

遊戲的介面與資料都是繁體中文寫的。「⚙️ 設定」對話框右上角的「語言」可以切換成簡體中文：畫面上的文字在**顯示時**轉成簡體，程式與資料不用另外準備一份簡體版。

## 1. 兩個語言設定

| 設定 | 位置 | 管什麼 |
|---|---|---|
| 語言（`uiLanguage`） | 設定對話框的頁籤列右側 | 畫面上的文字用繁體或簡體 |
| AI 的輸出語言（`language`） | 「敘事與判定」頁籤 | 提示詞裡的 `{{language}}`：AI 寫的正文、判定的理由用哪一種 |

兩者分開：介面用簡體的玩家通常也會把 AI 的輸出語言改成簡體，但不強制。

## 2. 怎麼轉

- 用 OpenCC **逐字**轉（台灣字形 → 大陸簡體；一字多義的字照 OpenCC 的詞組判斷，例如 乾淨→干净、乾坤→乾坤）。
- **不用 OpenCC 的台灣用語詞典（twp）**：那是給資訊類文章的，會把奇幻的文字與音譯的名字改壞。用全部遊戲資料檢查過，會出事的例如：哥布林→哥布尔、熔岩核心→熔岩内核、傳送卷軸→发送卷轴、月光晶片→月光芯片、傑佛瑞→杰福雷、艾佛瑞→艾福雷、地平線上→地平在线、檔案室→文件室、叮噹→丁当、行程表→进程表、仍在執行命令→仍在运行命令。玩家自訂的名字也會遇到同樣的問題。
- 換成大陸用語的只有一小張介面用語表（`uiScript.ts` 的 `UI_TERMS`）：儲存→保存、匯入→导入、匯出→导出、選單→菜单、圖示→图标、介面→界面、內建→内置、檔案→文件、程式→程序、載入→加载、快取→缓存、機率→概率、預設值→默认值、建立角色→创建角色……。只收介面與說明才用得到、不會出現在名字與故事裡的詞；會撞到故事用法的寫法放在旁邊保留原樣（档案室、载入史册）。
- 「設定」維持「设定」不換成「设置」：世界書與提示詞裡的「世界观设定」「角色设定」是設定集的意思，而「设定」在簡體中文也是通用的寫法。
- 新增介面用語前，用全部的 `data/` 與 `worldgen/worlds/` 檢查會命中哪些地方，確定不會改到名字與故事。
- 轉換的範圍：文字節點，`title`、`placeholder`、`aria-label`、`alt` 屬性，以及 `alert`／`confirm`／`prompt` 的訊息。網頁標題也會轉。
- 畫面之後出現或改變的文字由 `MutationObserver` 接手，同一個畫格的變動一起轉。
- 切回繁體時，停止轉換，還在畫面上、沒有被程式改過的文字換回原文（被程式改過的就是新的繁體原文）。
- `<html lang>` 跟著切換。字型依它挑選：簡體時 Noto Serif SC 排第一（`style.css` 的 `:root:lang(zh-Hans)`），繁體時 Noto Serif TC 排第一、Noto Serif SC 補上簡體字。

## 3. 不轉的地方

| 內容 | 原因 |
|---|---|
| 輸入框、文字框裡的值（角色名、背景、內容編輯器的欄位……） | 玩家輸入什麼就存什麼；轉了會改到資料 |
| `<pre>`：提示詞預覽、注入資料、思考過程、原始報告、形象圖的提示詞 | 這是實際送給 AI 或 AI 傳回的文字，要看到原樣 |
| AI 寫的正文（`data-no-convert`） | 語言由「AI 的輸出語言」決定 |
| `<code>`、`contenteditable`、標上 `data-no-convert` 的元素 | 程式碼與可編輯的內容 |

資料、存檔與送給 AI 的提示詞都維持繁體。新增元件時，要原樣顯示的地方加 `data-no-convert`。

## 4. 提示詞（盤點，還沒改）

### 4.1 現在的樣子

「AI 的輸出語言」只影響兩個地方：敘事規則第 6 條的 `{{language}}`，以及判定的 `narrative`、`summary` 用哪一種寫。其他所有送出的文字都照原本的寫法：

| 提示詞的區塊 | 來源 | 寫法 |
|---|---|---|
| 敘事規則、判定規則、輸出格式、戰敗與成人場景規則、本次要求 | 程式（`narrator/prompt.ts`、`judge.ts`），敘事規則可以在提示詞頁籤改 | 繁體 |
| 文風、其他提示詞 | 提示詞組（內建的預設是繁體；玩家寫的照玩家） | 繁體／玩家自訂 |
| **世界書** | `data/worldbook/elondia.worldbook.json`（SillyTavern 格式） | **簡體**；玩家改寫或新增的條目照玩家；世界包「艾隆迪亞擴充」新增的條目是繁體 |
| 主角、隊伍、行囊、對象、報告、機制結果、可用的 effects | 遊戲資料 | 繁體（玩家輸入的名字、外貌照玩家） |
| 人際關係與冒險記憶 | 存檔（一部分是 AI 寫的） | 大多繁體，AI 用簡體寫過的就是簡體 |
| 居民潤飾、商店特別商品、談判方式 | 程式 | 繁體，沒有指定輸出語言 |
| 形象圖的標籤轉換 | `imageInfo.ts` | 英文樣板＋繁體的角色描述 |

也就是說，**不論輸出哪一種，送出去的提示詞本來就是繁簡混在一起**：繁體的指示與資料，夾著簡體的世界書。

### 4.2 AI 回傳、會寫進存檔的東西

| 功能 | 回傳 | 寫進存檔的文字 | 要和資料比對名字的欄位 |
|---|---|---|---|
| 敘事正文 | 散文＋`<relationship_updates>` | 正文（原樣顯示）、關係的提議 | 人的 id |
| 判定 | JSON | `summary`（日誌的簡述、冒險記憶）、`rationale`、關係文字、認識的新人（名字、外貌）、印記名稱、自創物品與特質 | **物品名稱**、**能力名稱**、勢力與人的 id |
| 居民潤飾 | JSON | 居民的名字、外貌、性格、背景、職業 | 人的 id |
| 商店特別商品 | JSON | 交易的標題與說明、自創物品 | **目錄的物品名稱**、底材與材料 id |
| 談判方式 | JSON | 選項的文字 | — |
| 形象圖標籤 | 英文標籤 | — | — |

### 4.3 輸出簡體時會遇到的問題

1. **名字的寫法不一致**：指示與資料是繁體，AI 要用簡體寫，名字常常照抄繁體（「萊茵堡」「莉娜」夾在簡體的句子裡），同一個名字前後寫法不同。
2. **資料混進簡體**：判定的 `summary` 指定用輸出語言寫，所以會用簡體存進日誌與冒險記憶，之後再當成資料送回提示詞；切回繁體介面時，這些字會停在簡體。
3. **名字比對**：如果把提示詞整份轉成簡體，AI 回傳的物品、能力名稱也會是簡體（「治疗药水」），和資料裡的「治療藥水」對不上，會被當成自創物品或被拿掉。
4. **繁體輸出也有混雜**：世界書是簡體，輸出繁體時 AI 偶爾會把世界書的簡體用語帶進正文。
5. 快取不受影響：轉換是固定的，同樣的內容轉出來每次都一樣。

### 4.4 建議的做法（待決定）

原則：**存檔裡的資料一律是繁體**（介面再依「語言」顯示）；**AI 寫的散文**照「AI 的輸出語言」。

1. **散文類的請求（敘事正文、判定）整份轉成輸出語言**：組好提示詞之後，輸出簡體時整份逐字轉成簡體（同介面的 OpenCC 逐字轉換，不換用語）；輸出繁體時把簡體的部分（世界書）轉成繁體。AI 看到的全是同一種寫法，名字也會照著寫。提示詞頁籤的預覽顯示轉換後、實際送出的內容。
2. **回傳的資料轉回繁體**：`summary`、`rationale`、關係文字、新認識的人、印記名稱、自創物品與特質的名稱說明，存進存檔前逐字轉回繁體。
3. **名字比對改成不分繁簡**：物品、能力、特質的名稱比對時兩邊都轉成簡體再比，比到了就換成資料裡的寫法。
4. **只回傳資料的請求（居民潤飾、商店、談判）維持繁體**，不轉換：回傳的都是存檔資料，顯示時再交給介面轉換。
5. 玩家自己寫的文風、其他提示詞、世界書條目也跟著第 1 點一起轉，不用另外準備兩份。

要決定的事：

- 第 2 點：AI 寫的簡述、記憶、關係文字要轉回繁體存（建議），還是照 AI 寫的存？
- 第 1 點的反方向：輸出繁體時，要不要也把簡體的世界書轉成繁體（建議要，順便解決第 4.3 節第 4 點）？
- 正文本身維持 AI 寫的樣子（不轉），對嗎？

## 5. 其他還沒做的

- 匯出的檔名、下載的檔案內容維持繁體。
