# NPC 系統：名單、互動、警戒與通緝

> 狀態：已實作（實作的位置見第 11、12 節）。金額單位為白鸛幣。

## 1. 目標

- 每個地點有一份**相對固定**的 NPC 名單，偶爾才有人搬來、離開。
- NPC 分成**普通人**與**冒險者**（約 1:1）。只有冒險者有職業、可以雇用（任何地點）、可以戰鬥。
- 右側常駐「這裡的人」列表，顯示和主角同一個地點的 NPC，可以直接互動：聊天、送禮、偷竊、獻媚、攻擊、雇用。
- NPC 依**活躍地點**與**標籤**決定出現在哪裡；野外與地下城也會遇到人。
- 已經認識的人符合規則時會再遇到。
- 偷竊、攻擊會留下後果：衛兵警戒、聲望、通緝；聲望影響買賣價格，警戒與通緝影響出入城。

## 2. 程式與資料

- 程式：`src/engine/population.ts`（名單、活躍地點、每日位置、這裡的人、名單變動、野外訪客）、`interactions.ts`（聊天、送禮、獻媚、偷竊、偷襲）、`encounters.ts`（對峙）、`security.ts`（警戒、通緝、罰金、城門盤查、王城）、`traits.ts`（名字、外貌、性格）、`npcs.ts`（NPC 登錄）。
- 資料：`data/rules/npc_tags.json`、`npc_population.json`、`security.json`；`data/world/npcs.json`（具名 NPC）、`npc_traits.json`、`npc_pool.json`。
- 相關文件：上層 [GAME_DESIGN](GAME_DESIGN.md)；依賴 [ACTIONS](ACTIONS.md)（互動都是主動行動）、[WORLD](WORLD.md)（地點與地區）；被依賴 [COMPANIONS](COMPANIONS.md)（雇傭、主人的身分）、[TRADE](TRADE.md)（聲望影響價格）。

## 3. NPC 資料

型別是 `NpcDef`（`src/engine/data.ts`）與 `NpcRecord`（`src/engine/types.ts`），主要欄位：

| 欄位 | 說明 |
|---|---|
| `kind` | `commoner` 普通人、`adventurer` 冒險者（沒寫時有戰鬥職業的算冒險者，否則是普通人） |
| `class`、`occupation` | 職業；普通人另有職業描述（麵包師、守衛、修女……，給 AI 參考） |
| `tags` | 標籤，見第 4 節 |
| `haunts` | 活躍地點 `{ location, zone, weight }`，見第 5 節 |
| `location` | 名單所屬的地點 |
| `spot` | 固定待的設施（店主、職員） |
| `hostile`、`dead` | 被攻擊後敵對、已經死亡 |
| `character` | 戰鬥資料（入隊過、或戰鬥時才產生） |
| `lineage` | 血統、部族、氏族（見第 13 節） |

- **普通人不能被攻擊**，所以沒有戰鬥資料。
- 店主、公會職員、旅店老闆是「職員」：普通人，有 `spot`，不算在名單人數裡，不會移動。

### 3.1 固定 NPC 的小隊（`squad`）

固定 NPC 可以帶一支小隊（2–4 人，含隊長），寫在**隊長**身上（`src/engine/squads.ts`）：

```json
"squad": { "name": "旅歌隊", "members": ["npc_ael"], "together": 0.85, "requires": { "flags": ["…"] } }
```

| 欄位 | 說明 |
|---|---|
| `name` | 隊名（介面與 AI 看得到） |
| `members` | 隊員：其他固定 NPC 的 id，不含隊長，1–3 人 |
| `together` | 隊員每天跟著隊長的機率（0–1，預設 1）；用「隊員 id＋日期」的固定亂數，重新整理不會變 |
| `requires` | 小隊成立的條件（劇情旗標、好感）；不成立時各自照自己的活躍地點行動 |

- 隊員跟著隊長的那天，出現在隊長所在的區域、站在隊長旁邊走得到的一格；沒跟上的那天照自己的活躍地點。隊長入隊、在主角家看家或死亡時，隊員各自行動。
- 小隊不拆開：隊員不會出現在雇用名單（`hireable`）與邀請名單，只能找隊長**整隊邀請**或**請他們帶主角同行**（見 [COMPANIONS](COMPANIONS.md) 第 2.6 節）。
- 隊長不能同時是別隊的隊員；同一個人只算進第一個列出他的小隊，不存在的 id 略過（執行時判斷，內容編輯器的選單也會排除）。
- 「這裡的人」在名字旁標出隊名（隊長另標「隊長」）；AI 判定時對象的資料會寫出小隊與隊員。
- 內建範例：米菈＋艾爾溫「旅歌隊」（晨光城一帶，同行 85%）。

## 4. 標籤

標籤定義在 `data/rules/npc_tags.json`，NPC 可以同時有多個。目前的用途：決定活躍地點與生成機率，並傳給 AI 當作身分參考。

| 標籤 | 適用 | 活躍地點數 | 地區傾向 | 稀有度 | 說明 |
|---|---|---|---|---|---|
| 旅人 | 兩者 | 2～4（沿道路相連的城鎮） | 城鎮、近郊 | 常見 | 和「商人」並存就是行商 |
| 商人 | 普通人為主 | 1 | 城鎮 | 常見 | |
| 平民 | 普通人 | 1 | 城鎮、近郊 | 很常見 | |
| 奴隸 | 兩者 | 跟隨主人 | — | 少 | 只給 AI 參考 |
| 貴族 | 兩者 | 1～2 | 城鎮、貴族區 | 少 | 和冒險者並存就是落魄貴族 |
| 皇族 | 普通人為主 | 1（只在王都） | 貴族區、王城 | 極少 | |
| 神官 | 兩者 | 1 | 城鎮、貴族區、神殿 | 少 | 冒險者神官多半是牧師、聖騎士 |
| 主教 | 普通人 | 1 | 貴族區、神殿 | 極少 | |
| **惡人** | 冒險者為主 | 1～3 | 近郊、地下城 | 少 | 在聚落以外（近郊、地下城、旅途）遇到時不看好感度，直接進入敵對檢定（第 8 節）；在城裡不會主動攻擊 |
| 娼妓 | 普通人 | 1 | 娼館 | — | 只出現在有娼館的聚落（`requires_zone`），見 [WORK](WORK.md) 第 2 節 |
| **好人** | 兩者 | 1 | 城鎮 | 少 | 和惡人互斥；比較好相處（聊天 DC −2、送禮與獻媚 −1、雇傭與邀請入隊 −2）；不會因關係差在野外動手（被攻擊過才會）；偷他東西被發現、當著人偷襲他時聲望再 −1 |

每個標籤在資料裡有：`kinds`（適用類型）、`zone_weights`、`commoner_weight`／`adventurer_chance`／`extra_chance`（生成機率）、`haunt_extra`／`haunt_extra_weight`（額外的活躍地點）、`wealth`（財富等級）、`occupations`、`location_types`（例如皇族只在王都）、`requires_zone`、`ai_hint`（給 AI 的身分說明）。表格裡的「活躍地點數」「稀有度」是概略的說明，實際數值看這些欄位。另外可以有：`exclusive`（互斥的標籤）、`dc_mods`（和他互動的參考 DC 修正：chat、gift、flatter、hire、invite）、`never_hostile`（不會因關係差在野外動手）、`crime_reputation`（對他犯罪被發現時額外的聲望變化）。還有 `class_mult`：依冒險者職業調整 `adventurer_chance` 的倍數（先抽職業再抽標籤）。例如聖騎士抽到惡人的機率 ×0.1、牧師 ×0.3，盜賊 ×2；好人與神職則是聖騎士、牧師比較高。沒寫的職業 ×1。

**好人標籤用在哪些系統**：

| 系統 | 效果 |
|---|---|
| 生成 | 普通人權重 6、冒險者 12%，和惡人互斥（地下城的惡人訪客也會拿掉好人） |
| 交流 | 聊天、送禮、獻媚的 DC 降低 |
| 雇傭、邀請入隊 | DC −2 |
| 野外遭遇 | 關係再差也不會主動敵對 |
| 偷竊、偷襲 | 被發現或被目擊時聲望多扣 1 |
| 當主人（[`COMPANIONS.md`](COMPANIONS.md)） | 允許離家的天數 +3 而且 ×2；談判解除契約 DC −3；有自己的一組主人事件（關心你、替你上藥、放假、談你自由之後的打算）；投靠時 DC −2；很少在奴隸市場買人、不去黑市 |
| AI | `ai_hint`：心地善良、樂於助人，會幫助弱者（包括奴隸） |

## 5. 地區與活躍地點

### 5.1 地區（zone）

| 地區 | 在哪裡 |
|---|---|
| 城鎮 `town` | 聚落的一般區塊（城門區、城中區、港區……） |
| 貴族區 `noble` | 王都的區塊 |
| 王城 `palace` | 王都的區塊（教廷是聖殿、精靈王庭是王庭……依勢力換名稱） |
| 神殿 `temple` | 聚落裡的神殿格 |
| 近郊 `outskirts` | 城鎮近郊（野外地圖） |
| 地下城 `dungeon` | 地下城各層 |
| 娼館 `brothel` | 聚落裡的娼館格（和神殿一樣） |

`maps.json` 的王都地圖有「貴族區」「王城」區塊，各區塊標示 `zone`。

- 貴族區：自由進出，**通緝中不能進入**。
- 王城：入口有衛兵，**需要該勢力聲望 ≥ 10** 或有任務許可；通緝中不能進入。

### 5.2 活躍地點

活躍地點是一張權重表，例如：

```
平民・麵包師：索里耶爾/town 1.0、索里耶爾/outskirts 0.4、萊茵堡/town 0.1
旅人・冒險者：索里耶爾/town 1.0、河谷鎮/town 0.8、低語墓穴/dungeon 0.5
```

產生方式：
1. 從名單所屬地點開始，依標籤的 `zone_weights` 填入這個地點的各地區。
2. 有 `haunt_extra` 的標籤（例如旅人）再從兩步路程以內隨機挑幾個地點，權重在 `haunt_extra_weight` 的範圍內隨機（旅人 0.5～0.9）；其他人只加一個鄰近的聚落，權重 0.1。
3. 冒險者另外加上附近 1～2 座地下城。

## 6. 名單（相對固定）

### 6.1 規模（冒險者：普通人 ≈ 1:1，不含職員）

| 地點類型 | 冒險者 | 普通人 |
|---|---|---|
| 王都（capital） | 12 | 12 |
| 城市（city） | 8 | 8 |
| 城鎮、港口（town、port） | 5 | 5 |
| 村落、哨站、要塞（village、outpost、fortress） | 3 | 3 |

設定在 `data/rules/npc_population.json`。具名 NPC（莉娜等）算在他所屬城鎮的冒險者名額裡。

### 6.2 建立與變動

- **第一次進入**一個地點時建立名單（固定種子，同一局內不變）。
- **每天誰在哪裡**：用「日期＋NPC id」的固定亂數，依活躍地點權重決定今天在哪個地點、哪個地區。不存額外資料，重新整理也不會變。
- **變動**：每 3 天，每個已建立的名單有 25% 機率發生一件事：
  - 搬來一位新的冒險者或普通人（未滿額時）
  - 一位冒險者搬去他的另一個活躍地點（加入那邊的名單）
  - 名單滿額時，隨機一位生成的成員離開：冒險者有別的聚落可去就搬家，認識的人搬到兩步路程內的聚落，其他人直接移除
- **清理**：只清臨時的 NPC（酒館候選人、奴隸市場、別人的隊伍、野外訪客：id 開頭是 `tav`、`slv`、`pty`、`vis`）：不在任何名單、不在隊伍、和主角沒有關係也沒有記憶的會被移除。名單居民與主人不會被清掉。
- **重逢**：在近郊與地下城遇到人時，有一定機率是認識的人（`npc_population.json` 的 `visitors.reunion_chance`）。
- **酒館候選人**改成「今天在城裡、可以雇用的冒險者」，不再每天新生一批。

## 7. 「這裡的人」列表（右側常駐）

- 依主角目前所在的**區塊與格子**列出在場的人：
  - 聚落：同一區塊的人；站在設施上時，那個設施的人排在最前面（店主、職員、酒館裡的冒險者）。
  - 近郊、地下城：遭遇到、還沒離開的人。
- 分成「冒險者」「普通人」兩組，用名牌顯示（種族 emoji＋性別顏色的名字＋職業 emoji），加上標籤與關係階段。
- 點一下展開互動選單（第 8 節）。
- 「主動行動」的對象選單也列出這裡的人：隊伍、身邊的人（同一格或相鄰）可以選；同一區較遠的人列在「要先走近」底下，不能選。展開互動選單裡的「🎲 主動行動」會直接把這個人帶進主動行動。

## 8. 互動

都接到現有的主動行動框架：先擲骰，再由 AI 判定（看得到骰值，可以出乎預料）或依規則判定。

| 互動 | 對象 | 屬性 | 成功 | 失敗 | 大失敗 |
|---|---|---|---|---|---|
| 聊天 | 全部 | 魅力 | 好感小增、可能得到情報（旗標、記憶） | 沒有進展 | 好感小降 |
| 送禮 | 全部 | 魅力 | 選一件持有物品；依價值增加好感（程式計算，見第 11 節） | 禮物不合意，好感不變 | 冒犯，好感下降 |
| 偷竊 | 全部 | 靈巧 | 偷到錢或物品（依標籤決定油水：貴族、商人多，平民少） | 被發覺：好感下降、該地警戒 +1、聲望 -1 | 被抓：警戒 +2、聲望 -2，冒險者轉為敵對；警戒累積到 3 就通緝（第 9 節） |
| 獻媚 | 全部 | 魅力 | 好感增加（可搭配魅惑術等能力，花資源換加值） | 好感下降 | 好感大降 |
| 攻擊 | **只限冒險者** | 靈巧（偷襲） | 偷襲成功、無人目擊：戰鬥時先手，沒有衛兵與聲望後果 | 被目擊：對方敵對＋**現在地點與對方各活躍地點**的警戒與聲望後果，進入戰鬥 | 同失敗，且對方先手 |
| 雇用 | 只限冒險者 | 魅力 | 沿用現有雇用規則，任何地點都可以 | — | — |

- 偷竊的難度：對方等級與標籤（商人、貴族比較警覺）；偷到的東西由程式依標籤的財富等級決定範圍，AI 判定時可以描述是什麼物品。
- 攻擊在近郊、地下城沒有衛兵；被目擊時，聲望後果仍然傳到對方的活躍地點（「有人看到」）。

### 8.1 地下城遭遇敵對冒險者（複合檢定）

遭遇的冒險者（孤狼或隊伍）符合以下任一條件時，視為敵對：
- 帶有「惡人」標籤（**不看好感度**）
- 和主角的關係不好（好感度低於門檻，或已經敵對）

流程：

```
1. 察覺檢定：由主角代表擲潛行（靈巧），對抗對方的察覺
   ├─ 未被發現 → 選擇：悄悄避開／偷襲（戰鬥先手）／現身（進入 2，加值 +2）
   └─ 被發現   → 進入 2
2. 應對（擇一，一次檢定）
   ├─ 蒙混：魅力或智力
   ├─ 威嚇：力量或魅力，依雙方隊伍的等級與人數修正
   ├─ 交涉：付錢或物品換取通過（不需檢定，金額依對方開價）
   └─ 戰鬥
   成功 → 對方放行（可能留下關係與記憶）
   失敗 → 戰鬥；大失敗時對方先手
```

非敵對的冒險者：中立遭遇，可以聊天、交易、邀請入隊或忽略。

### 8.2 打贏之後：處置被制伏的人

會和 NPC 打起來的情境（都只限冒險者）：
- **對峙開戰**（8.1）：敵對的冒險者在野外、地下城攔路，談判失敗或選擇開戰、偷襲——算**對方先動手**（`aggressor: 'npc'`）。
- **偷襲**（第 8 節「攻擊」）：主角對冒險者出手——算**主角先動手**（`aggressor: 'party'`）。
- 特殊任務的戰鬥任務點也可能有 NPC（`foes`），但結果照任務走，不另外處置（倒下的人照舊死亡）。

打贏時，倒下的人不再直接死亡，而是被制伏（`state.captives`，`engine/captives.ts`），擋住移動與休息，事件視窗出現「戰後處置」。每個人可以：

| 處置 | 結果 | 後果（`security.json` 的 `captives`） |
|---|---|---|
| 主動行動 | 自由描述要對他做的事（審問、勸降……），交給 AI 判定（判定與敘事都會被提醒：對方還在你手上，不能寫成離開或死亡）；之後還是要選下面一種 | 依判定 |
| 順便劫財 | 處置時勾選：把對方從頭到腳再搜一遍，連藏起來的錢也翻出來（30 × 等級 × 0.5～1.5 白鸛），對方親密度 -10 | 主角先動手：警戒 +1、聲望 -1；對方先動手：無 |
| 順便劫色（只在開啟成人向時） | 處置時勾選：趁對方無力反抗時強行佔有，報告帶成人場景（敘事附上成人場景規則）；對方親密度 -30 | 主角先動手：警戒 +2、聲望 -3；對方先動手：警戒 +1、聲望 -2 |
| 放過 | 留在原地、敵對，今天不會再打起來；對方先動手時，對方欠你一份情（親密度 +5） | 無 |
| 收為奴隸 | 以奴隸身分加入隊伍（預設契約，要有空位），剛被打倒，以 1 HP 加入 | 主角先動手：警戒 +2、聲望 -3；對方先動手：警戒 +1、聲望 -1 |
| 處決 | 死亡（從名單移除） | 主角先動手：警戒 +3、聲望 -4；對方先動手：無 |

- 警戒只在有衛兵的聚落裡加（近郊、地下城沒有）；聲望扣在這個地點所屬的勢力。主角先動手時，對好人等的額外聲望（標籤的 `crime_reputation`）也算。
- 劫財、劫色和處置寫成同一篇日誌（一份報告），後果加總計算。
- 主角偷襲時沒有人看到（偷襲檢定部分成功以上）：處置不加警戒，聲望照扣。會讓警戒到頂而被通緝時，畫面上的後果提示寫「會被通緝」。
- 放過、收為奴隸、處決都可以寫下怎麼做（例如怎麼搜身、怎麼處決、放過時說了什麼）：結果照選的處置，文字記在報告的 `narration.player_intent`，交給 AI 寫經過。
- 等待處置的人不能聊天、送禮、獻媚、偷竊、雇用或再偷襲；「這裡的人」標示「被制伏」。
- 戰報裡被制伏的人狀態是「被制伏」（不是「死亡」），AI 寫經過時不會寫成死掉。

## 9. 後果：警戒、聲望、通緝

### 9.1 警戒（每個地點，0～3）

- 偷竊被發覺、攻擊被目擊時增加。
- 從最後一次提高警戒那天起，每 7 天降 1（人在不在當地都一樣；天數是存檔規則，見 [SAVES](SAVES.md) 第 7 節）。
- **出入城門**（出城到近郊、出發旅行、從近郊回城、抵達城鎮）時：
  - 警戒 0：自由通過。
  - 警戒 1～2：檢定（主角的靈巧潛行或魅力蒙混，DC 10＋3×警戒）。失敗 → 付罰金通過，或折返。
  - 警戒 3：這個地點有所屬勢力時等同通緝；沒有勢力的地點（例如灰港鎮）只是盤查 DC 19。
- **繳納罰金可以清空該地點的警戒**（任何時候都可以在城門主動繳納）。

### 9.2 通緝（每個勢力）

- 在某勢力的地點警戒達到 3 時，被該勢力**通緝**。
- 通緝中，經過該勢力的城門**不能檢定**：必須付通緝罰金（賄賂）才能通過；付清後解除通緝，該地警戒歸零。
- 通緝中不能進入貴族區與王城。
- 和奴隸契約的「逃亡中」（`fugitive`）是不同的狀態。

### 罰金

以「一般人的生活費」為單位（`economy.json` 的 `commoner_living_cc_per_day`，每天 15 白鸛），再乘上該勢力聲望的倍率：

| 罰金 | 金額 |
|---|---|
| 警戒罰金 | 一般人生活 **1 週** × 警戒等級 × 聲望倍率（每天 15 白鸛時：105／210 白鸛 × 倍率） |
| 通緝罰金 | 一般人生活 **2 個月**（60 天）× 聲望倍率（每天 15 白鸛時：900 白鸛 × 倍率） |

| 聲望 | 罰金倍率 |
|---|---|
| ≤ -10 | ×2 |
| -9 ～ -5 | ×1.5 |
| -4 ～ 4 | ×1 |
| 5 ～ 9 | ×0.8 |
| ≥ 10 | ×0.6 |

### 9.3 聲望（每個勢力，已存在 `state.reputation`）

依地點所屬勢力的聲望調整商店價格（買入價／賣出價）：

| 聲望 | 買入 | 賣出 |
|---|---|---|
| ≤ -10 | +30% | -30% |
| -9 ～ -5 | +15% | -15% |
| -4 ～ 4 | ±0 | ±0 |
| 5 ～ 9 | -5% | +5% |
| ≥ 10 | -10% | +10% |

設定在 `data/rules/security.json`（警戒、罰金、價格倍率、王城門檻）。

## 10. AI 的角色

維持「規則決定數值，AI 寫文字」：

- **建立名單時**（AI 判定開啟）：一次請求潤飾整個地點的名單（名字、外貌、性格、背景、普通人的職業描述），標籤與活躍地點當作參考。每個人只潤飾一次（記在 NPC 登錄的 `flavored`）：名單變動搬來的新居民，下次（AI 判定開啟）來到這個地點時再請 AI 潤飾，只送還沒潤飾過的人。交給 AI 但 AI 漏掉的人保留原本的文字，不再重問；已經認識的人不潤飾。
- 地下城遭遇的冒險者不另外潤飾，由敘事帶出。
- 標籤、職業描述放進敘事與判定的人際關係區塊，讓 AI 知道對方的身分。
- 互動的判定沿用 AI 判定的規則：骰值是參考，數值後果由程式夾在上限內。

## 11. 第一階段的實作

| 項目 | 位置 |
|---|---|
| 標籤、類型的地區權重 | `data/rules/npc_tags.json` |
| 名單規模、冒險者等級 | `data/rules/npc_population.json` |
| 普通人的性格、服裝 | `data/world/npc_pool.json` 的 `commoner_personalities`、`commoner_outfits` |
| 王都的貴族區、王城 | `data/world/maps.json`（區塊的 `zone`、`palace_names`） |
| 名單、活躍地點、每日位置、這裡的人 | `src/engine/population.ts` |
| 聊天、送禮、獻媚 | `src/engine/interactions.ts`、`data/rules/actions.json` 的 `chat`、`gift`、`flatter` |
| 右側列表 | `src/components/PeoplePanel.vue` |
| AI 潤飾名單 | `buildRosterPrompt`（`src/narrator/judge.ts`），到達地點時送還沒潤飾過的人 |

- 名單用「存檔種子＋地點」的固定亂數生成，不會改變遊戲本身的亂數。
- 送禮的親密度：部分成功以上，禮物價格每達到「一般人生活費 × 對方財富等級的倍率 × 0.5／2／8」的一級，再 +1（貴族要更貴的禮物）。
- 獻媚：對方財富等級每高於 2（貴族 3、皇族 4）一級，檢定 -2。
- 親密度由程式依成功程度改變；AI 判定時只能補充關係文字與旗標（例如聽到的消息）。

### 11.1 格子上的位置

- 店主、公會職員等職員固定在自己的設施格子上。
- 其他人在所在區塊的格子上散開：依「NPC id＋日期＋時段（每 6 小時）」的固定亂數挑格子，所以一天會換幾次位置。冒險者常在酒館與公會，普通人多在街上，神官、主教在神殿，商人在商店附近（權重在 `population.ts` 的 `CELL_WEIGHTS`、`TAG_CELLS`）；城鎮的特色地標依類型聚集不同的人（[LANDMARKS](LANDMARKS.md) 第 2 節）。固定 NPC 可以「待在地標」。
- 有好幾個同類區塊時（例如王都的城門區與市集都是一般區域），每人每天固定在其中一個。
- 地圖上有人的格子右上角會標出人數（敵對的人是紅色）；「這裡的人」列出整個區塊的人，但**只有同一格或相鄰格的人能互動**，遠處的人會顯示方向與距離。

## 12. 第二、三階段的實作

| 項目 | 位置 |
|---|---|
| 名單變動（每 3 天 25%） | `refreshRosters`（`population.ts`），抵達地點與讀檔時補算 |
| 近郊、地下城遇到的人、重逢 | `spawnVisitors`（`population.ts`），參數在 `npc_population.json` 的 `visitors` |
| 敵對判定 | `isHostile`：被攻擊過，或在野外與地下城遇到「惡人」、親密度 ≤ -20 的冒險者 |
| 對峙與複合檢定 | `src/engine/encounters.ts`、`src/components/StandoffPanel.vue`；蒙混、威嚇是主動行動（`actions.json` 的 `bluff`、`intimidate`） |
| 和冒險者戰鬥 | `startCombat` 的 `npcs`、`surprise`、`aggressor`；打贏時倒下的人被制伏、等主角處置（8.2 節），其他情況倒下的人死亡；活著的人敵對；經驗與戰利品依等級（`hostility`） |
| 偷竊、偷襲 | `src/engine/interactions.ts`，規則在 `data/rules/security.json` 的 `steal`、`attack` |

| 聲望影響價格 | `dealMoney`、`sellPrice`（`trade.ts`）乘上 `reputation_bands` 的倍率 |

- 城門盤查發生在：出城到近郊、從近郊回城、從聚落出發旅行、抵達聚落。當天通過一次就不再查；被攔下當天就過不去，要繳罰金。
- 抵達時被攔下：付得起罰金就自動繳交；付不起就被擋在城外（近郊），可以之後回到城門繳罰金。
- 對峙中不能移動、休息或旅行。
- 戰敗或撤退後，對方今天不會馬上再找你麻煩。

## 13. 名字、外貌與性格

素材在 `data/world/npc_traits.json`（依世界書的種族條目整理），生成在 `src/engine/traits.ts`。

- **名字**：人類男女名各 40 個、精靈、矮人、魔族、貓魅族各 30 個；玉璘族男女共用一池 60 個（外觀一律女性化）。姓氏：人類 24 個（40% 帶姓）、精靈 12 個（30%）、矮人用氏族名。名字已經被用過時換一個，都用完才加編號。

- **血統**：每個種族下分成血統、部族、氏族或出身派系，依所在地點加權（`home`）：
  - 人類：萊茵帝國、晨曦王國、奧德聯邦、聖環教廷出身
  - 精靈：森居族群、翠輝議會的世家、星月之環的學者、新芽同盟、迷霧之幕的暮影精靈
  - 矮人：鐵爐、灰岩、銅鬚、迷石氏族（名字帶氏族姓氏，例如「托林・灰岩」）
  - 魔族：魅魔（赤翼宮廷）、炎魔（炎獄軍團）、影魔（暗影氏族）、獸人（血角氏族）、死靈（幽冥典儀會），外貌依世界書分男女
  - 貓魅族：赤鬃、夜爪、沙痕、月尾部落（耳尾毛色與髮色依部族）
  - 玉璘族：春潮閣、夏瀾殿、秋珊苑、冬璃宮（外觀一律女性化）
- **外貌**由部位組成：身高、壯碩程度、眼睛、面部、髮色、髮型、胸部（大小）、胸型、腰身、髖臀、腿部、足部，再加上**至少一項種族或血統特徵**（貓耳與長尾、尖耳、鰓裂、角與翅膀、礦石色澤的肌膚……）與服裝。胸部、胸型、腰身、髖臀與部分面部、髮型依性別對應的體型挑選：男性陽剛；女性、TS、扶她、偽娘陰柔；未知隨機（陽剛、陰柔、中性）。再依性別調整（`npc_traits.json` 的 `gender_rules`）：偽娘不寫胸部與胸型、不會圓潤福態或魁梧壯碩；女性、TS、扶她抽到圓潤福態的權重 ×0.3。胸型只有陰柔體型才有，接在胸部大小之後抽，用標籤避開矛盾（小胸不會是水滴形、深溝或下垂；平胸只會是小巧或勻稱；下垂不會出現在年輕的描述上）。
- **性格**由象限組成：社交、處事、待人、情緒、嗜好與習慣；**至少一項來自種族或血統**（例如矮人「重承諾」、貓魅族月尾部落「沉靜神祕」、玉璘族「樂天知命」）。冒險者與普通人各有一些專屬的習慣。
- **避免矛盾**：每個選項有標籤與互斥標籤（外貌與性格共用），例如「嬌小」不會配「魁梧」、「沉默寡言」不會配「愛吹噓」、矮人不會「修長的雙腿」、精靈與玉璘族沒有鬍子。
- **主角的體態**（建立角色的「體態與外貌」，`look.ts`、`components/LookPicker.vue`）：用同一套部位詞條。體型可以選陽剛、陰柔、中性（存在角色的 `body`；沒選時依種族與性別，主角的性別文字也會對應，例如「女」是陰柔），部位依體型、種族與性別列出可選的詞條（`traits.ts` 的 `lookOptions`，種族固定的部位只列種族的，例如矮人的身高；性別略過的部位不列，例如偽娘沒有胸部）；玩家自己選，不檢查詞條之間的互斥。「隨機一組」照 NPC 的抽法（`rollLookParts`，會避開矛盾）。選了的部位寫成一段（`describeLook`，和 NPC 外貌的寫法相同）放在外貌的開頭，後面接玩家自己寫的外貌細節；裝備欄與刺青的人形圖（小人）照體型畫，建角時體型選單旁邊有預覽；開始之後可以在角色視窗「角色設定 → 編輯設定」改體型（`character.ts` 的 `editProfile`，選「依種族與性別」就拿掉）。
- 有些部位只從種族或血統的選項抽（`force`）：矮人的身高、部族的髮色、炎魔與獸人的體格。
- AI 潤飾名單時會拿到這份草稿，並被要求保留種族特徵與性格基調；血統也會出現在給 AI 的身分說明裡。
