# 發給 AI 的提示詞結構

> 這份文件整理目前所有送給 AI 的請求，作為調整文風的依據。程式碼在 `src/narrator/prompt.ts`（敘事）、`src/narrator/judge.ts`（判定與生成）、`src/narrator/lore.ts`（世界書挑選）。

## 1. 五種請求

| 請求 | 什麼時候 | 寫正文嗎 | 帶世界書 | 帶文風條目 | 輸出 |
|---|---|---|---|---|---|
| **A. 敘事** | 開啟「AI 細節描述」，每份報告之後（交易除外） | ✅ | ✅ | ✅ | 小說正文（＋選用的關係更新提議） |
| **B. 主動行動判定** | 開啟「AI 判定主動行動」，主動行動擲骰之後 | ✅（`narrative` 欄位） | ❌ | ❌ | JSON |
| C. 酒館候選人 | AI 判定開啟，第一次進酒館 | ❌ | ❌ | ❌ | JSON |
| D. 商店清單 | AI 判定開啟，第一次進店 | ❌ | ❌ | ❌ | JSON |
| E. 談判方式 | AI 判定開啟，開始談判時 | ❌ | ❌ | ❌ | JSON |

會出現在日誌裡的正文只有 **A** 與 **B**，調整文風主要就是調整這兩種。

## 2. A. 敘事請求

### system

```
你是奇幻 RPG《埃隆迪亞大陸》的敘事者。遊戲引擎已經決定了這次事件的一切結果……

硬性規則：
1. 報告的結果、數值、物品、傷亡、時間不可更改，不可新增
2. 依 timeline 順序描寫；擲骰與 DC 不寫數字，改以描寫呈現
3. 親密值不寫數字；attitude 是態度基調、personality 是性格
4. 視角：第二人稱，以「你」指稱主角（報告 narration.pov 可改第三人稱）   ← 文風
5. 篇幅：短 200～400 字／中 500～900／長 1000～1500（報告 narration.length）  ← 文風
6. 只輸出正文，不要標題、狀態欄、思考過程
7. 使用繁體中文／简体中文（設定）
8. 以世界書為準，忽略世界書裡聊天用的「格式」「狀態欄」指示
9. <protagonist>、<relationships>、<memories> 的用法
10.（有人際關係時）正文後可附 <relationship_updates>
```

### user（依序）

| 區塊 | 內容 | 來源 | 大小 |
|---|---|---|---|
| `<worldbook>` | 世界書條目，見下表 | `selectLore`，上限 = 設定的「世界書注入字數上限」（預設 12000 字） | 通常 6000～12000 字 |
| `<protagonist>` | 主角的名字、性別、種族職業等級、出身、外貌、背景 | 建角時填寫、隊伍視窗可改 | 數十～數百字 |
| `<relationships>` | 參與人的外貌、性格、與主角／他人的關係、親密度階段 | 人際關係 | 每人約 150 字 |
| `<memories>` | 最多 6 筆相關記憶（時間｜地點｜參與人｜簡述） | 共同記憶檢索 | 數百字 |
| `<report>` | 報告 JSON（id 換成中文名稱） | 遊戲引擎 | 戰鬥報告可達數千字 |
| 玩家意圖、描寫重點 | `narration.player_intent`、`narration.focus` | 行動備註、各系統 | 一兩行 |

世界書條目的挑選（`src/narrator/lore.ts`）：

| 條目 | 規則 |
|---|---|
| 埃隆迪亞大陸（3152 字）、區域地理與勢力概述（1370）、神祇信仰（1075） | 每次都放 |
| **視角和文風條目（1542）** | **每次都放**，把裡面寫死的玩家名換成主角名 |
| 區域地理地標相對位置（1983） | 只有旅行報告 |
| 高維巨龍（2072） | 報告裡出現「龍」時 |
| 其他條目 | 報告文字（地點、場景、簡述、人名、性格）命中條目關鍵字時，依 order 排序 |
| 成人向條目 | 只有設定開啟時 |
| 規則類條目（親密值、公會等級、力量體系、職業、技能、COT、格式規範、角色扮演指導） | 一律不放（已經由遊戲引擎實作，或和介面衝突） |

### 目前決定文風的地方

1. **世界書「視角和文風條目」**：寫的是通用的「奇幻魔幻式文風」，附了三個和本作無關的範例（魔法森林、雙月城邦、海底王國），內容是簡體，而且每次都會送出（約 1500 字）。
2. system 的第 4、5 條：視角與篇幅，由報告決定（大多數是第二人稱、短篇）。
3. system 的第 7 條：語言。
4. 其餘的規則都是「不可改數值、不寫數字」這類正確性約束，和文風無關。

## 3. B. 主動行動判定請求

### system

```
你是……判定者兼敘事者……只輸出一個 JSON 物件。

判定方式：
1～2. 骰值是參考，可以出乎預料
3～5. degree、attr、dc（參考值 ±3）、effects 的規則
6.    玩家描述只代表「嘗試」
7.    narrative 用繁體中文、第二人稱、約 200～400 字、分段；不寫骰值與數字   ← 文風（寫死）
8.    只輸出 JSON

可用的 effects：（依行動種類列出，含上限）
輸出格式：{"degree":…,"narrative":"……",…}
```

### user（依序）

| 區塊 | 內容 |
|---|---|
| `<action>` | 行動名稱、場景、出價、玩家描述、長休互動的說明、搭配使用的能力 |
| `<actor>` | 主角的種族職業等級、性別、出身、外貌、背景、五屬性、技能、金錢、契約 |
| `<party>` | 每位隊員的入隊方式、性別、種族職業、HP、裝備、狀態、對主角的態度 |
| `<target>` | 對象的資料與人際關係 |
| `<relationships>`、`<memories>` | 同敘事請求 |
| `<dice>` | 自然骰、情境修正、各屬性總值、參考 DC、依預設屬性的參考結果 |
| `<mechanics>` | 各成功程度在程式中會發生什麼 |

### 和敘事請求的差異

- **沒有世界書、沒有文風條目**，所以這類日誌的文字風格可能和一般敘事不一樣。
- 第二人稱、繁體中文、200～400 字都寫死在第 7 條，不會跟著設定的語言或報告的篇幅改變。

## 4. C～E. 生成請求

只輸出 JSON，內容是名字、外貌、性格（酒館）、交易清單（商店）、談判方式（談判），不會出現在日誌正文裡。它們的語氣只會影響角色設定的用詞，和文風關係不大。

## 5. 調整文風的建議做法

文風最好集中在一個地方設定，同時套用到 A 與 B：

```
設定 →「文風」
├─ 預設文風（選一個）：例如 史詩奇幻／輕小說／黑暗寫實／詼諧冒險／簡潔報告
├─ 自訂補充（文字）：例如「多寫環境與氣味，對白要口語」
├─ 視角：第二人稱／第三人稱（覆寫報告的預設）
└─ 篇幅：短／中／長（覆寫報告的預設）

送出時：
A. 敘事：system 加入 <style> 區塊；不再注入世界書的「視角和文風條目」（或保留為「預設文風」的一種）
B. 判定：system 第 7 條改成引用同一個 <style>，視角、篇幅、語言跟著設定
```

要先決定的事：

1. 預設文風要哪幾種？要不要保留世界書原本的「奇幻魔幻式文風」作為其中一種？
2. 文風要跟著存檔走（每個角色各自的風格），還是跟著瀏覽器設定走（所有存檔共用）？
3. 判定請求要不要也帶上世界書？帶上可以讓世界觀更一致，但每次行動多送 6000～12000 字。
