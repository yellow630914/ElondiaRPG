# 人際關係與共同記憶

> 上層：[GAME_DESIGN](GAME_DESIGN.md)。被依賴：[ACTIONS](ACTIONS.md)（判定時帶上關係與記憶）、[PROMPTS](PROMPTS.md)（敘事時帶上關係與記憶）、[EVENTS](EVENTS.md)（關係更新的提議）。
> 程式：`src/engine/social.ts`（介面在「💞 關係」視窗）。主動行動原本寫在這份文件的第 5 節，已移到 [ACTIONS](ACTIONS.md)。

## 1. 人際關係

主角與每個認識的角色之間有一個條目。它和「隊友」是不同的系統：隊友管的是戰鬥數值，人際關係只記錄關係，任何人都可以有：招募、交流、主動行動與事件第一次碰到某人時就會建立條目（`ensureRelationship`）。

| 欄位 | 說明 | 誰可以改 |
|---|---|---|
| 親密度 | -100～100，階段名稱沿用世界書「分階段親密值規則」 | 只由遊戲規則變動（戰鬥、事件、主動行動） |
| 外貌 | 文字 | 玩家編輯；初始值來自 `data/world/npcs.json` |
| 與主角的關係 | 文字 | 玩家編輯；之後可由事件結果更新 |
| 與其他角色的關係 | 角色 → 文字 | 玩家編輯；初始值來自 `npcs.json` 的 `relations` |
| 別名 | 稱號、暱稱，供比對用 | 玩家編輯 |
| 性格、勢力 | 來自 NPC 資料 | — |
| 初次見面、最後一次見面 | 時間與地點 | 自動 |

隊友的 `affinity` 是這裡的同步副本：報告中的親密度變化一律寫進人際關係條目，再同步到隊伍。

### 1.1 歡愉的惡作劇（改性別）

> 程式：`src/engine/genderSwap.ts`（`swapNpcGender`、`genderSwapBlock`、`genderSwapNote`）。

關係卡片上的「🎭 歡愉的惡作劇」可以把一個人變成別的性別（`npc_pool.json` 的任何一種），寫成一則事件日誌（`event`，摘要「歡愉的惡作劇：某某一覺醒來，發現自己從男性變成了女性」，自動敘事時照開關寫成正文），也記進共同記憶（重要程度 2）。

- **只有隨機產生的人**（`state.npcs` 裡、不是固定 NPC）而且已經認識、還活著的可以改。固定 NPC 不開放：他們的特殊任務、世界書、劇情階段與成人向外貌都照原本的性別寫（性別在世界編輯器改）。主角的性別在建角時決定。
- 存檔的 NPC 紀錄與隊伍成員（不在隊上時是紀錄裡的角色資料）一起改。
- **外貌**照新的性別重新組一份（同一個種族與血統，最後的服裝那一句照舊），關係條目的外貌也換成新的；之後可以再編輯。
- **預設內衣**照新的體型換掉（原本穿的是舊體型的預設內衣時；自己換過的、鎖住的不動）；其他衣服與飾品不換。生成的身分稱謂照新的性別（`npc_tags.json` 的 `gendered_occupations`，結尾符合也換，例如「某某的妻子」→「某某的丈夫」、「女僕」→「男僕」）。名字不變。
- **形象圖**（`stores/portraits.ts` 的 `retire`）：目前的圖退成舊版、記住的描述清掉；設定開了自動畫形象圖時排隊畫新的。
- 記下改過（`NpcRecord.genderSwap`：原本的性別與哪一天）。交給 AI 的隊伍、登場角色與人際關係都附上一句「這個角色的性別因為歡愉的惡作劇，已經改成某某，以前的記憶以這個為準」；以前的日誌與記憶不改。

## 2. 共同記憶

主角經歷過的事件，每一筆記錄**時間、地點（含細部場景）、參與人、簡述**，以及重要程度（日常／重要／難忘）與是否釘選。

自動記錄規則（`recordMemory`）：

| 報告類型 | 是否記錄 | 重要程度 |
|---|---|---|
| 戰鬥 | ✅ | 1；戰敗、有隊員倒下或慾望勝利為 2 |
| 委託（接取／完成） | ✅ | 2／3 |
| 交流（招募、離隊，以及報告類型是 `social` 的主動行動：聊天、送禮、雇傭、談判、回應主人、特殊任務的判定……） | ✅ | 結果普通（`neutral`）為 1，其他為 2 |
| 旅行（抵達） | ✅ | 1 |
| 主動行動（報告類型是 `action` 的：自由行動與工藝，見 [ACTIONS](ACTIONS.md) 第 6 節） | 有檢定才記 | 1；大成功、大失敗為 2 |
| 休息 | 夥伴有變動才記 | 2 |
| 特殊任務（事件報告） | ✅ | 接下任務、失敗或放棄為 2；完成為 3；中間的任務點為 1（大成功、大失敗或親密度變動為 2） |
| 其他事件（旅途事件、陷阱、寶箱、對峙、歸隊、解讀情報……） | ✅ | 1；高階旅途事件、主人的突發事件、戰敗事件、大成功或大失敗為 2 |
| 用餐、交易 | ✗ | — |

事件與特殊任務的效果 `memory`（`{ "type": "memory", "summary": "…", "importance": 2 }`）也會直接加一筆：參與人是當時的隊伍成員，重要程度沒寫時是 2。

簡述先用引擎產生的一句話；玩家可以在「關係」視窗改寫、調整星等、釘選、刪除，也可以手動新增（例如把 AI 敘事裡一段喜歡的情節記下來）。舊存檔讀入時，會從過去的報告補建記憶。

存檔記下記憶規則的版本（`memoryRules`）。版本 2 之前事件報告不會留下記憶（例如「翻覆的篷車」整段任務都沒有記憶）；讀入這樣的舊存檔時，會從過去的事件報告補上記憶，依時間排進去，只補一次。

## 3. 事件的三個關鍵欄位

每一份報告都已經帶有這三個欄位，檢索直接使用：

- **參與人**：隊伍成員＋報告中出現、已有人際關係條目的角色＋親密度有變化的角色。
- **地點**：`location.at`（旅行為目的地）與 `location.scene`。
- **時間**：`time.start`。

所有報告（包括特殊任務與主動行動）都用同樣的格式，所以檢索方式一樣。

## 4. 檢索與交給 AI

生成文本時（`selectContext`）：

- **人際關係**：參與人（主角除外）的條目全部帶上。
- **記憶**：只考慮「有共同參與人」「同一地點」或「釘選」的記憶，依分數取前 6 筆，再按時間排序：

```
分數 = 10（釘選）+ 3 × 共同參與人數 + 2（同一地點）+ 重要程度 + 時間接近度（3 天內 1.5、10 天內 0.75）
```

正在描寫的那份報告本身不會被當成「過去的記憶」。結果整理成 `<relationships>` 與 `<memories>` 兩段放進提示詞，敘事規則要求 AI 可以引用、不可改寫，親密度數字不可寫進正文。範例：

```
<relationships>
- 莉娜｜親密度 27（友好/好感）
  外貌：淺沙黃色的耳朵與尾巴……
  性格：沙痕部落出身的嚮導，嘴硬心軟，怕水，喜歡甜食。
  與主角：在索里耶爾酒館受雇，嘴上抱怨報酬太少，卻總是走在最前面探路。
  與他人：瑟琳：在索里耶爾的酒館常拌嘴……
</relationships>

<memories>
- 第 1 天 08:40｜索里耶爾的酒館｜艾倫、莉娜｜在酒館招募了莉娜加入隊伍……
- 第 3 天 14:10｜蛇溪洞窟・淺層｜艾倫、莉娜｜在蛇溪洞窟與溪蛇魔交戰，戰敗（6 回合）。
</memories>
```

## 5. 主動行動

見 [ACTIONS](ACTIONS.md)：擲骰先發生，再把行動者、隊伍、對象的人際關係與第 4 節檢索到的記憶交給 AI 判定。

## 6. 事件後的人際關係更新提議

- 主動行動：AI 回傳的 `relationship_updates`。
- 一般敘事：當提示詞帶有 `<relationships>` 時，AI 可以在正文後附上 `<relationship_updates>[…]</relationship_updates>`；程式把它從正文中取出（串流時也不會顯示出來）。

提議會自動彈出事件視窗（見 [EVENTS.md](EVENTS.md)），也會出現在「關係」視窗，可以修改文字後採用、不採用，或稍後再說。同一個角色只保留最新的一筆提議。

## 7. 記憶上限

記憶超過 200 筆時，把較舊的日常記憶（重要程度 1、未釘選）合併成摘要：先依「同一天」合併，還是太多就依「10 天」為一段再合併；最近 50 筆不動，釘選與重要、難忘的記憶不合併。合併後的記憶在「關係」視窗標示「合併 N 筆」。
