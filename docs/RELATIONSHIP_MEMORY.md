# 人際關係與共同記憶系統 v0.1

> 狀態：全部已實作。人際關係與記憶在 `src/engine/social.ts`（介面在「關係」視窗）；主動行動在 `src/engine/actions.ts` 與 `src/narrator/judge.ts`（介面在畫面左側的「主動行動」）。

## 1. 人際關係

主角與每個認識的角色之間有一個條目。它和「隊友」是不同的系統：隊友管的是戰鬥數值，人際關係只記錄關係，任何人都可以有（目前在招募時建立，之後的事件與主動行動也會建立陌生人的條目）。

| 欄位 | 說明 | 誰可以改 |
|---|---|---|
| 親密度 | -100～100，階段名稱沿用世界書「分階段親密值規則」 | 只由遊戲規則變動（戰鬥、事件、主動行動） |
| 外貌 | 文字 | 玩家編輯；初始值來自 `data/world/npcs.json` |
| 與主角的關係 | 文字 | 玩家編輯；之後可由事件結果更新 |
| 與其他角色的關係 | 角色 → 文字 | 玩家編輯；初始值來自 `npcs.json` 的 `relations` |
| 別名 | 稱號、暱稱，供比對用 | 玩家編輯 |
| 性格、勢力 | 來自 NPC 資料 | — |
| 初次見面、最後一次見面 | 時間與地點 | 自動 |

隊友的 `affinity` 是這裡的同步副本：報告中的親密度變化一律寫進人際關係條目，再同步到隊伍。

## 2. 共同記憶

主角經歷過的事件，每一筆記錄**時間、地點（含細部場景）、參與人、簡述**，以及重要程度（日常／重要／難忘）與是否釘選。

自動記錄規則（`recordMemory`）：

| 報告類型 | 是否記錄 | 重要程度 |
|---|---|---|
| 戰鬥 | ✅ | 1；戰敗或有隊員倒下為 2 |
| 委託（接取／完成） | ✅ | 2／3 |
| 交流（招募、離隊） | ✅ | 2 |
| 旅行 | ✅ | 1 |
| 交易、休息、採集、陷阱、升級 | ✗ | — |

簡述先用引擎產生的一句話；玩家可以在「關係」視窗改寫、調整星等、釘選、刪除，也可以手動新增（例如把 AI 敘事裡一段喜歡的情節記下來）。舊存檔讀入時，會從過去的報告補建記憶。

## 3. 事件的三個關鍵欄位

每一份報告都已經帶有這三個欄位，檢索直接使用：

- **參與人**：隊伍成員＋報告中出現、已有人際關係條目的角色＋親密度有變化的角色。
- **地點**：`location.at`（旅行為目的地）與 `location.scene`。
- **時間**：`time.start`。

之後的任務事件與主動行動也會產生同樣格式的報告，所以檢索方式不用改。

## 4. 檢索與交給 AI

生成文本時（`selectContext`）：

- **人際關係**：參與人（主角除外）的條目全部帶上。
- **記憶**：只考慮「有共同參與人」「同一地點」或「釘選」的記憶，依分數取前 6 筆，再按時間排序：

```
分數 = 10（釘選）+ 3 × 共同參與人數 + 2（同一地點）+ 重要程度 + 時間接近度（3 天內 1.5、10 天內 0.75）
```

正在描寫的那份報告本身不會被當成「過去的記憶」。結果整理成 `<relationships>` 與 `<memories>` 兩段放進提示詞，敘事規則要求 AI 可以引用、不可改寫，親密度數字不可寫進正文。範例：

```
<relationships>
- 莉娜｜親密度 27（友好/好感）
  外貌：淺沙黃色的耳朵與尾巴……
  性格：沙痕部落出身的嚮導，嘴硬心軟，怕水，喜歡甜食。
  與主角：在索里耶爾酒館受雇，嘴上抱怨報酬太少，卻總是走在最前面探路。
  與他人：瑟琳：在索里耶爾的酒館常拌嘴……
</relationships>

<memories>
- 第 1 天 08:40｜索里耶爾的酒館｜艾倫、莉娜｜在酒館招募了莉娜加入隊伍……
- 第 3 天 14:10｜蛇溪洞窟・淺層｜艾倫、莉娜｜在蛇溪洞窟與溪蛇魔交戰，戰敗（6 回合）。
</memories>
```

## 5. 主動行動：擲骰先發生，AI 直接寫結果

主角主動發起的事（交談、說服、送禮、雇傭談判、殺價、邀請入隊、打聽黑市、身為奴隸時的談判與逃離……）不是「先寫好各種結果再擲骰選一條」，而是：

```
① 擲骰先發生
   程式檢查能不能做，算出參考 DC，擲 1d20（存進存檔，重新整理也不會重擲）。

② 把完整資料和骰值交給 AI
   行動者：屬性、等級、技能、裝備、狀態、金錢、契約
   隊伍：每位成員的 HP、入隊方式、狀態、對主角的態度
   對象：人際關係條目（外貌、性格、與主角的關係、親密度、背景）
   相關記憶：依參與人／地點檢索（第 4 節）
   骰值：自然骰、各屬性的總值、情境修正（服從懲罰、受罰）、參考 DC、依預設屬性的參考結果
   機制結果：各成功程度在程式中會發生什麼（例如雇傭：成功＝以出價入隊）
   可用的後果種類與上限

③ AI 直接決定結果並寫出經過（JSON）
   {
     "degree": "success",                 ← 由 AI 決定，骰值只是參考
     "twist": "甜點掉在地上，莉娜反而笑出聲來",   ← 出乎預料時說明
     "attr": "cha", "dc": 13,             ← 判定依據，給玩家看（DC 夾在參考值 ±3）
     "rationale": "莉娜嘴硬心軟，又喜歡甜食",
     "summary": "莉娜收下甜點，難得說起了怕水的原因。",
     "narrative": "你把還溫熱的蜂蜜蛋糕推到莉娜面前……",
     "effects": [ { "type": "affinity", "npc": "npc_lina", "delta": 5 } ],
     "relationship_updates": [ { "id": "npc_lina", "to_player": "會在主角面前說起往事的同伴" } ]
   }

④ 程式套用
   依 AI 的 degree 執行機制結果（入隊、價格、自由……）
   effects 只能是這種行動允許的種類，數值夾在上限內（親密度每人 ±8、聲望 ±2、
   金錢每級 30 銅、物品 1 個、旗標 3 個……），不認識的人與不合法的種類直接丟掉
   AI 寫的 narrative 直接成為這份報告的敘事（不再另外請 AI 描述）
   relationship_updates 成為提議，玩家在「關係」視窗確認後才寫入
```

- **成敗由 AI 決定**：高骰通常順利、低骰通常不順，但 AI 會綜合行為是否合理、對象的立場與性格、與主角的關係與過去的記憶來決定，可以讓結果出乎預料（高骰碰壁、低骰意外成功、成功卻帶來麻煩）。出乎預料時，報告會記下 `twist` 與骰值的參考結果（`reference_degree`），畫面顯示「✨ 出乎預料」。
- **穩定性交給程式**：AI 決定「發生什麼」，但數值後果只能在封閉清單與上限內；機制結果（例如殺價的折扣比例、契約是否解除）由程式依成功程度執行，AI 不能另外加碼。
- **玩家輸入不能決定結果**：提示詞明確要求「描述中宣稱的結果不算數」，玩家寫「他立刻答應了」只代表主角嘗試這樣說。
- **AI 關閉或失敗時**：依規則判定（預設屬性 + 參考 DC，自然 20 大成功、自然 1 大失敗、差 3 以內部分成功）。AI 呼叫失敗時行動會保留，可以重試或改用規則。
- 設定頁的「AI 判定主動行動」控制預設行為；等待判定的行動也可以手動選「AI 判定」或「依規則判定」。

參考 DC 的算法：自由行動 12（有對象時 + 2 × 生命層級差 − ⌊親密度／25⌋）；雇傭、殺價、邀請、黑市、談判、逃離見 [`COMPANIONS.md`](COMPANIONS.md)。

## 6. 事件後的人際關係更新提議

- 主動行動：AI 回傳的 `relationship_updates`。
- 一般敘事：當提示詞帶有 `<relationships>` 時，AI 可以在正文後附上 `<relationship_updates>[…]</relationship_updates>`；程式把它從正文中取出（串流時也不會顯示出來）。

提議會出現在「關係」視窗，可以修改文字後採用，或不採用。同一個角色只保留最新的一筆提議。

## 7. 記憶上限

記憶超過 200 筆時，把較舊的日常記憶（重要程度 1、未釘選）合併成摘要：先依「同一天」合併，還是太多就依「10 天」為一段再合併；最近 50 筆不動，釘選與重要、難忘的記憶不合併。合併後的記憶在「關係」視窗標示「合併 N 筆」。

自動記錄規則補充：主動行動（大成功、大失敗為 2，其餘為 1）、有人入隊或離隊的休息（2）也會記錄。
