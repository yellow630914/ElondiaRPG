# 存檔

> 上層：[GAME_DESIGN](GAME_DESIGN.md)。依賴：[CONTENT_EDITOR](CONTENT_EDITOR.md)（世界與自訂內容）、[CONTENT_DEPENDENCIES](CONTENT_DEPENDENCIES.md)（讀檔時的清理）、[PORTRAITS](PORTRAITS.md)（形象圖）。各系統新增的存檔欄位記在第 5 節。

程式：`src/stores/saves.ts`（儲存位置、檔案格式）、`src/stores/game.ts`（存檔、讀檔、匯出、匯入）、`src/components/SaveDialog.vue`。

## 1. 存在哪裡

| 資料 | 位置 | 說明 |
|---|---|---|
| 進行中的遊戲 | IndexedDB `elondia` 的 `current`（`state`、`narrations`、`usage` 三筆 JSON 文字） | 每次動作後自動保存 |
| 存檔欄位（手動、快速、自動 ×3） | IndexedDB `elondia` 的 `slot_meta`、`slot_data` | 欄位存了當時的自訂內容 |
| 形象圖 | IndexedDB `elondia-portraits` | 依「種子:角色 id」保存，見 [PORTRAITS.md](PORTRAITS.md) |
| 世界（自訂內容）、模型來源、插圖設定、提示詞組、自動存檔輪替的位置 | localStorage（`elondia.worlds`、`elondia.settings`、`elondia.image`、`elondia.promptSets`、`elondia.autoIndex`） | 跟著瀏覽器走；存檔記住用哪個世界，見 [CONTENT_EDITOR.md](CONTENT_EDITOR.md) 第 0 節 |

瀏覽器不支援 IndexedDB 時（或打不開時）改存在 localStorage。

### 首頁與進行中的遊戲

- 打開遊戲先到**首頁**：▶ 繼續（有進行中的遊戲時，顯示角色、地點、天數與世界）、🆕 開新遊戲、📂 讀取存檔、🌍 世界管理、🧩 提示詞管理、⚙️ 設定。
- **啟動時不會自動進入遊戲**：只讀出進行中的遊戲放著，按「繼續」才載入（並切到它的世界）。遊戲中按右上角「🏠 首頁」會存好進度回到首頁。
- 開新遊戲或從首頁讀取存檔，會蓋掉還沒繼續的遊戲：先提醒，確定後把它**備份到自動存檔欄位**（「自動存檔（開新遊戲前）」「自動存檔（讀檔前）」），之後可以從讀取存檔找回。遊戲中讀檔照舊先自動存一份。
- F9 快速讀檔只在遊戲中有效（首頁要從「讀取存檔」讀，才會先提醒）。

### 進行中的遊戲的儲存

- 以前存在 localStorage（`elondia.save`、`elondia.narrations`、`elondia.usage`，上限約 5MB，玩久了會滿）。新版啟動時（`main.ts` 的 `preloadCurrent`，掛上畫面之前）把它們搬進 IndexedDB，成功後刪掉 localStorage 的舊資料。
- 寫入是非同步的：寫到一半又有新的動作時，只保留最新的一份，這次寫完再寫（不會排一長串）。
- **寫入失敗不再默默略過**：畫面上方一直顯示「自動保存失敗」的警告（空間不足時會說明），直到下一次保存成功；這段期間關掉或重新整理頁面，瀏覽器會先詢問。警告建議先匯出存檔，或刪掉用不到的存檔欄位與形象圖。

## 2. 匯出

「💾 存讀檔」的「📤 匯出目前進度」或欄位的「匯出」。下方可以勾選要附上的東西：

- **自訂內容**（預設勾選）：整份「🌍 世界」的自訂資料。存檔欄位匯出的是存檔當時的內容；舊的欄位沒有記下時，用這個瀏覽器目前的內容。
  附上整份而不是只挑存檔「用到的」：自訂內容彼此串在一起（特殊任務用到固定 NPC、怪物、物品，NPC 與怪物又用到技能、裝備底材），而且存檔之後才會遇到的任務、出沒的 NPC、商店的商品也都屬於這個存檔的世界；只挑一部分很容易漏掉。自訂內容通常只有幾十 KB。
- **形象圖**（預設不勾）：這一局（種子）所有角色的圖，轉成 data URL。圖片很大，檔案會變大很多。

檔案格式（JSON）：

```json
{
  "state": { "...": "遊戲狀態" },
  "narrations": { "日誌 id": { "text": "…", "status": "done" } },
  "usage": { "日誌 id": { "input": 0, "output": 0, "calls": 0 } },
  "content": { "version": 1, "enemies": {}, "items": {}, "bases": {}, "materials": {}, "npcs": {}, "stories": {}, "abilities": {}, "perks": {} },
  "portraits": { "pc": { "data": "data:image/png;base64,…", "prompt": "…", "service": "novelai", "time": 0 } }
}
```

`content` 與 `portraits` 都是選填的，舊版匯出的檔案照樣可以匯入。

- 匯出時記下存檔用的世界（`state.world` 的 id 與**名字**）。`content` 是那個世界的自訂內容（欄位存檔時附的；舊的欄位沒有時用這個瀏覽器裡那個世界的，不是目前作用中的世界）。
- **原版世界的存檔不附 `content`**，`state.world` 標明是原版（`{ "id": "vanilla", "name": "原版世界" }`）。

## 3. 匯入

匯入的存檔會加到列表（手動存檔），不會直接讀取。不會再把附帶的自訂內容合併進目前的世界：

- **遊戲中匯入**：存檔用的世界和目前的世界不同時**拒絕匯入**，提示「請回首頁匯入」（沒有記世界的舊存檔視為同一個世界）。
- **首頁匯入**：存檔附了自訂內容、而且它的世界在這個瀏覽器**不存在或內容不同**時，直接用附帶的內容**建立一個新的世界**，名稱用存檔世界的名字（同名已經存在時後面加 4 位數字，依內容固定算出，匯入面板預覽的名稱就是實際建立的），存檔改指向這個新世界；目前的世界不會變動。
  - 這個瀏覽器已經有**內容完全相同**的世界（例如同一個檔案匯入第二次）：沿用那個世界，不再建立。
  - 沒有記世界的舊匯出檔、但附了自訂內容：一樣建立新的世界，名稱「匯入的世界」。
  - 世界存在而且內容相同、原版世界、或沒有附內容時照舊。
- 會建立新的世界或附有形象圖時，先顯示匯入面板說明：
- **還原形象圖**（預設勾選）：同一個角色已經有圖時換成檔案裡的。圖片不會留在存檔欄位裡。

## 4. 清理形象圖

刪除存檔欄位、覆寫存檔欄位（包括自動存檔輪替）、開新遊戲時，收集進行中的遊戲與所有存檔欄位的種子（舊的欄位摘要沒有種子時讀整份存檔），不屬於任何一個的形象圖刪除。讀不到存檔列表時不清理。

## 5. 存檔格式的版本

存檔的 `state.schema` 記錄存檔格式的版本（`src/engine/state.ts` 的 `SAVE_SCHEMA`，目前是 9；沒有這個欄位的舊存檔視為 1）。

- 讀檔（`migrate`）時依序執行 `SCHEMA_STEPS` 裡比存檔版本新的轉換步驟，每一步做完就把版本記上去；同一份存檔不會轉換兩次。
- **以後改了存檔的結構**（新增必要欄位、改名、改格式）：`SAVE_SCHEMA` 加一，並加一個轉換步驟把舊資料補齊或改寫。不要只靠讀取時的 `??=` 補值，那樣分不出新舊存檔。
- 特殊地圖（[SPECIAL_MAPS](SPECIAL_MAPS.md)）存在 `state.areas` 的 `sm/<id>`（旅行、換地點時不清掉），在裡面時 `state.special` 記回程與要刷新的地圖；都是選填欄位，不用轉換。這個世界沒有的特殊地圖在讀檔時作廢（`pruneSpecialMaps`）。
- 店名（[TRADE](TRADE.md) 2.1 節）：AI 取的店名存在 `state.shopNames`（選填，不用轉換）；規則生成的店名每次重算，不存檔。
- 存檔來自**比較新的版本**（`schema` 大於目前支援的）：拒絕讀取與匯入，並說明要先更新遊戲，不會硬讀而把存檔弄壞。啟動時讀不了進行中的遊戲，會顯示原因而不是當掉，也不會用空資料蓋掉它（開新遊戲或讀取存檔才會蓋掉）。
- 1 → 2：加上公會的階級與功績（`guild`，沿用依等級換算的階級）、存檔規則（`options`，戰敗時失去一半），正在地下城裡的存檔從現在開始記這趟探索（`expedition`）。
- 2 → 3：加上房屋（`homes`，空的；見 [HOMES.md](HOMES.md)）。留守的夥伴記在 NPC 登錄的 `staying`，工藝等級記在角色與 NPC 登錄的 `crafts`（都是選填，不用轉換）。
- 3 → 4：主人的家改成每座聚落固定的民宅：`homes` 裡主人的家（`m-` 開頭、有 `master`）拿掉，改記 `masterHome`（主人、城市、家裡的人、房子的規格 `district`），家裡的人保留；**規格沿用舊的房子**（舊版主人沒有身分標籤時看空地的地段，可能是三層的豪宅），站在裡面的人位置照樣有效；地圖不再存檔（見 [COMPANIONS.md](COMPANIONS.md) 3.4 節）。
- 4 → 5：名單的 AI 潤飾改成記在每個人身上（NPC 登錄的 `flavored`）：整份潤飾過的名單（舊的 `roster.flavored`），上面程式生成的人都記成潤飾過，拿掉名單上的記號（見 [NPC_SYSTEM.md](NPC_SYSTEM.md) 第 10 節）。
- 5 → 6：刺青。角色身上的奴隸契約（`contract`）搬進刺青清單（`tattoos` 的奴隸印記，契約掛在 `contract`）；沒有存條款的印記補上模板的條款，條款加上部位（見 [TATTOOS.md](TATTOOS.md) 第 2 節）。隊伍與 NPC 登錄裡的角色都轉換。

這個機制之前的轉換（飾品欄位、夥伴系統、事件記憶……）仍在 `migrate` 的前半，用各自的檢查判斷要不要做。

## 6. 日誌瘦身

日誌（`state.reports`）每一則都帶著隊伍快照、經過的時間軸與變化清單，玩久了會讓存檔越來越大。程式：`src/stores/logArchive.ts`。

- 設定的「💾 存檔」頁籤可以設定**完整保留最近幾則日誌**（預設 200，50～5000）。超過 50 則以上時，最舊的整理到只剩保留的數量。
- 整理後的紀錄放在 `state.logArchive`：時間、地點與場景、簡述、AI 寫的經過（有寫過時），以及這則用掉的 token。日誌最上方載入完之後可以按「📦 顯示封存的舊紀錄」。
- **token 用量分開算**：用量依日誌 id 記在 `usage` 裡。封存時，那幾則的用量（含依功能與模型來源分開的明細）併進 `_archive`，本局的合計與各來源的合計都不會變少。日誌上方分開顯示「日誌」「已封存的日誌」「其他（酒館候選人、商店清單、談判方式等）」。
- 送給 AI 的提示詞本來就不包含過去的日誌（人際關係與記憶另外記在 `relationships`、`memories`），所以封存不影響 AI 看到的內容。
- `logArchive` 是選填欄位，不影響存檔格式；舊版本的遊戲讀到整理過的存檔，只是看不到封存的紀錄。
