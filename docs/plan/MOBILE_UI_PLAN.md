# 手機版 UI 計畫

> 上層：[計畫與追蹤](README.md)。狀態：**實作中**。M1（探索畫面的骨架）、M2（分頁滑動）、M3（細修）已完成，見第 5 節；其餘照這份計畫繼續。

樣稿：`docs/mockups/mobile.html`（可以直接在手機上點）。電腦版維持原樣，只在 **720px 以下**換成這套版面（平板橫拿照舊是電腦版），面板元件共用。

---

## 1. 前提

- **直式**、單手操作。
- 先做**一般探索**畫面；戰鬥畫面之後另外規劃。
- 使用頻率（高 → 低）：地圖移動 → 切換地圖（換區域） → 設施選項 ≈ 這裡的人 ≈ 主動行動 → 隊伍 → 長休／短休 → 其他。
- 行囊目前用得少，但以後可能變多。

## 2. 版面

```
┌────────────────────┐
│ 狀態列：時間 地點 金錢 🔔 │  只看不按（待處理的鈴鐺除外）
├────────────────────┤
│ 地圖（可收成一條）        │
├────────────────────┤
│ 冒險日誌                │  最下面是等待判定的行動
├────────────────────┤
│ 🎲 主動行動：想做什麼…     │  點了展開
├────────────────────┤
│ [ 進入○○ ] 情境按鈕       │  站在設施上、或旅途中才出現
├────────────────────┤
│ 地圖│隊伍│休息│這裡│更多   │  底部分頁列
└────────────────────┘
```

要按的放下面（拇指好按），上面只放資訊。

### 2.1 主畫面：探索／閱讀兩種狀態

| 狀態 | 地圖 | 日誌 | 什麼時候 |
|---|---|---|---|
| 探索 | 大，好點 | 剩下的空間 | 點地圖那一條、或底部「地圖」 |
| 閱讀 | 縮成一條（地名、所在設施、展開鈕） | 整頁 | AI 寫了一段敘事時自動切過來 |

- **鍵盤打開時地圖自動收起**（文字框拿到焦點時；實作時再用 `visualViewport` 的高度變化輔助判斷）。鍵盤收起時：中間有新的敘事就維持閱讀狀態，沒有就放回原本的狀態。用 AI 判定送出主動行動時，因為敘事會來，維持收起；規則判定沒有敘事，地圖放回來。在主動行動列裡換到選單（對象、能力）時也維持收起。
  - **注意**：收起地圖時不能重畫主動行動列。重畫會換掉文字框，焦點跑掉、鍵盤立刻收起，而且手機上只有點擊才能再打開鍵盤（樣稿 v2.1 有這個 bug，v2.2 修好）。打到一半的文字另外存著，萬一重畫也不會不見。
- **只能點相鄰的格子**，一次走一步。點到其他格子不會動，相鄰的格子閃一下提示能走哪裡。走錯比沒點到更煩，所以不做「點遠處自動走」，也不放大地圖。
- 切換地圖＝走到出口格（出城、進地下城、下一層），不另外加按鈕；出口格用醒目的顏色和目的地名稱。

### 2.2 設施：情境按鈕

站在設施上時，底部列上方出現「進入○○」，點了滑出設施面板（選項＋這裡的人）。設施的「購買」「出售」打開交易頁（全螢幕，見 2.6）。

### 2.2.1 旅途

城門的「啟程旅行」選目的地之後，地圖換成**旅途進度條**（起點、每一天一格、終點；路上的事件先標「?」），情境按鈕變成「前進一天」（最後一天是「前進一天，抵達○○」）。遇到事件時打開事件頁（全螢幕）。閱讀狀態時進度條縮成一條，寫著「起點 → 終點・第 N／M 天」。

### 2.3 底部分頁列

| 按鈕 | 內容 | 提醒 |
|---|---|---|
| 地圖 | 切換探索／閱讀狀態 | — |
| 隊伍 | 分頁：隊伍｜行囊 | 有人可以升級 |
| 休息 | 短休、長休、生命骰 | — |
| 這裡 | 這裡的人、意圖（主動行動在日誌底部，見 2.5） | 身邊的人數 |
| 更多 | 次級選單（見 2.4） | 底下項目的提醒加總 |

「休息」「這裡」「更多」打開**半屏面板**（從下往上滑出；拉把手可以拉到全螢幕，往下拉或點外面關掉）；「隊伍」打開全螢幕頁面（見 2.6）。

行囊以後用得多，再升格成底部的獨立按鈕。

### 2.4 更多（次級選單）

關係、筆記、工藝、契約（有契約時）、存讀檔、快存、快讀、設定、語言、提示詞、世界、首頁。快存、快讀、語言、首頁直接執行，其他打開全螢幕頁面。

### 2.5 主動行動：日誌底部（和電腦版一樣）

- 日誌和情境按鈕之間一條「🎲 主動行動：想做什麼…」，點了展開：AI 判定開關、對象、搭配能力、對象標籤、文字框、「行動」。
- 擲完骰的行動顯示在日誌最下面（同電腦版的 `PendingActionCard`），判定完換成這次行動的日誌；等待時這一列不能送出。
- 「這裡的人」每一列有「🎲」：把這個人加進對象並展開這一列。

### 2.6 半屏面板與全螢幕頁面

| 種類 | 用在 | 關閉 |
|---|---|---|
| 半屏面板（快速操作） | 這裡、休息、設施、更多、旅行目的地 | 往下拉、點外面、右上 × |
| 全螢幕頁面（內容多） | 隊伍（隊伍｜行囊）、角色詳情、交易、事件、待處理、關係、筆記、工藝、契約、存讀檔、設定 | 左上角「←返回」 |

- 頁面裡再開頁面（隊伍 → 角色詳情），「←返回」回到上一頁。
- **從半屏面板打開的頁面，返回後面板還在**（更多 → 筆記 → 返回，回到「更多」；鐵匠鋪 → 購買 → 返回，回到鐵匠鋪）。做法是頁面蓋在面板上面、不關掉面板，捲動位置也留著。
- **有分頁的頁面可以左右滑換分頁**：隊伍（隊伍｜行囊）、角色詳情、交易。
  - 所有分頁並排在一條軌道上，**內容和分頁底線跟著手指移動**；放開後拉過四分之一寬、或甩得夠快就換頁，不然彈回，用減速的緩動停下來。
  - 一開始先判斷方向（移動 8px 後）：橫的才接手，直的交給上下捲動。從分頁列開始的滑動不算（分頁列自己可以橫向捲）。
  - 第一頁往右、最後一頁往左拉得動但有阻力，放開彈回；不會返回上一頁，避免誤觸。拖動結束時不觸發手指下的按鈕。
  - 點分頁也是同一個滑動動畫；容器高度跟著目前的分頁慢慢變。
  - **注意**：軌道的位移要用每一頁自己的寬度算（`translateX(-i × (100% + 間距))`），不能用外層容器的寬度：兩者差幾 px，分頁越後面偏得越多（樣稿 v2.2 的「能力」頁偏了一截，v2.3 修好）。分頁之間留 32px 間距，隔壁頁的邊不會露出來。
- **手機的返回鍵**（Android 返回鍵、iPhone 邊緣右滑、瀏覽器上一頁）和左上角「←返回」一樣：先關最上層的頁面，再關半屏面板，都關了才離開遊戲。做法是每打開一層就 `history.pushState` 一筆，返回鍵觸發 `popstate` 時關掉最上層；用畫面上的按鈕關掉時把那一筆退回去。必須回應的事件頁按返回鍵不會關，只提示「先選一個選項」。
- 必須回應的事件頁沒有返回鈕，選了選項才關。
- 分頁多的頁面（角色詳情的六個分頁）分頁列可以左右滑。

## 5. 實作進度

| 階段 | 內容 | 狀態 |
|---|---|---|
| **M1 骨架** | `components/mobile/`：`mobile.ts`（720px 判斷、返回鍵的層級堆疊）、`BottomSheet.vue`（半屏面板）、`MobileGame.vue`（狀態列、地圖的探索／閱讀狀態、日誌、情境按鈕、底部分頁列、這裡／休息／設施／更多面板）；`AppDialog` 在手機上變成全螢幕頁面、左上角返回、接上返回鍵；`ActionPanel` 手機上收成一行；隊伍頁的「隊伍｜行囊」分頁 | 完成 |
| **M2 分頁滑動** | `components/mobile/SwipeTabs.vue`：隊伍（`App.vue`）、角色詳情（`CharacterDialog`）、交易（`ShopDialog`）；手機上行囊與商店的物品列改成兩排 | 完成 |
| **M3 細修** | 逐頁截圖檢查（隊伍、角色詳情各分頁、關係、筆記、工藝、存讀檔、設定、提示詞、世界、休息、這裡、旅行、旅途）：地圖面板與日誌的標題列縮短、旅途與休息、設施面板不重複標題、工藝的技能表可以橫向捲動 | 完成 |
| M4 戰鬥 | 等慾望條定案（慾望戰鬥已合併）後規劃戰鬥畫面 | 還沒做 |

M1 的做法：
- `App.vue` 在手機版、冒險頁時不畫電腦版的上方列與三欄，換成 `MobileGame`；對話框（隊伍、筆記……）照舊由 `App.vue` 管，`MobileGame` 用 `open` 事件請它打開。
- 面板（地圖、這裡的人、地點、休息、行動備註、日誌）都是原本的元件，放進手機的容器裡；`RoadPanel` 在手機上不畫自己的「往前走」按鈕（在情境按鈕）。
- 情境按鈕：旅途中往前走；站在 `floor`、`wall`、`water`、`road` 以外的格子（或特殊任務點、房屋裡）時，「進入／查看○○」打開地點面板（`PlacePanel`）。

M2 的做法（`SwipeTabs`）：
- 預設插槽 `#default="{ id }"` 依分頁 id 畫內容；手機上（`swipe`）所有分頁並排在軌道上，只畫目前與相鄰的分頁（看過的保留）。電腦版：`all` 時依序畫出所有分頁（交易視窗的左右兩欄），否則只畫目前的分頁，外觀和原本一樣。
- `bar` 時自己畫分頁列與跟著拖動的底線；`#tab` 插槽可以放圖示、提醒點（角色詳情用）。電腦版的角色詳情照舊用自己的分頁列。
- 滑動範圍是整個頁面（`AppDialog` 的內容區，設 `touch-action: pan-y`），內容很短時在下面的空白處滑也可以；在輸入框、選單、分頁列上開始的不算。

M3 的檢查結果：
- 全螢幕頁面原本就大多是單欄（角色詳情、紙娃娃、刺青圖、關係都有窄螢幕的排版），沒有超出畫面寬度的內容；只有工藝的技能表撐開畫面（grid 子項目要 `min-width: 0` 才會在自己的框裡捲動）。
- 地圖格子：遊戲預設 9×7 在手機上每格約 40px，夠點；最寬 13 格時約 28px，照計畫不放大（只能點相鄰的格子，點不到不會走錯）。
- 旅途：地圖面板本來就把路畫成一排格子（一格一天），當作進度條用，不另外做。
- 提示詞、世界頁在手機上可以用（沒有超出寬度）；要不要限制成只能看，留到 3 節。
