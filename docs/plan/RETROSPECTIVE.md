## 1. 規則、數值與平衡

**代表問題**

- 怪物生命的重新平衡做了兩次，因為耐久模擬器的抗性正負號寫反（8b7ea7f → e30bcca）。`enemies.json` 前後改了 52 次。
- 戰士命中後行動點淨賺，運氣好可以一直打到敵人全滅（9f6fc25），之後全部怪物重調（296a463）。
- 抗性原本相加，兩件 −75% 就完全免傷，改成相乘（dcf70e5）。
- 升級太快：史詩線 17～19 級才開，第三個任務就滿級。每級經驗 100 → 135 → 150 × 等級（0d67a0b、77d5aa6）。
- 做不完、拿不到的內容：
  - 玉璘族的預設出生地沒有路（6dba342）；
  - 沿海洞窟線在臨時地圖倒下就卡住（69fc5a8）；
  - 情報商賣做不完的任務（ac786cd）；
  - A／S 級一般委託不會生成（L1）；
  - 哥布林左耳（L4）；
  - 拿不到的特質、拿不掉的缺陷（L5）。
- 可以濫用：撤退失敗再打贏比撤退成功還省時間（原 B9）；物價上限 1 億（L2）。

**為什麼**：數值靠模擬器擬合，但模擬器和規則一直在變；內容一天可以加 22 批（10-26，四百多個任務），卻沒有自動檢查「拿得到、做得完」。

**怎麼擋**：`balance.spec`、`bossFight.spec`（要設環境變數才跑）、世界檢查工具的勝率模擬（至少 40 場）、特殊任務檢查的提醒。

**還開著**：L1～L5、R1 數值平衡。

## 2. 存檔相容與遷移

**代表問題**

- 存檔格式從 2 升到 11，共 10 次（37d9d1b～fb290bc）。其中 7、8、9 是 10-23 兩小時內連升三次，都在修名稱產生器做出的「鐵鐵腰帶」「鐵鐵靴」（8cbddd8、30c41e7、33147d7）。
- 格式 4 的遷移把主人家的人放到地圖外（220ee5c）。
- 匯入存檔時把內容併進錯的世界（原 B8，5ed33e0）。
- 自動存檔寫入失敗被默默吞掉，後來改用 IndexedDB 並顯示警示（1d4ba84）；上傳的圖示讓存檔膨脹（16facfd）。
- 改名就要遷移：獨特裝備改名（db1dcbf，格式 10）、「魅魔女王」改名（格式 11，存過之後 0.3.7 讀不了）。
- 改過敘事規則的玩家拿不到新規則，要自己按「恢復預設」（v0.2.2、v0.3.7）。

**為什麼**：存檔用物品的顯示名稱當 key，所以改名等於改存檔格式；`migrate()` 是每次讀檔都跑一遍的修補，一直往上疊。

**怎麼擋**：讀到比較新的存檔會擋下（`assertSchema`）；`saves.spec`、`saveBundle.spec`、`storySave.spec`；存檔樣本 `fixtures/saves-v0.2.5.json`；會弄壞任務進度的編輯擋儲存（C1，f9594fa）。

**風險**：只有 v0.2.5 一份存檔樣本，沒有逐版測試遷移。

## 3. 自訂內容與世界編輯器

**代表問題**

- W1～W4：整理內容時先登錄才檢查，同一包裡互相引用的新特質、新商店、新怪物、自動生成的裝備被默默丟掉（9d19516 → c8a4b31）。
- W6 指定的技能獎勵被換成隨機的；W8 普通人沒寫類型就變成能雇用的戰士；W9 特殊地圖 id 拼錯，任務點被搬到萊茵堡下水道。
- W12～W14：地標放在牆上、商店放不下、掉落引用不存在的東西，都沒有提示（369a45c）。
- W20～W23：世界檢查工具本身誤報、行動點估錯、勝率雜訊太大（4754438）。
- 重構後特質編輯器的上限檢查失效（55bcfce）。

**為什麼**：匯入時寬鬆接受、默默修正，丟掉欄位不報錯；引用檢查散在各個 `sanitize` 函式。

**怎麼擋**：世界檢查工具與 `worldCheck.spec`（afa3bee）；刪除、改名時檢查誰在用（396fc69）；檢查結果分成錯誤與提醒（C2）；編輯器改用下拉選單（6d0b59c）。

**還開著**：L2、L3、點子 I12。

## 4. AI 提示詞與敘事

**代表問題**

- AI 判定讓金錢變負、送出比持有還多的物品、寫出不存在的勢力（4dea71f）；規則和 AI 都付錢時重複入帳（c1dbaf4）；程式裁掉金額後，正文還寫原本的數字（33147d7）。
- 被制伏的俘虜在正文裡自己走掉（e23962a）；多人行動把同行的人寫成入隊（6f97768）；正文承諾給物品或答應入隊，實際沒給（I3、I11）。
- 判定提示詞有兩條「9.」、快取的前段不穩（原 B10、L9）；敘事規則的段落規則互相矛盾（f4b79bc）。
- 成人分流漏接：
  - 任務的親密場景被一筆帶過（30ae134）；
  - 旅途事件沒交給成人寫手（d10089b）；
  - 成人的前文接進一般請求（0cc802f）。

**為什麼**：規則和正文是兩個真相來源；成人分流的判斷散在各模組。

**怎麼擋**：效果超出上限時裁掉，並把實際結果交給寫手；`continuity.ts`；`adult_scene` 統一分流；`narrativeFlow.spec`、`aiJoin.spec`。

**還開著**：點子 I2（正文輸出檢查）、I3。

## 5. 效能

**代表問題**

- 自動存檔經過 Vue 的響應式代理，每次動作前還深複製日誌。大存檔走一格從 24 ms 降到 1 ms（6d0b59c）。
- NPC 階段同步每次回傳新物件，地圖一直重繪（39c3bdf）。
- 每走一步都掃一遍 408 個任務和小隊表，王都每步 45 ms → 9 ms（3308453、b97f8f1）。
- 頭目慾望上限用的生命中位數快取沒有跟著世界設定失效（2f3be99）。

**為什麼**：「每一步全部掃一遍」的寫法隨內容量變慢；加了快取之後，什麼時候失效成了新風險。

**怎麼擋**：`contentRevision` 內容版本號、`contentCache.spec`。

**風險**：沒有效能基準測試；城鎮地圖快取的失效條件靠手動列舉（`invalidateBlocks`）。

## 11. 最常重複的五個模式

1. **內容先大量上線，實測後才補**：九個實測修正包。
2. **同一件事有好幾份**：JSON、產生器、文件、世界書、CHANGELOG 互相漂移。
3. **默默修正、不報錯**：整理自訂內容時丟欄位、AI 效果被裁掉、存檔寫入失敗。
4. **名稱就是 id**：改名就是存檔遷移（格式 7～11）。
5. **平行分支撞熱點檔**：規則被另一條分支推翻，而且推送時沒有 CI。

## 12. 預防的建議（還沒決定）

1. **CI**：每次推送就跑 `vitest` 與型別檢查（`vue-tsc`）；缺 Python 時攻略測試要失敗，不要略過。
2. **可達性檢查**：擴充世界檢查工具，確認每個物品、特質、缺陷的去除方式、每個任務都有來源、做得完；L4、L5 這類問題變成測試。
3. **存檔**：物品改用穩定的 id，顯示名稱可以隨便改；每個版本留一份存檔樣本，跑遷移測試。
4. **熱點檔**：
   - CHANGELOG 改成每條分支一個片段檔，發布時才合併；
   - 已發布的段落和標籤比對，被改到就失敗；
   - 產生器重跑後 `git diff` 必須是空的。
5. **集中邊界與正文檢查**：
   - 年幼、成人向、死亡、被制伏、不能攻擊做成共用的判斷，加一個測試掃過全部內容；
   - 實作點子 I2，比對正文裡的物品、金額和入隊。
