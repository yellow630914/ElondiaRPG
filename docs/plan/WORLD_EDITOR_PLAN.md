## 1. 局部匯入（E1、E2）

### 1.1 現況：不能局部匯入

| 入口 | 位置 | 行為 |
|---|---|---|
| 📥 匯入成新的世界 | `WorldBar.vue` → `content.importWorld` | 整個世界包／內容檔建成**新的世界** |
| 📥 匯入自訂內容 | `ContentView.vue` 頁尾 → `content.importMods` | **取代目前世界的全部內容**（按鈕只有 `title` 提示，沒有確認） |
| 匯入存檔 | `SaveDialog` → `worldForImport` | 存檔附的內容不同時建新的世界 |

- 也就是說：想把別人做的「一個任務＋它的兩位 NPC＋一件報酬」放進自己的世界，目前只能手改 JSON。
- `stores/content.ts` 已經有 `diffMods`（逐項比對：新增、不同、相同，key 是 `區塊:id`）與 `mergeMods`（只合併勾選的、合併進來的任務有錯誤就保留原本的版本），但**沒有任何畫面在用**（存檔匯入改成建新世界之後就沒人呼叫了）。這是局部匯入現成的底。
- 缺的是**正向的引用表**：`usage.ts` 只回答「誰用到 X」（擋刪除用），沒有「X 用到誰」。沒有它就算不出「選了這個任務，要連帶哪些東西才不會壞」。

### 1.2 顆粒度：最小單位是「一個內容項目」，匯入匯出的單位是「項目＋所有關聯的閉包」

**原子＝`ContentMods` 的一筆**（`區塊:id`，物品是 `items:名稱`）。不能再切細：

- 任務點不能單獨匯入：任務點之間靠同一個任務的旗標串起來，開頭旗標還有「不能和別的任務重複」的檢查；拆開就失去意義。要拿別的任務的幾個任務點，用「複製任務再刪」。
- 怪物的掉落存在怪物身上（[CONTENT_EDITOR](../CONTENT_EDITOR.md) 第 2 節）：物品和掉落它的怪物靠這筆關聯一起走（見下面的關聯表）。
- 設定類只有一筆的（`eventRules`、`markRules`、`bindRules`、`categoryIcons` 的每一類）整筆選；被選的項目關聯到它時（例如奴隸印記 → 印記設定）一樣帶上。

**關聯只有一種，一律一起帶**（2026-10-30 決定：不分硬依賴、軟依賴）：

- 「A 關聯到 B」＝ A 的資料裡寫了 B 的 id 或名稱，**或** A 讀到的劇情旗標、劇情計數器是 B 寫的（設定、清除、加減）。
- 匯入、匯出時，選了 A 就一定帶上 A 關聯到的所有 B，再帶上 B 關聯到的……直到沒有新的（**閉包**）。清單上這些項目打勾、不能取消；要不帶，只能連 A 一起不選。
- 只算**來源世界的自訂內容**（自建的與修改過的內建）：沒有修改的內建項目每個世界都有，不用帶；`ai:` 旗標、園區印章這類由 AI 或引擎寫的旗標沒有內容可以帶，列在預覽的「外部旗標」，不擋。
- **方向**：只沿著「A 用到誰」走，不反過來帶「誰用到 A」。用到 A 的東西留在來源世界不會壞，匯進來的東西也不會少任何引用；反過來帶的話，選一件常用的物品就可能把半個世界拉進來。預覽會列出「來源世界還有哪些東西用到它」，要的話自己勾（勾了就照樣帶上它的閉包）。

**關聯表**（E1 要寫成 `src/engine/contentRefs.ts` 的 `refsOf(section, id, entry)`；只讀資料，不改任何規則）：

| 項目 | 關聯到 |
|---|---|
| 特殊任務 | 固定 NPC（開頭、`at.npc`、`foes`、`allies`、`join`／`leave`、`deaths`、效果的 NPC、主人、好感條件與好感檢定）、怪物（`enemies`）、物品（效果、報酬、`start.items`、`wear` 的名稱）、底材／材料（裝備效果、`wear` 的底材 id）、技能、特質、非戰鬥狀態、刺青圖樣、奴隸印記、其他特殊任務（`start_story`）、地標與自建商店（`at.cell`）、特殊地圖（任務點與傳送）、劇情計數器；讀到的旗標與計數器的寫入者 |
| 固定 NPC | 技能、特質、底材／材料（裝備）、地標（`landmark`）、特殊地圖（固定格子）、自建商店（`keeper`）、小隊隊員、`relations` 裡的其他 NPC；`requires`、`stages` 讀到的旗標的寫入者 |
| 物品 | 底材、材料、狀態、非戰鬥狀態、特質（書籍）、其他物品（燃料、配方、種子）；**掉落它的怪物**（掉落存在怪物身上，算物品的關聯） |
| 怪物 | 技能、物品（掉落） |
| 地標 | 特質（受訓）、效果裡的物品／技能／特質／非戰鬥狀態／刺青、場景的 `cast`；讀到的旗標的寫入者 |
| 特殊地圖 | 怪物（遭遇表、BOSS 格）、物品（採集物）、商店、通道接到的其他特殊地圖與園區；讀到的旗標的寫入者 |
| 事件（旅途、城鎮、地下城） | 物品、特殊任務（`start_story`）、特殊地圖、自建商店、非戰鬥狀態；讀到的旗標的寫入者 |
| 主人的事件 | 刺青圖樣、技能（`teaches`）、物品；讀到的旗標的寫入者 |
| 商店 | 物品（固定清單）、特質（受訓） |
| 技能／狀態／特質／非戰鬥狀態 | 狀態、其他狀態、其他特質（前置、互斥）、其他非戰鬥狀態 |
| 奴隸印記 | 印記設定（用到這個印記時） |

- **一致性測試**：`contentRefs` 和 `usage.ts` 是同一件事的兩個方向，加一個測試：對內建資料與測試用的世界，`usage(B)` 列出的每個 A，`refsOf(A)` 都要包含 B（反過來也一樣）。以後新增引用欄位時兩邊一起改，避免 [RETROSPECTIVE](RETROSPECTIVE.md) 第 3 節的「引用檢查散在各個 sanitize」再發生。
- **閉包可能很大**：旗標把同一條故事線的任務串在一起，選一個任務通常會帶上整條線與線上所有的 NPC、物品。預覽要依類別分組、可以收起，最上面寫總數（「選了 1 項，連帶 23 項」）。

### 1.3 撞名：只在撞到時改名，不在每個 id 後面加 hash

（2026-10-30 討論「匯入匯出時所有 id 後面加 8 位 hash」的結論。）

全部加 hash 的問題：

| 問題 | 說明 |
|---|---|
| 內建項目不能改 id | 修改過的內建項目靠內建 id 對應；任務引用的內建 NPC、怪物也是內建 id。所以只能加在自建的上，「全部」本來就做不到 |
| 同一包匯入兩次會變兩份 | hash 每次不同：同一位 NPC、同一個任務出現兩份，遊戲裡真的會有兩個人、兩個任務。hash 依內容算：內容一樣的會合併，但**改過一個字的新版本**又變成另一份，舊版不會被取代 |
| 物品的 key 是名稱 | 物品用中文名稱對應（存檔、掉落、配方都是），加 hash 會變成玩家看得到的「鐘樓的鑰匙a1b2c3d4」 |
| 旗標加了會斷線 | 任務刻意讀別條線或內建的旗標（例如 `wt_open`）時，改了就讀不到 |
| 長度與格式 | 非戰鬥狀態的 id 限 `mod_cond_` ＋ 24 字、旗標與任務 id 限 40 字、物品名稱限 20 字；每次匯出再加一次會越來越長 |
| 其實很少撞 | 自建的 id 本來就是 `mod_<種類>_<時間><亂數>`，不同世界各自建的幾乎不會撞；會撞的通常是**同一個來源**（複製的世界、同一包匯進兩個世界），那時撞名的意思是「同一個東西的不同版本」，加 hash 反而讓它們變成兩個東西 |

所以改成：

1. **建立時就夠唯一**：`newModId` 的亂數由 3 碼加到 8 碼；地標、特殊地圖、自建商店的 id 產生方式一樣加長（格式照舊）。
2. **匯入時逐項判斷**（只看自訂內容）：
   - 目標世界沒有 → 直接加入。
   - 有、內容完全一樣 → 沿用，不加第二份。
   - 有、內容不同 → **衝突**，三選一：**用檔案的取代**、**保留這個世界的**、**另存一份**。
3. **另存一份才改名**：自建的 id 加 8 碼 hash 後綴（依檔案的內容算，同一包重複另存會得到同一個 id，不會越存越多）；物品改成「名稱（2）」這種看得懂的名字；包裡**所有**引用它的地方一起改。內建項目的修改不能另存，只有取代或保留。
4. **旗標**：只在「開頭旗標和目標世界的任務撞到」（`storyCheck` 本來就判錯誤）時，替包裡這條線自己的旗標（寫入者全在包裡的）加同一個前綴；讀外部旗標的不動。
5. **指紋**：hash 拿來當**內容指紋**很有用：匯出時每一項記 `meta.fingerprints`，匯入時一眼看出「和上次匯入的同一包」「同一個東西的新版本」，預覽可以直接寫「這是新版本，建議取代」。

### 1.4 不在世界內容裡、要另外說明的

- **固定 NPC 的形象圖**：存在 IndexedDB（`stores/portraits.ts`），不在 `ContentMods`。第一版不帶，預覽上註明；之後可以在局部匯出時選「附上形象圖」（另一個欄位，大小要提醒）。
- **世界書條目**：在提示詞組裡，靠關鍵字觸發，沒有 id 連到 NPC，算不出關聯。第一版不帶；之後可以選「附上關鍵字提到這些名字的新增條目」。
- **地圖位置**：自建地標、自建商店、固定在格子上的 NPC 可能和目標世界自己擺的東西撞格子。合併後照常跑 `computePlacements`／`landmarkSpotProblem`，預覽列出「擺不上去」的項目（目前套用時才會出現在頁面上方）。

### 1.5 流程與畫面

**來源**（同一個對話框）：

1. 檔案：世界包、內容檔（包括局部匯出的小檔）。
2. **這個瀏覽器的其他世界**：「從另一個世界帶入」——目前做不到，最常見的需求（在測試用的世界做好一個任務，搬到正式的世界）。

**對話框**（新元件 `ImportPickerDialog.vue`，取代頁尾「📥 匯入自訂內容」的直接取代）：

```
┌ 從「某某世界」帶入 ───────────────────────────────────┐
│ 搜尋…   [只看衝突]                                       │
│ ⭐ 特殊任務                                              │
│  ☑ 鐘樓的幽靈            新增　　（選了 1 項，連帶 5 項）  │
│     └ 🔒 固定 NPC 艾德溫        新增（任務的開頭）        │
│     └ 🔒 物品 鐘樓的鑰匙        新增（完成報酬）          │
│     └ 🔒 特殊任務 鐘樓的幽靈・二  新增（寫 🚩bell_open）  │
│     └ 🔒 怪物 鐘樓的石像鬼      和這個世界的不同 ⚠        │
│           ( ) 取代  ( ) 保留這個世界的  (•) 另存一份       │
│  ☐ 港口的走私者          這是新版本（指紋）⚠              │
│ ℹ 來源世界還有 2 項用到「艾德溫」：…［一起帶］             │
├────────────────────────────────────────────────────┤
│ 檢查：✅ 可以匯入；外部旗標 ai:bell_seen（由 AI 判定寫）   │
│ 不會帶入：形象圖、世界書條目                               │
│                                   [取消]  [帶入 6 項]     │
└────────────────────────────────────────────────────┘
```

- 勾選一項時自動勾上它的閉包（🔒，只要被選的項目還在就不能取消）；取消勾選時，只被它拉進來的一起取消。
- 衝突一定要選完三選一才能按「帶入」（因為關聯一定要帶，不能「略過這一項」）。
- **預檢查在沙盒裡跑**：`clone(目前的內容) ＋ 選取的項目（已經套用改名）` → `normalizeMods` → `dropBrokenStories`，和整理前比對，列出「會被拿掉的引用」（照理應該是 0，不是 0 就是 `contentRefs` 漏了，當成程式錯誤）、「有錯誤的任務」、「擺不上去的位置」；跑完 `applyContent(目前的內容)` 還原（`diffMods` 現在就是這樣做）。有錯誤的任務不能帶入時，**整包不帶入**（不能只拿掉它，因為別的項目可能關聯到它）。按「帶入」才真的寫進世界（`mergeMods`，擴充成收「取代／保留／另存」）。
- 原版世界不能帶入（和現在一樣要先建世界）。
- 頁尾的「📥 匯入自訂內容」改成開這個對話框；「整個取代」變成對話框裡的一個選項（全選＋「取代目前的內容」），要再確認一次。

**局部匯出**：清單多一個「選取」模式，勾幾項 → 「📤 匯出選取的項目」，自動帶上閉包，存成一般的內容檔（`type: elondia-content`，多一個選填的 `meta`：`picked` 記原本勾的是哪幾項、`fingerprints` 記每一項的指紋）。不用新格式，舊版也讀得懂。

## 2. 世界編輯器的介面整理（E5）

**界線**：只改 `src/components/ContentView.vue`、`WorldBar.vue`、`src/components/content/` 與 CSS；編輯器交給 store 的資料形狀不變，`engine/` 不動。保險：先加一個**來回測試**——每個編輯器打開內建項目、不改任何東西按儲存，`ContentMods` 不能多出任何一筆；整理前後都要過。

## 3. 特殊任務的流程圖（E3）

### 3.1 現況

- 任務點的順序與分支完全由旗標表達（[STORY_QUESTS](../STORY_QUESTS.md) 第 1 節「不用畫流程圖」）。編輯器只有**任務點清單**（每列標「需要 🚩」「→ 🚩」「✅／❌」）和**旗標流向表**（`flagUsage`：每個旗標誰設定、誰清除、誰需要），要在腦中把表拼成圖。
- repo 裡有離線的 `worldgen/tools/flowdoc/flowdoc.py` → `ElondiaQuestFlows.html`：只看內建任務、要手動重跑，而且是**時間軸卡片**（任務點往下排、分支縮排），不是圖；自建的任務看不到。
- 規模：內建 409 個任務，每個 1～10 個任務點（平均 2.8）。單一任務的圖很小，不需要圖形函式庫；故事線（跨任務）才大。

### 3.2 圖的模型（`storyGraph(def)`，純函式，只讀任務資料）

**節點**

| 節點 | 來源 | 樣子 |
|---|---|---|

### 3.3 排版

- **分層**（左到右；手機版上到下）：先用 DFS 拿掉回頭的邊（清除、重試造成的環），最長路徑分層，同一層用重心法排 2～3 輪減少交叉。十個節點以內，手寫一百多行就夠，不加套件。

### 3.4 兩種視角

1. **單一任務**（編輯器裡）：特殊任務編輯器的「任務點」區塊多一組切換「📋 清單／🕸️ 流程圖」。點任務點 → 在旁邊（手機版是全螢幕頁面）開同一個 `StoryNodeEditor`；改了即時重畫。圖只讀草稿，不另外存東西。
2. **故事線總覽**（特殊任務頁籤的清單最上面一筆「🗺️ 故事線總覽」，和「🔢 劇情計數器」同一種做法）：節點是任務，邊是「A 設定的旗標 → B 的接取條件」與 `start_story`，共用的計數器標在任務上。依連通的群組分開畫，可以搜尋 NPC、旗標；點任務進編輯器。409 個任務不一次全畫，先選一個群組。

### 3.5 三項新的檢查：加進「檢查任務鏈」的提醒

（2026-10-30 決定：加進 `storyCheck` 的**提醒**，不是錯誤：不擋儲存、不擋匯入，在編輯器的檢查清單、匯入預覽、世界檢查工具都看得到；流程圖上同時標在對應的節點與出口。）

分析放在引擎這邊的新檔 `engine/storyReach.ts`（純函式），`storyCheck` 與流程圖共用：

- **到不了的任務點**：從開頭旗標出發，加上「任務外面可能寫的旗標」（其他任務設定的、`ai:`、園區印章，以及任務裡沒人設定的——那些已經有自己的提醒），反覆套用「解鎖 → 結果設定的旗標」，最後還是解鎖不了的任務點。`flags_none`、計數器、好感、主角條件都當成**可能成立**，所以只抓「一定到不了」的。
- **走不到完成**：上面算出來，可能解鎖的任務點裡沒有任何一個有「完成任務」的結果。（現在的錯誤「沒有任何結果會完成任務」只看有沒有寫，不看走不走得到。）
- **死路的結果**：結果不完成、不失敗、不重試，設定的旗標也不會讓任何任務點解鎖，而且這個任務點解鎖的時候，不可能有別的任務點同時開著（玩家選了這個結果就卡住，只能放棄任務）。

**上線前先對內建資料跑一遍**：409 個內建任務的每一筆新提醒，要嘛是真的資料錯誤（修資料），要嘛是規則誤報（修規則），目標是內建任務**零筆**這三種提醒，再合併。政治史詩的六個路線版本（靠計數器分路）、旅途開頭的任務、臨時地圖裡的任務點是最可能誤報的地方，先拿它們當測試。文件 [CONTENT_DEPENDENCIES](../CONTENT_DEPENDENCIES.md) 第 4 節的提醒清單一起補上。

**目前存檔的進度**（有存檔時可以打開）：完成的任務點打勾、解鎖中的發亮、選過的出口加粗，用 `state.stories` 與旗標算，只讀。

## 4. 特殊任務生成器（E4）

點子庫的 I5（「AI 依一段文字生成特殊任務，再經程式驗證與玩家確認」）。玩家寫一段描述，AI 編排一個新的特殊任務，需要時新增物品、固定 NPC、地標、特殊地圖，也可以引用現有的；結果經過程式整理與檢查、玩家確認後，加進目前的世界。

### 4.1 現有可以用的

| 需要 | 現有的 | 位置 |
|---|---|---|
| 呼叫 AI | `completeText`（串流收齊；五種供應者；沒有 JSON 模式、沒有工具呼叫、不自動重試） | `narrator/providers.ts` |
| 從回覆取 JSON | `extractJson`（容忍 ```json 區塊與前後說明） | `narrator/judge.ts` |
| 功能各自選模型來源 | `AiFeature` ＋ `routes`（目前 7 種功能） | `stores/settings.ts` |
| 用量記錄 | `addUsage`，和日誌無關的記在 `_other` | `stores/game.ts` |
| 整理 AI 給的內容 | 「今日特別商品」可以發明物品與裝備（`applyAiDeals`）、自創配方（`sanitizeDesign`）：截字、夾數值、白名單、拿掉不存在的引用 | `trade.ts`、`invention.ts` |
| 整理世界內容 | `normalizeMods` → `dropBrokenStories` → `storyCheck`（錯誤／提醒）；地標與特殊地圖會檢查 id 與格子 | `engine/mods.ts`、`storyMods.ts` |
| 合併進目前的世界 | `diffMods` ＋ `mergeMods`（E2 會接上畫面） | `stores/content.ts` |
| 格式說明 | `worldgen/guides/stories.md` 等（給離線生成世界的 Agent） | 全部約 30 萬字，不能整份放進提示詞 |

**還沒有的**：

- 給 AI 看的**現有內容目錄**（地點、設施、NPC、地標、怪物……）：目前只有判定提示詞裡零散的清單。
- **機器可讀的格式定義**：`schemas/` 只有報告的 schema，任務格式只有文件的表格與 TS 型別。
- 目前 AI 生成的東西都只存在**單一存檔**（`state.customItems`、`state.inventions`），沒有寫進世界內容的先例。

### 4.2 原則

1. **AI 只寫劇情與結構，數字由程式決定**：報酬（金錢、經驗、功績）、怪物數值、物品價格依建議等級與 [worldgen/balance](../../worldgen/balance/README.md) 的表算，AI 寫的只當參考或直接覆蓋。
2. **AI 不取 id**：新東西用暫時的代號（`$npc1`、`$lm1`、`$item1`），程式換成正式的 id（`newModId`、`newLandmarkId`、`newSpecialMapId`）並改掉所有引用。旗標一律由程式加上這個任務專屬的前綴（`g<短碼>_`），不用讓 AI 知道內建的一百多個前綴；只有 AI **刻意引用的現有旗標**（必須在 `knownFlags` 裡）保留原名。
3. **格子由程式擺**：AI 只說「放在某城鎮的某區塊」，程式找一格空地（`landmarkSpotProblem` 通過的道路）。特殊地圖第一版只生成**隨機地圖**（大小、挖幾步、遭遇表從現有怪物選），不讓 AI 畫格子。
4. **可以新增怪物、技能、狀態、地標，不能新增「新的東西種類」**（2026-10-30 決定）：
   - **允許**：新的怪物（`enemies` 的一筆，id 由程式配），欄位都是怪物編輯器現有的：等級、種類、生命、行動點、五屬性、攻擊骰、抗性、技能（只能選現有的技能）、掉落（現有或這次新增的物品）、出現地點（只限這次新增的特殊地圖；不改現有的遭遇表）。
   - **技能與狀態也可以新增**：欄位都是技能、狀態編輯器現有的（目標、判定方式、傷害段、治療、施加的狀態、次數……；狀態的數值修正、擲骰、持續效果、控制……）。新技能可以施加這次新增的狀態，新怪物可以用這次新增的技能。數值照 `sanitizeAbility`／`sanitizeStatus` 夾範圍，再對照 [worldgen/balance/abilities.md](../../worldgen/balance/abilities.md) 與 [statuses-perks-tattoos.md](../../worldgen/balance/statuses-perks-tattoos.md) 的同等級範圍，超出就拉回並標「已調整」。新技能只給怪物與這次的新 NPC 用，不加進職業的初始能力或升級選項（那會改到所有玩家）。
   - **地標**：照第 3 點由程式擺格子；開放條件、場景、探索、打工都用地標編輯器現有的欄位。
   - **不允許**：新的屬性、新的傷害類型、新的怪物種類或特性、特質、刺青、奴隸印記——也就是任何規則裡還沒有的欄位或類別，以及第一版還沒開放的幾種內容。AI 寫了就在整理時拿掉並提醒。
   - **數值**：AI 寫的照 `sanitizeEnemy` 夾在合法範圍，再依 [worldgen/balance/monsters.md](../../worldgen/balance/monsters.md) 的等級曲線檢查耐打度與傷害（和世界檢查工具同一套，`balanceSim` 的部分要從測試資料夾搬到 `engine/` 才能在遊戲裡用）；超出同等級的範圍就拉回範圍的邊緣，並在預覽寫「已調整」。
   - **和 NPC 打**：照 [STORY_QUESTS](../STORY_QUESTS.md)「和固定 NPC 戰鬥」的規則用替身怪物；AI 可以選一隻現有怪物當樣板（程式複製數值、換名字與描述），也可以照上面的規則直接寫一隻新的。
5. **一切走既有的整理與檢查**，再加 E3 的可達性分析；不合格不寫入。
6. **玩家確認後才寫入**，寫入後就是普通的自建內容，可以在編輯器繼續改。

### 4.3 流程

```
玩家輸入 ──→ ① 整理目錄 ──→ ② 大綱（AI）──→ 玩家看大綱、可以改 ──→ ③ 完整內容（AI）
                                                                      │
        ⑥ 加入世界 ←── ⑤ 預覽與確認 ←── ④ 程式整理＋檢查 ←──────────┘
                         （E3 流程圖＋E2 匯入清單）   │ 有錯誤
                                                    └──→ 把錯誤交回 AI 修（最多 2 次）
```

**① 輸入**（特殊任務頁籤的「＋ 新增特殊任務」旁邊多一個「✨ AI 編排」）：

- 描述（必填，例如「港口的燈塔守夜人其實是走私集團的眼線，主角要決定揭發他還是收下封口費」）。
- 選填的釘選：開頭方式與地點、指定要用的現有 NPC、建議等級、任務點數量上限（預設 6）、內容標籤（成人向只有在設定開放時才能勾）、允許新增哪些東西（物品／固定 NPC／地標／特殊地圖，預設全開）。
- 原版世界不能用（和現在一樣先建世界）；遊戲進行中可以用，寫入後立刻生效。

**② 目錄**（新檔 `narrator/questCatalog.ts`，只讀資料）：依釘選與描述裡出現的名字挑，控制在約 1～2 萬字：

- 現有的技能與狀態：建議等級附近、怪物可以用的，各一行（給新怪物引用，或當新技能的參考）。
- 地點（47 個，全列：id、名稱、地區、類型）與每個聚落有哪些設施（公會、情報商、酒館……，`storyCheck` 會檢查的那些）。
- 相關地點的地標、特殊地圖；固定 NPC：描述提到的、釘選的、相關地點的（名字、種族、職業、等級、一句話背景、`no_attack`／`unhireable`）。
- 怪物：建議等級 ±2 的、相關地點的遭遇表，各一行。
- 可以當報酬的物品：依等級挑一小撮＋描述提到的。
- 劇情計數器、相關的現有旗標（給「呼應其他故事線」用）。

**③ 提示詞**：

- **格式說明**放在新檔 `narrator/questGenSpec.ts`，從 `worldgen/guides/stories.md` 第 2、4、6.4 節濃縮（約 1.5 萬字）；列舉值（開頭方式、`at.where`、任務點種類、效果種類、內容標籤）**在執行時從程式的常數產生**（`START_KINDS`、`WHERE_NAME`、`NODE_KINDS`、`STORY_EFFECTS`、`CONTENT_TAGS`），不手抄，避免 [RETROSPECTIVE](RETROSPECTIVE.md) 說的「同一件事有好幾份」。加一個測試：說明裡提到的欄位都是 `sanitizeStory` 認得的。
- **兩段式**：先要大綱（標題、前提、任務點用一句話寫＋分支、要新增的東西），玩家看了覺得方向對才要完整 JSON。大綱便宜，方向錯了不浪費大的那一次。大綱可以直接用 E3 的圖顯示（大綱裡就有任務點與分支）。
- 回覆格式（第 ③ 段）：

```jsonc
{
  "story": { /* StoryDef，引用用代號或現有 id */ },
  "new": {
    "npcs":        [{ "ref": "$npc1", /* NpcDef 的欄位，沒有 id */ }],
    "items":       [{ "ref": "$item1", "name": "鐘樓的鑰匙", /* … */ }],
    "landmarks":   [{ "ref": "$lm1", "location": "soriel", "area": "港區", /* … 沒有格子 */ }],
    "specialMaps": [{ "ref": "$sm1", "location": "soriel", "size": [10, 10], "enemies": ["…現有怪物 id"] }],
    "statuses":    [{ "ref": "$st1", "name": "鐘聲的迴響", /* 狀態的現有欄位 */ }],
    "abilities":   [{ "ref": "$ab1", "name": "石化凝視", "statuses": ["$st1"], /* 技能的現有欄位 */ }],
    "enemies":     [{ "ref": "$foe1", "template": "bandit_captain", "name": "守夜人", "desc": "…" },   // 照樣板複製
                    { "ref": "$foe2", "name": "鐘樓的石像鬼", "level": 6, /* 怪物的現有欄位 */ }]
  },
  "notes": "給玩家看的設計說明"
}
```

**④ 整理與檢查**（新檔 `engine/questGen.ts`，純函式，測試用固定的 AI 回覆）：

1. 解析：`extractJson`；解析失敗算一次錯誤。
2. 換代號、配 id、改旗標前綴（4.2 第 2 點）；替身怪物照樣板複製；報酬、價格依等級重算。
3. 新怪物、技能、狀態的數值檢查（4.2 第 4 點）；地標找格子；找不到時改成「站在某設施」的任務點並記一筆說明。
4. 組成一份 `Partial<ContentMods>`，在**沙盒**裡跑 E2 的預檢查：`normalizeMods` 前後比對（被拿掉的引用＝寫錯的地方）、`dropBrokenStories`／`storyCheck`、E3 的「到不了」「走不到完成」。
5. 有錯誤時，把錯誤清單和上一版 JSON 一起交回 AI 修（單一訊息，因為呼叫只有 system＋user 一輪），最多 2 次；還是不行就把能用的部分和錯誤一起給玩家，讓他手動修或重來。

**⑤ 預覽**：上面是 E3 的流程圖；下面是 E2 的匯入清單（新的任務、NPC、物品、地標、地圖、怪物，全部勾選；照第 1 節，關聯一律一起帶），每一項可以點開看內容；AI 的設計說明；提醒與用量。按鈕：「加入世界」「重新生成」「只重寫大綱」。

**⑥ 寫入**：`mergeMods`，之後打開那個任務的編輯器。生成中與還沒加入的結果存成草稿（localStorage，最多幾份），關掉頁面不會不見。

### 4.4 設定、費用與安全

- **新的 AI 功能** `designer`（「世界設計」）：在 `AiFeature` 與 `AI_FEATURES` 加一項，可以選不同的模型來源（建議用推理強的模型）。用量記在 `_other`，預覽顯示這次花了多少。
- **份量**：一次完整生成約輸入 2～3 萬 token、輸出 5 千～1 萬 token；大綱約一半的輸入、一千多 token 的輸出。用 Anthropic 時 system 的格式說明會被快取，連續生成比較便宜。
- **內容篩選**：設定的「內容篩選」關掉的標籤，提示詞要求不能用，整理時拿掉；成人向沒開放時拿掉 `scene` 與成人向標籤（不然 `storyCheck` 會判錯誤）。被拒絕（`NarrationRefusedError`）時顯示原因，不重試。
- **不新增**：特質、刺青、奴隸印記、劇情計數器、事件（第一版），以及任何新的屬性、傷害類型、怪物種類；「主角淪為奴隸」這種重大效果只有玩家在輸入勾了才允許。

## 5. 建議順序

1. **E5 介面整理**的低風險部分（不碰資料）先做，順便把之後要放流程圖、匯入對話框的位置整理出來。
2. **E1 → E2**：局部匯入本身有用，也是 E4 寫入的路。
3. **E3**：流程圖本身有用，也是 E4 確認的畫面。
4. **E4**：最後做，前面三項都會用到。

## 6. 已決定（2026-10-30）

1. **依賴不分硬軟**：只有一種「關聯」，旗標與計數器的讀寫也算（1.2 節）。
2. **有關聯就一定一起匯入匯出**：沿著「用到誰」走到底，不能取消；「誰用到它」不帶（已確認），只列出來（1.2 節）。
3. **不在每個 id 後面加 hash**：只在衝突、選「另存一份」時，替自建的 id 加 8 碼 hash（依內容算）；hash 另外當內容指紋用（1.3 節）。
4. **流程圖的三項檢查加進 `storyCheck` 的提醒**，內建任務要零筆（3.5 節）。
5. **生成器可以新增怪物、技能、狀態、地標**，只用現有的欄位，數值照平衡表檢查；不能新增屬性、傷害類型這類新的種類（4.2 第 4 點）。
6. **生成器只放在世界編輯器**，不開遊戲中的入口。
