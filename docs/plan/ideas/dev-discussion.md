### I32

**懷孕、泌乳、苗床的延伸**（成人向；2026-11-12 從 R28 計畫的「這一版不做的」搬來）

- 情況：R28 懷孕、嬰兒、泌乳與怪物的苗床完成時（[FAMILY](../../FAMILY.md)、設計紀錄 [PREGNANCY_PLAN](../roadmap/PREGNANCY_PLAN.md) 第 13 節），先不做的部分。
- **懷孕與嬰兒**：告知父親與父親的反應、主人的家（主角是奴隸時把孩子放在主人家）、酒館寄放、雇保母（可以和 R31 家僕一起考慮）、帶在身上、送養、成長與成年、繼承、贍養費、雙胞胎、流產、求子祈福、用孩子開新局。
- **泌乳**：陽剛主角泌乳。
- **苗床**：夥伴變成苗床（寄生物要先能放在夥伴身上）、魔物卵孵化成使魔、留下魔物幼體當寵物。

### I31

**房子的延伸**（2026-11-12，盤點房屋系統、規劃 R30 儲物箱與 R31 雇用家僕之後的發想）

同一批發想裡決定要做的寫進 [R32](../roadmap/HOME_EXPANSION_PLAN.md)（舒適度分段、擴建、房間用途、成套家具、熟成、同居、傳送陣）與 R31 的 H6（家僕的事件）；決定不做的記在 R32 的 0.1 節。下面是還沒決定的：

- **戰利品展示**：展示櫃擺獨特裝備、標本架擺怪物圖鑑裡打倒過的怪物；在家的敘事與來訪的 NPC 會提到。可以和 R32 的 X3（房間用途）合成「陳列室」。
- **出租**：不住的房子租給房客（NPC），每週收租；工錢「欠著再結清」的做法反過來用。房客可能鬧事、欠租。
- **自家開店**：一樓擺貨架，家僕顧店，把箱子裡的東西以市價打折慢慢賣掉。依賴 R30、R31；要和市場行情（[TRADE](../../TRADE.md)）一起想，避免變成無限的賣場。
- **畜欄**：院子養雞、羊、蜂，產出蛋、毛、蜂蜜當材料；照種植的時間機制。
- **訪客事件**：在家時，認識的 NPC、夥伴來拜訪（喝茶、借錢、帶消息、留宿）；城鎮事件的模板加 `scope: "home"`（R31 的 H6 會先做出這個範圍）。也可以讓親密度高的人主動提出想同居（R32 的 X6）。
- **辦宴會**：花錢請客，聲望上升、邀到的 NPC 親密度上升；有廚師（R31）時效果更好。
- **留守的夥伴在家修練**：留在家裡的夥伴「NPC 自己的日子」的升級機率提高，舒適度越高越快。
- **研究室**：書房加書架讓學技能、發明更快；R32 的 X3 書房目前只給檢定加值，要的話併進去。

### I28

**工藝的延伸**（2026-11-06，R21 工藝規則做完後剩下、還沒決定要不要做的部分）

R21 的 0 級規則、學工藝、新的檢定公式與 DC、圖紙都做好了（規則寫在 [CRAFTING](../../CRAFTING.md) 1.1、2.2 節，[已完成](../roadmap/COMPLETED.md)）；製革與裁縫照擁有者的決定不合併。剩下：

- **NPC 隨機帶工匠身分**：R20 加的 15 個新身分（職業、工匠、地下）NPC 不會隨機抽到（`npc_tags.json` 的 `commoner_weight` 是 0）。要的話給一點權重，工匠身分的同伴入隊時就會帶那門工藝 Lv.2（`startCrafts` 已經支援）。會改變現有的 NPC 生成。
- **老師教工藝與圖紙**：固定 NPC 的老師（`mentor`）現在只教特質。可以加「會教的工藝」（學費照受訓的老師打 8 折）與「會送的圖紙」。
- **數值**：學費、圖紙價格、DC 照建議先定，實際遊玩後併進 R1 調整。

### I25

**貿易的延伸**（2026-11-05，R19 貿易做完後剩下、還沒決定要不要做的部分）

R19 的購物車、貿易類別、城鎮標籤、動態狀態、價格拆解、收購遞減與價格依據表都做好了（規則寫在 [TRADE](../../TRADE.md) 第 3～5 節，[已完成](../roadmap/COMPLETED.md)）。剩下：

- **事件、任務改變行情**：事件或特殊任務的效果加上或解除某座城的動態狀態（例如清掉山賊後解除「商路不安全」、礦坑事件觸發「礦坑塌方」）。狀態現在只由種子與日期決定、不存檔，要做的話得在存檔裡另外記「手動加上／解除的狀態」，並在 `market.ts` 的 `townStates` 合併。
- **世界編輯器編輯行情**：編輯固定標籤與動態狀態（`market.json`）、替聚落貼標籤（聚落本身現在不能在編輯器改，見 I23）。
- **數值**：類別倍率、狀態的權重與收購遞減照模擬（[trade-sim](../../../worldgen/balance/trade-sim.md)）先定，實際遊玩後併進 R1 調整。

### I24

**慾望戰鬥的收尾**（成人向；2026-11-05 從 ROADMAP R8 移回點子庫，原本是 I14）

S0～S9 在 v0.4.0 發布、S10（流派的老師與秘法書、寄生類的雙面效應、稱號）2026-11-02 完成（[已完成](../roadmap/COMPLETED.md)）；規則寫在 [COMBAT_SYSTEM](../../COMBAT_SYSTEM.md) 第 8.5 節、[LEWD_STATS](../../LEWD_STATS.md)、[LUST_PARK](../../LUST_PARK.md)、[ADULT_EVENTS](../../ADULT_EVENTS.md)。剩下的部分還沒決定要不要做。素材：玩家提供的修仙題材世界書（原文是第三方著作，不放 repo；繁簡兩版在擁有者的私人頁面 <https://claude.ai/artifact/DayFjAbU6wqCTK3JcZ6hWk>）。

#### 還沒做的

| 項目 | 說明 |
|---|---|
| 神殿的淨化 | 慾望指標的成長來源之一（降淫亂、敏感）；現在只有清心類的消耗品、特質與流派 |
| 園區規則的編輯器 | 地點的 `park`、`lewd.json` 的 `park` 還要改 JSON；特殊地圖編輯器已經能選「園區」 |
| 新的園區（例如拘束機關屋） | 每個園區就是一座地下城加一條通道（[LUST_PARK](../../LUST_PARK.md)） |
| 防具＋拘束具的淫器合煉 | 現在只有武器＋拘束具（展開成什麼還沒定義） |

稱號（S10）目前只顯示、沒有效果；之後要不要讓它影響 NPC 的態度、交給 AI 再決定。稱號清單與寄生類的雙面效應的數值還要改 JSON（`lewd.json` 的 `titles`、`parasite_two_face`）。

#### 原則（之後的內容照這個做）

1. **主力在自己人身上**：敵人的慾望抗性差異很大，強力技能圍繞友軍增益與承傷；引爆把慾望轉成一般屬性的傷害，對免疫的敵人也有用。
2. **慾望是第二條生命，代價是高潮**：張力在於存多少、分給誰、什麼時候引爆。
3. **玩家的自主性**：不強迫帶哪種裝備、修哪個流派；允許「戲內非自願、戲外自願」，這類選項標上「主角非自願」，內容篩選照樣管得到。
4. **數值由引擎算，AI 只描寫**：AI 判定只能在上限內動這些數值。
5. **照內容篩選走**：「主角非自願」關掉時敵人不用慾望攻擊；`young` 特徵的怪物一律不參與。
6. **可以整套關掉**：存檔規則「慾望戰鬥」設成 0 時，戰鬥和以前一樣。

#### 要實際遊玩後再調的數值（屬於 R1 數值平衡）

- 引爆的係數（0.4～0.8）、脫力是不是固定一回合。
- 敵方高潮的 33% 真實傷害：頭目的慾望上限 2026-11-12 改成照生命比例的平方根放大（存檔規則「頭目的慾望上限」可以再調），再看實際遊玩。
- 主人工具人化的親密度門檻 60、新主人的門檻 40（`lewd.json` 的 `master_tool`）。
- 頭牌等級的次數門檻 0、5、15、30、60（`lewd.json` 的 `brothel.ranks`）。

#### 決定不做

- 淫物的特殊戰鬥機制：不能被選為目標、前後排、模仿技能、拔除、拖離隊伍、被吞到打倒花為止（要改戰鬥的目標規則，和仇恨系統衝突）。
- 三次倒下時，隊伍還有人站著也觸發戰敗事件（改成用高潮次數降低敵人起意的 DC）。
- 奴欲心經、殺手奴會、附魔「餘韻」、成人向世界書的條目編輯、奴印的契約深化。

### I23

**自建聚落與自建地區**（2026-11-03，做完自建地下城 R16 之後）

想先做「地點編輯器」再做東大陸那種新區域時盤點的。自建地下城已經做了（[CONTENT_EDITOR](../../CONTENT_EDITOR.md) 3.96 節、[已完成](../roadmap/COMPLETED.md) 2026-11-03）；聚落與地區牽涉的系統多、不確定性太大，先不做。要做的話從下面的盤點開始，地下城的做法（`dungeonMods.ts`、`pruneLocations.ts`、`locationNotes`）可以照著擴充。

#### 世界內容的依賴關係（2026-11-02 盤點）

箭頭表示「A 用到 B」。分成七層：上層用到下層，**刪除時要由上往下**才不會擋住。★ 是自建地下城新增的部分。

```
L6 存檔 ─────────── 所在地、地圖格子、隊伍、行囊、委託、情報、主人的家、房子、登場過的 NPC……（幾乎用到下面全部）
                     │
L5 劇情與事件 ─────── 特殊任務 ─┬─ 旅途／城鎮／地下城事件 ── 主奴與娼館的事件 ── 情報物品
                     │         │
L4 人 ────────────── 固定 NPC（出沒地點、固定格子、依旗標改變出沒）、小隊
                     │
L3 疊在地圖上的 ───── 地標（含內部）── 商店（擺放、搬移）── 特殊地圖（所屬地點、通道）── 房子與空地
                     │
L2 地點裡的空間 ───── 聚落區塊 ── ★地下城的各層（遭遇表、層主、光線）── 近郊（地區的城郊遭遇表）
                     │
L1 世界骨架 ───────── ★地點（地下城）── ★路線 ── 地區 ── 勢力
                     │
L0 基礎內容（不依地點）─ 怪物 ── 物品 ── 底材、材料 ── 技能 ── 狀態 ── 特質 ── 刺青與印記 ── 劇情計數器、旗標
```

##### 地下城用到的東西（L1、L2）

| 欄位或資料 | 誰會讀 | 沒有時 |
|---|---|---|
| 地區 | 城郊遭遇（遭遇表沒寫的層）、地下城事件的地區篩選、背景圖、曝露名聲、給 AI 的報告 | **一定要有**：`regionById` 找不到會丟錯 |
| 路線（天數、方式、船資） | 最短路徑、旅途、公會委託（7 天內的公會）、情報（7 天內）、冒險者 NPC 的出沒（相鄰的地下城） | 到不了，也不會有委託和情報 |
| 出現條件 `requires` | 旅行、任務、情報能不能抵達；有條件的地下城不會有冒險者出沒 | 一直開放 |
| 遭遇表 `encounters[地點]` | 各層的遭遇與層主、強敵、寶箱等級、建議階級、清剿與材料委託、晉升考核、情報、怪物圖鑑 | 每層用城郊的表，**委託、情報、圖鑑都不會有這座** |
| 光線 `lighting.locations[地點]` | 各層的光線 | 共用的各層預設 |
| `material_series` | 寶箱與人形怪掉的裝備系列 | 第一種材料 |
| 層的生成（數量、陷阱、寶箱、資源） | `maps.json` 的 `generation.dungeon.layers`，所有地下城共用 | 不用設 |

##### 引用地下城的內容（L3～L5）

| 內容 | 欄位 | 地下城不見時現在會怎樣 |
|---|---|---|
| 特殊任務 | 任務點 `at.location`（地下城的某一層）、結果 `travel_to` | 整理時拿掉，任務檢查報錯誤 |
| 地下城事件、旅途事件 | 地下城事件的 `dungeons`、改道 `travel_to` | 篩選掉 |
| 特殊地圖 | 所屬地點是地下城（陷阱、寶箱比照那一層，沒寫遭遇表就用那一層的） | 刪除會擋下；匯入「取代全部內容」拿掉地下城時，改到第一個地點並列在頁面上方的提醒 |
| 物品 | 情報的 `intel.location` | 拿掉 |
| 怪物 | 內建地下城的「出現地點」寫在怪物身上（`spawns`）；自建地下城的遭遇記在地下城上 | 遭遇表跟著地下城一起刪 |

聚落才有的引用（地標、商店、固定 NPC 的地點、房子）和地下城無關。固定 NPC 的出沒（`haunts`）只能是聚落的區域。

##### 存檔裡會寫到地下城的地方（L6）

`locationById` 找不到會丟錯（全專案約 265 處呼叫）；地下城的部分已經由 `pruneLocations.ts` 清理（[CONTENT_DEPENDENCIES](../../CONTENT_DEPENDENCIES.md) 第 2 節）。和地下城有關的：

- **讀檔時就壞**：
  - 所在地 `state.location`（人在地下城裡）
  - 地下城探索 `expedition`
  - 旅途 `road.from/to`
  - 待處理的移動 `pendingMove`
  - 戰敗 `pendingDefeat`
  - **生成的冒險者 NPC 的出沒**（`haunts`）：冒險者會自動在「相鄰、沒有出現條件」的地下城出沒，畫面每次查「這裡的人」都會讀到
- **打開畫面時才壞**：
  - 公會委託的目標（清剿、材料）
  - 情報
  - 日誌報告的地點、冒險記憶
- **只是留下沒用的資料**：地下城各層的地圖（`<地點>/L<n>`，下次旅行就清掉）、足跡、等待。

#### 自建聚落與自建地區要多做的

聚落比地下城多出這些：

- **區塊**：沒有專屬地圖時用類型範本；要自己畫的話沿用特殊地圖的畫筆，改用城鎮圖例。
  - 至少要一個城門，每個區塊連得到城門，貴族區與王城要有勢力。
  - 區塊 id 存檔後不能改。
  - 改區塊前要檢查擺在上面的地標、商店、NPC 固定格子、特殊地圖通道、任務點的格子，以及要公會或情報商開頭的任務。
- **依類型或地點的資料**：
  - 依類型：店的等級與物價、居民人數、房子、打造等級、城鎮事件。
  - 依地點：魅氣、奴隸市場、路人職業、店名的個別設定。
  - 依勢力：通緝、警戒、王城。
- **被引用**：地標、商店、固定 NPC（地點會默默改成索里耶爾，要改成擋下）、特殊地圖的通道、城鎮事件、任務開頭的公會或情報商。
- **存檔**：除了上面「存檔裡會寫到地下城的地方」（`pruneLocations.ts` 要擴充），還有主人的家、居民名單、在這裡生成的 NPC、房子、出生地、依地點記的酒館、市場、店的庫存、警戒、通行。
- **快取**：`homes.ts` 的 `lotCache`、`manorCache`，`masterHome.ts` 的 `layoutCache`，`grid.ts` 的 `baseBlocks`、`blockKinds`。
- **自建聚落之間的路線**：B 只接在 A 上時，刪掉 A 就到不了 B。
- **自建地區**：東大陸這種新區域要有。至少要有名稱、城郊遭遇表、店名風格、魅氣、NPC 種族比例、背景圖；`regionById` 找不到會丟錯，旅行面板與出生地依地區分組。
- **寫死的地點**：起始地點、各種族的預設出生地（`state.ts`）、好幾處預設的「索里耶爾」（`questGen.ts`、`mods.ts`、`storyMods.ts`、任務編輯器）、NPC 種族比例依地區的分支（`npcs.ts`）、天氣特效依地區（`AmbientLayer.vue`）。
- **世界地圖**是固定的一張圖，畫不到自建的地點（旅行面板照樣列得出來）。
