# 點子：開發討論

> 上層：[點子庫](README.md)。開發討論中提出、還沒做的構想。每一條寫出當時在做什麼。

（I10 主角身分標籤的效果已做，見 [NPC_SYSTEM](../../NPC_SYSTEM.md) 4.1 節。）

### I29

**新增職業；職業放進世界編輯器**（2026-11-06 評估，擁有者問：新增一個職業要做哪些事，分「不給 NPC」與「給 NPC」；能不能放進世界編輯器）

#### 現況

- 職業定義在 `data/rules/classes.json`：10 個戰鬥職業加「無法戰鬥」。引擎幾乎都讀資料：
  - 能力完全照欄位結算，沒有依能力 id 寫死的邏輯；圖示也依欄位自動畫（`abilityArt.ts`）。
  - 施法（`none`／`half`／`full` 查表）、施法屬性、生命骰、仇恨、職業抗性都是 `ClassDef` 的欄位。
  - 裝備沒有職業限制。
- 程式裡寫死的職業 id 只有預設值，新職業不用改：`'fighter'` 當預設或退路（建角、固定 NPC 與技能的範本、`gear.ts` 的裝備模板、`trade.ts`）、自建店主 `['rogue', 'fighter', 'bard']`、交涉的 `rogue`。
- 其他列出職業 id 的資料都是選填，沒寫照預設：

| 檔案 | 欄位 | 用途 |
|---|---|---|
| `gear.json` | `classes.<id>` | 開局裝備、生成裝備可以挑的底材（沒有時開局空手、生成裝備用戰士的） |
| `abilities.json` | `classes` | 誰可以學 |
| `perks.json` | `requires.classes`、`npc.classes` | 職業專屬特質；NPC 比較容易抽到的特質 |
| `npc_tags.json` | `class_mult` | 冒險者帶這個標籤的機率倍率（聖騎士很少是惡人） |
| `npc_traits.json` | 血統的 `jobs.classes` | 化龍族鱗色決定職業 |
| `shops.json` | `keeper.classes` | 店主的職業（只給 AI 參考） |
| `combat.json` | 戰敗事件起意者的 `classes` | 知識型、宗教型…… |
| `slavery.json` | `class_mult`、服務的 `classes` | 奴隸價格、法師解構 |
| `progression.json` | `classes` | 程式沒讀，只是參考 |

#### A. 兩種都要做的

1. **`classes.json` 一筆**：名字、emoji、生命骰、仇恨、屬性優先順序、施法類型與屬性、預設武器與防具、起始能力、定位說明、抗性。
2. **`gear.json` 的裝備模板**：開局裝備、可以用的底材、頭腿手腳用哪種材料。
3. **能力（最大的工）**：每個職業 1～20 級每一級都要有三選一（`levelChoices.spec` 檢查）。
   - 不施法的職業：現有的戰士 24 個、遊蕩者與武僧各 23 個技能，幾乎不和別的職業共用，等於全部新寫。
   - 施法職業：可以把現有法術的 `classes` 加上新職業（吟遊詩人 31 個能力裡 23 個是共用的），新寫的只有幾個招牌技能。
   - 數值照 [balance/abilities](../../../worldgen/balance/abilities.md) 的同等級能力。
4. **引擎**：只有新機制才要改，例如召喚物、姿態切換、另一種法術環表。只用現有欄位（產生行動點、印記、狀態、仇恨、吸血……）時不用改程式。
5. **測試**：「每個職業打完一場」「每個能力都用得出來」（`combat.spec`）會自動涵蓋新職業。平衡併進 R1。
6. **文件**：
   - COMBAT_SYSTEM 第 9 節的能力清單是產生的（`gen:class-abilities`，`docTables.spec` 會擋）。
   - 要手動加的：第 2 節的施法者分類、第 7 節的技能數、仇恨表、職業抗性的說明。
   - 還有 `worldgen/guides/abilities.md` 1.1 節的職業清單、玩家指南、CHANGELOG。
7. **AI**：敘事、判定與圖片只拿職業名（`judge.ts`、`describe.ts`、`imageInfo.ts`），特殊任務生成器的職業清單自動列出。名字不是常見職業時，在世界書加一條職業的描述，AI 才知道它的打法與形象。
8. 選填：職業專屬特質、技能書。

#### B. 不給 NPC（只有主角能選）

- `ClassDef` 加一個旗標（例如 `player_only: true`），`data.ts` 分出 `npcClasses`（`combatClasses` 去掉這種）。
- 隨機抽職業的兩個入口改用 `npcClasses`：
  - `npcs.ts` 的 `generateNpc`
  - `population.ts` 的 `generateResident`
- 指定職業的入口要決定擋不擋。建議都擋，遇到時退回戰士：
  - 固定 NPC 的整理（`sanitizeNpc`）與編輯器的下拉選單
  - 特殊任務生成器給 AI 的職業清單（`questGenSpec.ts`）
- 建角、技能編輯器、特質編輯器照舊用 `combatClasses`。
- 好處：
  - 隨機抽的清單長度不變，NPC 生成的亂數結果不變：既有存檔之後生成的人、依種子的測試都不受影響。
  - 只有主角一個人用，上表 `gear.json` 以外的 NPC 相關資料都不用補。
- 程式量小：旗標、`npcClasses`、兩個下拉、一個測試（生成大量 NPC 都不會抽到）。工作量幾乎都在 A 的能力。

#### C. 給 NPC

- 程式幾乎不用改：加進 `classes.json` 就會被隨機抽到。
- 影響：
  - 冒險者每種職業的機率從 1/10 變 1/11。
  - `rng.pick` 的清單變長，同一個種子抽到的職業會換：既有存檔之後新生成的冒險者會不同（已經生成的存在存檔，不受影響）；依種子寫期望值的測試可能要更新。
- 一定要補：`gear.json` 的裝備模板（沒有時 NPC 穿戰士的裝備）。
- 選填，但不補的話世界觀會怪（都是照預設）：
  - 身分標籤的 `class_mult`（惡人、神職的機率）
  - 血統的 `jobs.classes`
  - 店主的 `keeper.classes`
  - 戰敗事件起意者的類型
  - 奴隸價格的 `class_mult`、依職業的服務
  - 特質的 `npc.classes`
  - 要不要有固定 NPC 是這個職業（`npcs.json`、世界書的人物條目、形象圖）
- 要注意：
  - NPC 升級時自動挑三選一的第一個，能力的排列會影響 NPC 的配置。
  - 敵人 AI 依欄位挑技能（COMBAT_SYSTEM 8.3 節），新機制的能力要確認 AI 用得出來。
- 工作量：比 B 多 6～8 個資料檔的小修改、固定 NPC 的內容，以及平衡確認。

#### D. 放進世界編輯器

**做得到，規模大約是身分標籤編輯器（R20 C6：16 個檔案、+590 行）的一倍半**。要做的：

1. **存檔的保護（要最先做）**：
   - `classDef()` 找不到職業時會丟錯，建角、升級、短休、仇恨、角色面板等十幾處都用它。
   - 自建職業被刪掉、匯入時被整理掉後，同一個世界的其他存檔會打不開。
   - 做法：讀檔時把不認得的職業換成戰士，在日誌註明（或讓 `classDef` 退回戰士）。
2. **`ContentMods.classes`**：
   - 套用與整理時最先登錄（和身分標籤一樣）。`sanitizeAbility` 用 `abilityClasses()` 過濾 `classes`，職業還沒登錄的話，自建職業的能力會被拿掉。
   - 內建職業只存和內建不同的欄位，可以恢復預設、不能刪。
3. **`combatClasses` 改成套用世界時重算**：現在是模組載入時算一次的常數。`NewGameView`、`NpcEditor`、`PerkEditor`、`npcs.ts`、`population.ts` 都讀它。
4. **編輯畫面**（「⚔️ 戰鬥」組加「🎓 職業」頁籤）：
   - 基本：名字、emoji、說明、生命骰 6～12、仇恨、屬性優先順序、施法類型與屬性、抗性。
   - 起始能力：從這個職業學得到的能力挑。
   - 裝備模板（`gear.json` 的 `classes`）。
   - 給不給 NPC（B 的旗標）。標籤倍率這類 NPC 生成的細項可以先不開。
5. **批次指定能力**：技能編輯器的「誰可以學」已經從 `abilityClasses()` 動態列出，自建職業會自動出現。但一個職業要 20 多個能力，一個一個勾很累。建議職業頁直接勾現有的能力（等於批次改能力的 `classes`），或「從某職業複製全部能力」。
6. **三選一的提醒**：自建職業某些等級的選項不到 3 個時，在編輯器提醒「第 N 級只有 X 個選項」，不擋存檔（`abilityChoices` 選項不夠時照樣能選，不會壞）。`levelChoices.spec` 只測內建。
7. **刪除保護**：CONTENT_DEPENDENCIES 第 2 節加一列：
   - 固定 NPC、特質的 `requires.classes`、只有這個職業能學的能力，都會擋下刪除。
   - 目前存檔用這個職業的角色也會擋下。
8. **局部匯入匯出的關聯**（E1）：
   - 職業會用到起始能力與裝備底材；能力的 `classes`、固定 NPC 與特質也會指回職業。
   - 能力和職業互相指，要確認關聯的走訪不會繞圈。
9. **匯出與文件**：
   - 內建世界的匯出匯入（`builtinWorld.ts`）、世界包帶上職業。
   - `worldgen/guides` 加職業的寫法；CONTENT_EDITOR 加一節。
10. **測試**：
    - 世界編輯器的來回測試。
    - `classMods.spec`：整理、套用、恢復預設、刪除保護、讀到不認得的職業的存檔。
- **做不到的**：編輯器只能組合現有欄位，新機制（召喚、姿態……）還是要改程式。
- **修改內建職業的影響**：
  - 生命骰、抗性、仇恨立刻影響所有這個世界的存檔。
  - 屬性優先順序、起始能力、開局裝備只影響新建的角色。

#### 建議

- 只是想多一個主角能選的職業：走 **A＋B**，程式改動小，主要是寫能力。
- 想讓世界包的作者自己加職業：做 **D**。D1（存檔保護）與 D3（`combatClasses` 重算）對 A、B 也有好處，可以先做。
- 要先決定：
  1. 新職業的名字、定位、施法類型，有沒有新機制。
  2. 給不給 NPC。
  3. 要不要做編輯器，要不要開放 NPC 生成的倍率。

### I24

**慾望戰鬥的收尾**（成人向；2026-11-05 從 ROADMAP R8 移回點子庫，原本是 I14）

S0～S9 在 v0.4.0 發布、S10（流派的老師與秘法書、寄生類的雙面效應、稱號）2026-11-02 完成（[已完成](../roadmap/COMPLETED.md)）；規則寫在 [COMBAT_SYSTEM](../../COMBAT_SYSTEM.md) 第 8.5 節、[LEWD_STATS](../../LEWD_STATS.md)、[LUST_PARK](../../LUST_PARK.md)、[ADULT_EVENTS](../../ADULT_EVENTS.md)。剩下的部分還沒決定要不要做。素材：玩家提供的修仙題材世界書（原文是第三方著作，不放 repo；繁簡兩版在擁有者的私人頁面 <https://claude.ai/artifact/DayFjAbU6wqCTK3JcZ6hWk>）。

#### 還沒做的

| 項目 | 說明 |
|---|---|
| 神殿的淨化 | 慾望指標的成長來源之一（降淫亂、敏感）；現在只有清心類的消耗品、特質與流派 |
| 園區規則的編輯器 | 地點的 `park`、`lewd.json` 的 `park` 還要改 JSON；特殊地圖編輯器已經能選「園區」 |
| 新的園區（例如拘束機關屋） | 每個園區就是一座地下城加一條通道（[LUST_PARK](../../LUST_PARK.md)） |
| 防具＋拘束具的淫器合煉 | 現在只有武器＋拘束具（展開成什麼還沒定義） |

稱號（S10）目前只顯示、沒有效果；之後要不要讓它影響 NPC 的態度、交給 AI 再決定。稱號清單與寄生類的雙面效應的數值還要改 JSON（`lewd.json` 的 `titles`、`parasite_two_face`）。

#### 原則（之後的內容照這個做）

1. **主力在自己人身上**：敵人的慾望抗性差異很大，強力技能圍繞友軍增益與承傷；引爆把慾望轉成一般屬性的傷害，對免疫的敵人也有用。
2. **慾望是第二條生命，代價是高潮**：張力在於存多少、分給誰、什麼時候引爆。
3. **玩家的自主性**：不強迫帶哪種裝備、修哪個流派；允許「戲內非自願、戲外自願」，這類選項標上「主角非自願」，內容篩選照樣管得到。
4. **數值由引擎算，AI 只描寫**：AI 判定只能在上限內動這些數值。
5. **照內容篩選走**：「主角非自願」關掉時敵人不用慾望攻擊；`young` 特徵的怪物一律不參與。
6. **可以整套關掉**：存檔規則「慾望戰鬥」設成 0 時，戰鬥和以前一樣。

#### 要實際遊玩後再調的數值（屬於 R1 數值平衡）

- 引爆的係數（0.4～0.8）、脫力是不是固定一回合。
- 敵方高潮的 33% 真實傷害：頭目已經照生命比例放大慾望上限，再看實際遊玩。
- 主人工具人化的親密度門檻 60、新主人的門檻 40（`lewd.json` 的 `master_tool`）。
- 頭牌等級的次數門檻 0、5、15、30、60（`lewd.json` 的 `brothel.ranks`）。

#### 決定不做

- 淫物的特殊戰鬥機制：不能被選為目標、前後排、模仿技能、拔除、拖離隊伍、被吞到打倒花為止（要改戰鬥的目標規則，和仇恨系統衝突）。
- 三次倒下時，隊伍還有人站著也觸發戰敗事件（改成用高潮次數降低敵人起意的 DC）。
- 奴欲心經、殺手奴會、附魔「餘韻」、成人向世界書的條目編輯、奴印的契約深化。

### I23

**自建聚落與自建地區**（2026-11-03，做完自建地下城 R16 之後）

想先做「地點編輯器」再做東大陸那種新區域時盤點的。自建地下城已經做了（[CONTENT_EDITOR](../../CONTENT_EDITOR.md) 3.96 節、[已完成](../roadmap/COMPLETED.md) 2026-11-03）；聚落與地區牽涉的系統多、不確定性太大，先不做。要做的話從下面的盤點開始，地下城的做法（`dungeonMods.ts`、`pruneLocations.ts`、`locationNotes`）可以照著擴充。

#### 世界內容的依賴關係（2026-11-02 盤點）

箭頭表示「A 用到 B」。分成七層：上層用到下層，**刪除時要由上往下**才不會擋住。★ 是自建地下城新增的部分。

```
L6 存檔 ─────────── 所在地、地圖格子、隊伍、行囊、委託、情報、主人的家、房子、登場過的 NPC……（幾乎用到下面全部）
                     │
L5 劇情與事件 ─────── 特殊任務 ─┬─ 旅途／城鎮／地下城事件 ── 主奴與娼館的事件 ── 情報物品
                     │         │
L4 人 ────────────── 固定 NPC（出沒地點、固定格子、依旗標改變出沒）、小隊
                     │
L3 疊在地圖上的 ───── 地標（含內部）── 商店（擺放、搬移）── 特殊地圖（所屬地點、通道）── 房子與空地
                     │
L2 地點裡的空間 ───── 聚落區塊 ── ★地下城的各層（遭遇表、層主、光線）── 近郊（地區的城郊遭遇表）
                     │
L1 世界骨架 ───────── ★地點（地下城）── ★路線 ── 地區 ── 勢力
                     │
L0 基礎內容（不依地點）─ 怪物 ── 物品 ── 底材、材料 ── 技能 ── 狀態 ── 特質 ── 刺青與印記 ── 劇情計數器、旗標
```

##### 地下城用到的東西（L1、L2）

| 欄位或資料 | 誰會讀 | 沒有時 |
|---|---|---|
| 地區 | 城郊遭遇（遭遇表沒寫的層）、地下城事件的地區篩選、背景圖、曝露名聲、給 AI 的報告 | **一定要有**：`regionById` 找不到會丟錯 |
| 路線（天數、方式、船資） | 最短路徑、旅途、公會委託（7 天內的公會）、情報（7 天內）、冒險者 NPC 的出沒（相鄰的地下城） | 到不了，也不會有委託和情報 |
| 出現條件 `requires` | 旅行、任務、情報能不能抵達；有條件的地下城不會有冒險者出沒 | 一直開放 |
| 遭遇表 `encounters[地點]` | 各層的遭遇與層主、強敵、寶箱等級、建議階級、清剿與材料委託、晉升考核、情報、怪物圖鑑 | 每層用城郊的表，**委託、情報、圖鑑都不會有這座** |
| 光線 `lighting.locations[地點]` | 各層的光線 | 共用的各層預設 |
| `material_series` | 寶箱與人形怪掉的裝備系列 | 第一種材料 |
| 層的生成（數量、陷阱、寶箱、資源） | `maps.json` 的 `generation.dungeon.layers`，所有地下城共用 | 不用設 |

##### 引用地下城的內容（L3～L5）

| 內容 | 欄位 | 地下城不見時現在會怎樣 |
|---|---|---|
| 特殊任務 | 任務點 `at.location`（地下城的某一層）、結果 `travel_to` | 整理時拿掉，任務檢查報錯誤 |
| 地下城事件、旅途事件 | 地下城事件的 `dungeons`、改道 `travel_to` | 篩選掉 |
| 特殊地圖 | 所屬地點是地下城（陷阱、寶箱比照那一層，沒寫遭遇表就用那一層的） | 刪除會擋下；匯入「取代全部內容」拿掉地下城時，改到第一個地點並列在頁面上方的提醒 |
| 物品 | 情報的 `intel.location` | 拿掉 |
| 怪物 | 內建地下城的「出現地點」寫在怪物身上（`spawns`）；自建地下城的遭遇記在地下城上 | 遭遇表跟著地下城一起刪 |

聚落才有的引用（地標、商店、固定 NPC 的地點、房子）和地下城無關。固定 NPC 的出沒（`haunts`）只能是聚落的區域。

##### 存檔裡會寫到地下城的地方（L6）

`locationById` 找不到會丟錯（全專案約 265 處呼叫）；地下城的部分已經由 `pruneLocations.ts` 清理（[CONTENT_DEPENDENCIES](../../CONTENT_DEPENDENCIES.md) 第 2 節）。和地下城有關的：

- **讀檔時就壞**：
  - 所在地 `state.location`（人在地下城裡）
  - 地下城探索 `expedition`
  - 旅途 `road.from/to`
  - 待處理的移動 `pendingMove`
  - 戰敗 `pendingDefeat`
  - **生成的冒險者 NPC 的出沒**（`haunts`）：冒險者會自動在「相鄰、沒有出現條件」的地下城出沒，畫面每次查「這裡的人」都會讀到
- **打開畫面時才壞**：
  - 公會委託的目標（清剿、材料）
  - 情報
  - 日誌報告的地點、冒險記憶
- **只是留下沒用的資料**：地下城各層的地圖（`<地點>/L<n>`，下次旅行就清掉）、足跡、等待。

#### 自建聚落與自建地區要多做的

聚落比地下城多出這些：

- **區塊**：沒有專屬地圖時用類型範本；要自己畫的話沿用特殊地圖的畫筆，改用城鎮圖例。
  - 至少要一個城門，每個區塊連得到城門，貴族區與王城要有勢力。
  - 區塊 id 存檔後不能改。
  - 改區塊前要檢查擺在上面的地標、商店、NPC 固定格子、特殊地圖通道、任務點的格子，以及要公會或情報商開頭的任務。
- **依類型或地點的資料**：
  - 依類型：店的等級與物價、居民人數、房子、打造等級、城鎮事件。
  - 依地點：魅氣、奴隸市場、路人職業、店名的個別設定。
  - 依勢力：通緝、警戒、王城。
- **被引用**：地標、商店、固定 NPC（地點會默默改成索里耶爾，要改成擋下）、特殊地圖的通道、城鎮事件、任務開頭的公會或情報商。
- **存檔**：除了上面「存檔裡會寫到地下城的地方」（`pruneLocations.ts` 要擴充），還有主人的家、居民名單、在這裡生成的 NPC、房子、出生地、依地點記的酒館、市場、店的庫存、警戒、通行。
- **快取**：`homes.ts` 的 `lotCache`、`manorCache`，`masterHome.ts` 的 `layoutCache`，`grid.ts` 的 `baseBlocks`、`blockKinds`。
- **自建聚落之間的路線**：B 只接在 A 上時，刪掉 A 就到不了 B。
- **自建地區**：東大陸這種新區域要有。至少要有名稱、城郊遭遇表、店名風格、魅氣、NPC 種族比例、背景圖；`regionById` 找不到會丟錯，旅行面板與出生地依地區分組。
- **寫死的地點**：起始地點、各種族的預設出生地（`state.ts`）、好幾處預設的「索里耶爾」（`questGen.ts`、`mods.ts`、`storyMods.ts`、任務編輯器）、NPC 種族比例依地區的分支（`npcs.ts`）、天氣特效依地區（`AmbientLayer.vue`）。
- **世界地圖**是固定的一張圖，畫不到自建的地點（旅行面板照樣列得出來）。
