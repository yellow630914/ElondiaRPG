# 點子：開發討論

> 上層：[點子庫](README.md)。開發討論中提出、還沒做的構想。每一條寫出當時在做什麼。

### I10

**主角身分標籤的更多效果**

- 當時（2026-10）：加入主角的身分標籤，先只做了皇族的效果（不看聲望，見 [NPC_SYSTEM](../../NPC_SYSTEM.md) 4.1 節），其他效果先盤點。
- 構想：讓 AI 判定與敘事知道主角的標籤；貴族、神官、商人等在特定場合（價格、警戒、神殿服務）的效果。
- **決定（2026-10-29）**：要做，排在慾望戰鬥（[ROADMAP](../ROADMAP.md) R8、[LUST_COMBAT_PLAN](../LUST_COMBAT_PLAN.md)）做完之後，一起融入（例如身分和長期指標、曝露名聲、娼館與奴隸的互動）。下面是當時的盤點與規劃，數值是初稿；開工前還要決定的事列在最後。

**現況（2026-10-29 盤點）**

- 建角時最多選 3 個標籤（`engine/pcTags.ts`），只有皇族有效果（`pc_effects.bypass_reputation`）。
- AI 不知道主角的標籤：判定的主角資料（`narrator/judge.ts` 的 `pcDetail`）與敘事的隊伍資料（`character.ts` 的 `snapshot`）都沒有帶。
- 現在和標籤有關的檢定都是看 **NPC** 的標籤：`npc_tags.json` 的 `dc_mods`（例如和好人互動 DC 降低）、特質檢定條件的 `vs_tags`。主角的標籤不影響任何檢定。
- 事件、特殊任務、地標的條件（`StoryCond`）不能判斷主角的標籤。
- 世界編輯器沒有標籤的分頁，只能改 `npc_tags.json`。
- 順帶：`vs_tags` 在多人的自由行動只看主要對象（`actions.ts` 的 `prepareAction`）。

**規劃**

| 階段 | 內容 |
|---|---|
| A 讓 AI 知道 | 判定與敘事的主角資料多一行「身分：貴族、神官」，附每個標籤一句說明；判定規則補一句「身分可以影響 NPC 的反應，可以在 `dc_adjust` 的範圍內調整 DC」 |
| B 規則效果 | `pc_effects` 擴充成三種：**檢定加減**（沿用特質的 `CheckFilter`：屬性、場合、行動種類、`vs_tags`，進統一加減管線，日誌的情境修正顯示「貴族 +2」）、**價格倍率**（可依商店類型，買賣分開）、**服務折扣**（神殿洗刺青、解除契約等） |
| C 條件 | `StoryCond` 加「主角有／沒有某個標籤」，事件選項、特殊任務、地標開放條件都能用（神官才看得到的選項、貴族限定的委託）；編輯器的條件欄位一起加 |
| D 編輯器（可選） | 世界編輯器的標籤分頁：名稱、說明、主角能不能選、上面的效果 |

B 的初稿（建角時免費選，所以有好有壞）：

| 標籤 | 好處 | 代價 |
|---|---|---|
| 貴族 | 說服衛兵、和貴族與皇族互動 DC −2 | 一般商店售價 +10%（被當肥羊） |
| 神官 | 神殿服務 −20%；和神官、主教、好人互動 −2 | 和惡人互動 +2 |
| 主教 | 神殿服務 −40%，加上神官的好處 | 同神官 |
| 商人 | 買 −5%、賣 +10%，砍價 +2 | 威嚇 −1 |
| 旅人 | 旅途事件 +1 | 和貴族互動 +1 |
| 平民 | 和平民互動 −1 | （差異小，可以不給） |
| 好人 | 和好人互動 −2 | 犯罪被發現時聲望再 −1 |
| 惡人 | 威嚇 +2、和惡人互動 −2、黑市 −10% | 和好人互動 +2 |

存檔：標籤本來就存在存檔裡，效果由資料算出來，存檔格式不用改；舊存檔有選標籤的會自動生效。

**開工前要決定**

1. 範圍：只做 A、A＋B，還是 A＋B＋C（建議 A＋B＋C，D 之後再說）。
2. 好處要不要搭配代價（上表）。
3. 3 個標籤的檢定加值要不要封頂（例如同一次檢定最多 +3）。
4. 這次要不要做 D。
5. 和慾望戰鬥的接點：哪些標籤影響長期指標、曝露名聲、娼館與奴隸的互動（例如貴族的曝露名聲掉得比較重、娼妓以外的身分在娼館的待遇）。
