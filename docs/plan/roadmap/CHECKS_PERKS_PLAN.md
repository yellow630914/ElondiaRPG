## 1. 現況（2026-11-05 盤點）

- **特質**（`data/rules/perks.json`，引擎在 `src/engine/perks.ts`）：一般特質 37 個、缺陷 12 個、種族特質 6 個、慾望流派 16 個。
- 特質的檢定加成直接掛在很細的鍵上：
  - **26 種行動**（`kinds`，來自 `data/rules/actions.json`）：殺價、交涉價格、聊天、送禮、獻媚、威嚇、偷襲、蒙混過關、工作、雇傭談判、偷竊、打聽黑市、消費、邀請入隊……
  - **13 種情境**（`contexts`）：城門盤查、陷阱、開鎖、旅途、潛行、先攻、豁免……
  - 另外還有屬性（`attrs`）和對象的標籤（`vs_tags`）。
- 所以會出現「謊話連篇：蒙混過關 +3、城門盤查 +1」這種只對很窄的情況有效的特質；玩家看不懂為什麼兩者分開，AI 也很難對應。
- **沒有技能層**：每種行動直接對應一個屬性（社交大多是魅力，威嚇是力量，偷竊是敏捷）。
- **身分標籤**（`data/rules/npc_tags.json` 的 `pc_effects`，`src/engine/pcTags.ts`）：玩家可選 9 個（旅人、商人、平民、貴族、王族、祭司、主教、善人、惡人），最多 3 個。沒有獵人，也沒有工匠類。創角的「背景」是給 AI 看的自由文字，沒有效果。
- **受訓學特質**（`src/engine/perkActions.ts`，`TrainPanel.vue`）：例如巧手 400 白鸛、16 小時、靈巧 DC 12。玩家覺得太便宜、太容易。
- **創角版面**（`src/components/NewGameView.vue`、`PerkPicker.vue`）：特質和缺陷是兩串上下排的類別摺疊選單，每一列都佔滿整個寬度；只有「基本資料」「屬性」兩區是左右兩欄。寬螢幕上右半邊幾乎是空的。

## 3. 檢定分類（C1）——提案（2026-11-05，等擁有者確認）

13 個分類。每一種行動（`actions.json` 的 `kinds`，現在有 40 種）、每一種情境（`perks.json` 的 `contexts`，13 種）對到最多一個分類；對不到的維持現狀，只吃屬性、行動、情境的寫法。

| 分類 | 屬性 | 行動 | 情境 |
|---|---|---|---|
| 說服 | 魅力 | 聊天、送禮、雇傭談判、邀請入隊、請小隊帶你同行、談判、談判解除契約、向主人提議、投靠新主人、說服王城的衛兵、爭取特質、長休時的互動 | 談判 |
| 欺瞞 | 魅力 | 蒙混過關 | （城門盤查選「說謊」時） |
| 威嚇 | 力量 | 威嚇 | |
| 交易 | 魅力 | 殺價、交涉價格、打聽黑市 | |
| 魅惑 | 魅力 | 獻媚、誘惑、消費（娼館） | |
| 潛行 | 靈巧 | 偷襲 | 潛行 |
| 巧手 | 靈巧 | 偷竊 | 開鎖 |
| 察覺 | 智力 | | 察覺陷阱、戰鬥先攻 |
| 求生 | 智力 | | 旅行途中的危險、旅途上的事件、撤出地下城 |
| 工藝 | 智力 | 委託打造、親手製作、依配方製作、自創配方 | |
| 勞動 | 照工作 | 工作（打工） | |
| 侍奉 | 魅力 | 請求主人同意、請求主人讓你出門、回應主人、回到主人身邊、刻印 | 回應主人的要求 |
| 脫逃 | 靈巧 | 逃離主人、嘗試脫縛 | |
| （不分類） | | 自由行動（AI 判定時選一個分類）、特殊任務的判定、戰敗後的處境、探索地標、受訓、解除印記 | 主動行動、執行委託、戰鬥中的豁免 |

和草稿不同的地方：偷竊放「巧手」（扒手是手上功夫，妙手空空就是偷竊加開鎖）；察覺陷阱放「察覺」；逃脫、脫縛另立「脫逃」；旅途的三種情境合成「求生」（識途老馬、野外求生、怕水、路痴、懼高都在這裡）；打工另立「勞動」；主奴的行動合成「侍奉」。

- **屬性不變**：分類只是分組，每種行動照舊用原本的屬性（表裡的屬性只是大多數的情況）。
- **加成**：特質、身分標籤、獨特裝備、寄生物、狀態都可以寫 `skills: [...]`；`checkModifiers` 把這次的行動、情境換成分類一起比對。舊的 `kinds`、`contexts` 照舊有效。
- **自由行動**：判定前先替 13 個分類各算一份加成（和現在替每個屬性各算一份調整值一樣），AI 判定時回傳屬性與分類，程式照它選的加上去。
- **城門盤查**：盤查時選「說服（講道理、亮身分）」「欺瞞（說謊）」「潛行（混在人群裡）」或繳罰金；說服、欺瞞用魅力，潛行用靈巧，DC 照舊。
- **畫面**：行動按鈕、判定結果寫「說服檢定」「欺瞞檢定」，加成列出是哪個分類給的。

## 6. 受訓的價格與門檻（C4）——提案

現在：學費 250～500 白鸛、8～16 小時、DC 12～13。

- **學費** = 特質強度 × 400 白鸛（強度 2 → 800、3 → 1,200、4.5 → 1,800），老師教的照舊打 8 折。
- **時間** = 特質強度 × 8 小時（16～36 小時，可以分幾天學，進度保留）。
- **DC** = 12 + ⌊強度⌋（14～16），老師教的照舊 −2。
- **門檻**：強度 3 以上要角色 Lv.3；強度 4 以上要 Lv.5，而且店主或老師的親密度 20 以上。
- 失敗照舊扣一半學費；克服缺陷（受訓拿掉缺陷）照這個算法的一半。

## 6.1 世界管理：特質與身分標籤（C6）——評估（2026-11-05）

擁有者問：特質、標籤能不能放進世界管理（內容編輯器）。

- **特質**：已經在世界管理裡（「🧬 角色 → 特質」，[CONTENT_EDITOR](../../CONTENT_EDITOR.md) 3.6 節），可以改內建、新增自建、匯出匯入。R20 要補的只有：檢定加值多一欄「分類」（C1），自訂特質的 `PerkBuilder.vue` 同樣改成選分類（C2）。
- **身分標籤**（`data/rules/npc_tags.json`，現在 11 個）：**還不能編輯**，做得到，建議和 C3 一起做（先做編輯器，新身分就照同一條路加進資料，世界包也能自己加職業）。
  - 一個標籤有三種欄位：
    - **玩家效果**（`pc_effects`）：檢定加值、買賣價倍率、神殿服務價、成人向的曝光與抗性、略過聲望。這是 C3 主要用到的部分。
    - **NPC 生成**：普通人的權重、冒險者的機率、出沒地點、財富、出現在哪些區域與聚落類型、職業、職業的倍率。
    - **給 AI 的描述**（`ai_hint`）、emoji。
  - 少數標籤有寫死的特殊行為（皇族略過聲望、惡人的犯罪聲望、`never_hostile`、`dc_mods`、互斥）。編輯器只開放通用欄位，這些特殊欄位在內建標籤上照舊、不能刪；自建標籤沒有這些。
  - 用到標籤的地方有 22 個檔案：NPC 生成、固定 NPC 的標籤、商店店主的標籤、特質與裝備的「對象的標籤」、事件與任務條件的「主角的身分標籤」、主人的身分（`slavery.json` 另外一套，不在這裡）。刪除自建標籤時要擋住還有人用的，照特質的做法列出用到的地方。
  - 做法：「🧬 角色」組多一個「🏷️ 身分標籤」頁籤，存在 `ContentMods.npcTags`；`normalizeMods` 整理（數值夾範圍、不認得的欄位拿掉）、世界套用時合併進 `npcTags`；內建世界的匯出與匯入一起帶；內建的只存和內建不同的欄位、可以恢復預設；舊存檔裡 NPC 身上已經不存在的標籤略過。
  - 工作量：和商店編輯器差不多（一個編輯畫面、整理與套用、匯出、來回測試、文件）。
- **城鎮標籤與動態狀態**（R19 的 `market.json`）：可以照同一套做（標籤、狀態的定義與「哪座聚落貼哪些標籤」的覆寫），但聚落本身還不能在編輯器裡改（點子庫 I23），先留在點子庫 [I25](../ideas/dev-discussion.md#i25)。

建議順序：C1 → C2 → **C6（身分標籤編輯器）** → C3（新身分用 C6 的資料格式加）→ C4。

## 7. 創角版面（C5）

2026-11-05 完成（`PerkPicker.vue`：同一類別的特質與缺陷放同一個摺疊選單，缺陷紅底；寬螢幕 1100px 以上兩欄；種族特質改成一行；`NewGameView.vue` 的身分標籤與起始裝備並排、存檔規則的選單限制寬度）。以下是原本的規劃：


- 每一個類別一個摺疊選單，打開後上面是特質、下面是缺陷（缺陷用不同的底色區分），標題列寫「N 個可選、已選 M」。
- 寬螢幕（大約 1100px 以上）時，摺疊選單排成兩欄；窄螢幕維持一欄。
- 特質表的「效果」欄不要撐滿整列；名稱、效果、強度的寬度照內容。
- 種族特質、自訂特質各自維持一個區塊，放在類別摺疊選單的前後。
- 順便檢查創角頁其他全寬的區塊，寬螢幕下能並排的就並排。
