# 檢定與特質計畫：檢定分類、特質整併、身分標籤、創角版面

> 上層：[ROADMAP](../ROADMAP.md) R20。
> 2026-11-05 依玩家回饋（Discord 的 Tirpitz、[issue #62](https://github.com/yellow630914/ElondiaRPG/issues/62) 第 7、9～11 條）決定要做。這份計畫只寫還沒做的部分；做完的階段寫進 [PERKS](../../PERKS.md)、[ACTIONS](../../ACTIONS.md)、[NPC_SYSTEM](../../NPC_SYSTEM.md) 4.1 節，從這裡刪掉，最後整份刪掉並在[已完成](COMPLETED.md)記一段。

## 1. 現況（2026-11-05 盤點）

- **特質**（`data/rules/perks.json`，引擎在 `src/engine/perks.ts`）：一般特質 37 個、缺陷 12 個、種族特質 6 個、慾望流派 16 個。
- 特質的檢定加成直接掛在很細的鍵上：
  - **26 種行動**（`kinds`，來自 `data/rules/actions.json`）：殺價、交涉價格、聊天、送禮、獻媚、威嚇、偷襲、蒙混過關、工作、雇傭談判、偷竊、打聽黑市、消費、邀請入隊……
  - **13 種情境**（`contexts`）：城門盤查、陷阱、開鎖、旅途、潛行、先攻、豁免……
  - 另外還有屬性（`attrs`）和對象的標籤（`vs_tags`）。
- 所以會出現「謊話連篇：蒙混過關 +3、城門盤查 +1」這種只對很窄的情況有效的特質；玩家看不懂為什麼兩者分開，AI 也很難對應。
- **沒有技能層**：每種行動直接對應一個屬性（社交大多是魅力，威嚇是力量，偷竊是敏捷）。
- **身分標籤**（`data/rules/npc_tags.json` 的 `pc_effects`，`src/engine/pcTags.ts`）：玩家可選 9 個（旅人、商人、平民、貴族、王族、祭司、主教、善人、惡人），最多 3 個。沒有獵人，也沒有工匠類。創角的「背景」是給 AI 看的自由文字，沒有效果。
- **受訓學特質**（`src/engine/perkActions.ts`，`TrainPanel.vue`）：例如巧手 400 白鸛、16 小時、靈巧 DC 12。玩家覺得太便宜、太容易。
- **創角版面**（`src/components/NewGameView.vue`、`PerkPicker.vue`）：特質和缺陷是兩串上下排的類別摺疊選單，每一列都佔滿整個寬度；只有「基本資料」「屬性」兩區是左右兩欄。寬螢幕上右半邊幾乎是空的。

## 2. 已決定

| 項目 | 決定 |
|---|---|
| 檢定分類 | 在行動、情境和特質之間加一層**分類**（說服、欺瞞、威嚇……）；**只是分組，不新增技能點系統** |
| 創角版面 | 方案 A：同一類別的特質和缺陷放在同一個摺疊選單裡，摺疊選單在寬螢幕上兩欄並排 |
| 身分標籤 | 我們先自己加一批（第 5 節） |

## 3. 檢定分類（C1）

`actions.json` 每一種行動、每一種情境對到一個分類。下表是**草稿**，實作時逐一確認：

| 分類 | 行動、情境 |
|---|---|
| 說服 | 聊天、送禮、雇傭談判、邀請入隊、談判解除契約、向主人提議、說服王城的衛兵 |
| 欺瞞 | 蒙混過關、城門盤查（說謊混過去時） |
| 威嚇 | 威嚇 |
| 交易 | 殺價、交涉價格、打聽黑市 |
| 魅惑 | 獻媚、魅惑、娼館消費 |
| 潛行 | 潛行、偷襲（先手）、偷竊 |
| 巧手 | 開鎖、陷阱、逃脫 |
| 察覺 | 察覺陷阱、先攻 |
| 工藝 | 打造、依配方製作、自創配方（[CRAFTING_PLAN](CRAFTING_PLAN.md)） |

- 檢定加成的來源（特質、身分標籤、狀態、裝備……）都可以寫 `skills: [...]`，`checkModifiers` 把行動、情境換成分類後一起比對。舊的 `kinds`、`contexts` 寫法**繼續支援**，世界包、自訂特質不會壞。
- **城門盤查**：盤查時玩家選怎麼應付（說服、欺瞞、亮身分……），照選的走對應的分類，不再是單獨一個情境。
- **AI 判定**：提示詞改用分類的名字，AI 判斷自由行動屬於哪個分類，比現在列 26 種行動好懂。
- 行動畫面、判定結果寫出「說服檢定」「欺瞞檢定」，玩家看得出特質為什麼有加成。
- 規則與分類對照寫進 [ACTIONS](../../ACTIONS.md)。

## 4. 特質整併（C2）

- 37 個一般特質、12 個缺陷逐一改成加在分類上，例如：
  - 謊話連篇：欺瞞 +2。
  - 能言善道：說服 +1、交易 +1。
  - 凶神惡煞：威嚇 +2。
  - 生意頭腦：交易 +2。
- 效果太窄、和別的重疊的合併或改寫；強度（`power`）照新效果重算，保持創角點數的平衡。
- 分錯類的特質修正，例如幸運、老兵現在被歸在「學識與技藝」。
- **存檔不用遷移**：特質的 id 不變，效果每次都從資料讀。
- 自訂特質的編輯器（`PerkBuilder.vue`）改成選分類；舊的自訂特質照舊有效。

## 5. 身分標籤擴充（C3）

- 依類別補上身分，仍然最多選 3 個。先自己做一批，例如：
  - **平民的職業**：獵人、農民、漁夫、水手、傭兵、學者、藝人。
  - **工匠**：鐵匠、木匠、皮匠與裁縫、珠寶匠、煉金術士、廚師。開局對應的工藝 **Lv.2**（工藝等級見 [CRAFTING_PLAN](CRAFTING_PLAN.md) 第 3 節）。
  - **地下**：盜賊、走私客。
- 每個身分有一點檢定加成（加在第 3 節的分類上），有的再帶一點起始物品（獵人帶弓或陷阱、工匠帶工具組）。
- NPC 也有職業，同樣的標籤可以讓 NPC 同伴帶工藝等級（例如職業是鐵匠的同伴）。
- 創角的身分標籤選擇器（`PcTagPicker`）按類別分組。

## 6. 受訓的價格與門檻（C4，issue #62 第 7 條）

- 調高學特質的學費與時間，DC 照特質的強度往上加，並給玩家多一個花錢的地方。
- 強的特質要有條件：例如老師的好感、角色等級，或已經有某個前置特質。
- 數值等第 4 節的特質整併完再定，一起在平衡表裡看。

## 7. 創角版面（C5）

- 每一個類別一個摺疊選單，打開後上面是特質、下面是缺陷（缺陷用不同的底色區分），標題列寫「N 個可選、已選 M」。
- 寬螢幕（大約 1100px 以上）時，摺疊選單排成兩欄；窄螢幕維持一欄。
- 特質表的「效果」欄不要撐滿整列；名稱、效果、強度的寬度照內容。
- 種族特質、自訂特質各自維持一個區塊，放在類別摺疊選單的前後。
- 順便檢查創角頁其他全寬的區塊，寬螢幕下能並排的就並排。
