## 1. 範圍

| 決定（2026-11-02） | 內容 |
|---|---|
| 先做的 | **自建地下城**：世界頁籤新增一座地下城，**經由旅途到達**（有自己的路線），功能和內建地下城一樣（分層、遭遇、層主、寶箱、公會委託、情報） |

## 2. 世界內容的依賴關係（全部盤點）

箭頭表示「A 用到 B」。分成七層：上層用到下層，**刪除時要由上往下**才不會擋住。★ 是這次新增的部分。

```
L6 存檔 ─────────── 所在地、地圖格子、隊伍、行囊、委託、情報、主人的家、房子、登場過的 NPC……（幾乎用到下面全部）
                     │
L5 劇情與事件 ─────── 特殊任務 ─┬─ 旅途／城鎮／地下城事件 ── 主奴與娼館的事件 ── 情報物品
                     │         │
L4 人 ────────────── 固定 NPC（出沒地點、固定格子、依旗標改變出沒）、小隊
                     │
L3 疊在地圖上的 ───── 地標（含內部）── 商店（擺放、搬移）── 特殊地圖（所屬地點、通道）── 房子與空地
                     │
L2 地點裡的空間 ───── 聚落區塊 ── ★地下城的各層（遭遇表、層主、光線）── 近郊（地區的城郊遭遇表）
                     │
L1 世界骨架 ───────── ★地點（地下城）── ★路線 ── 地區 ── 勢力
                     │
L0 基礎內容（不依地點）─ 怪物 ── 物品 ── 底材、材料 ── 技能 ── 狀態 ── 特質 ── 刺青與印記 ── 劇情計數器、旗標
```

### 2.1 地下城用到的東西（L1、L2）

| 欄位或資料 | 誰會讀 | 沒有時 |
|---|---|---|
| 地區 | 城郊遭遇（遭遇表沒寫的層）、地下城事件的地區篩選、背景圖、曝露名聲、給 AI 的報告 | **一定要有**：`regionById` 找不到會丟錯 |
| 路線（天數、方式、船資） | 最短路徑、旅途、公會委託（7 天內的公會）、情報（7 天內）、冒險者 NPC 的出沒（相鄰的地下城） | 到不了，也不會有委託和情報 |
| 出現條件 `requires` | 旅行、任務、情報能不能抵達；有條件的地下城不會有冒險者出沒 | 一直開放 |
| 遭遇表 `encounters[地點]` | 各層的遭遇與層主、強敵、寶箱等級、建議階級、清剿與材料委託、晉升考核、情報、怪物圖鑑 | 每層用城郊的表，**委託、情報、圖鑑都不會有這座** |
| 光線 `lighting.locations[地點]` | 各層的光線 | 共用的各層預設 |
| `material_series` | 寶箱與人形怪掉的裝備系列 | 第一種材料 |
| 層的生成（數量、陷阱、寶箱、資源） | `maps.json` 的 `generation.dungeon.layers`，所有地下城共用 | 不用設 |

### 2.2 引用地下城的內容（L3～L5）

| 內容 | 欄位 | 地下城不見時現在會怎樣 |
|---|---|---|
| 特殊任務 | 任務點 `at.location`（地下城的某一層）、結果 `travel_to` | 整理時拿掉，任務檢查報錯誤 |
| 地下城事件、旅途事件 | 地下城事件的 `dungeons`、改道 `travel_to` | 篩選掉 |
| 特殊地圖 | 所屬地點是地下城（陷阱、寶箱比照那一層，沒寫遭遇表就用那一層的） | **默默改成第一個地點**（`specialMapMods.ts`），要改成擋下 |
| 物品 | 情報的 `intel.location` | 拿掉 |
| 怪物 | 現在的「出現地點」`dungeon:<地點>:<層>`、`boss:<地點>:<層>` 寫在怪物身上 | 拿掉；自建地下城改成記在地下城上（第 4 節） |

聚落才有的引用（地標、商店、固定 NPC 的地點、房子）和地下城無關。固定 NPC 的出沒（`haunts`）只能是聚落的區域。

### 2.3 存檔裡會寫到地下城的地方（L6）

**存檔完全沒有清理地點的程式**，而 `locationById` 找不到會丟錯（全專案約 265 處呼叫）。和地下城有關的：

- **讀檔時就壞**：
  - 所在地 `state.location`（人在地下城裡）
  - 地下城探索 `expedition`
  - 旅途 `road.from/to`
  - 待處理的移動 `pendingMove`
  - 戰敗 `pendingDefeat`
  - **生成的冒險者 NPC 的出沒**（`haunts`）：冒險者會自動在「相鄰、沒有出現條件」的地下城出沒，畫面每次查「這裡的人」都會讀到
- **打開畫面時才壞**：
  - 公會委託的目標（清剿、材料）
  - 情報
  - 日誌報告的地點、冒險記憶
- **只是留下沒用的資料**：地下城各層的地圖（`<地點>/L<n>`，下次旅行就清掉）、足跡、等待。

## 3. 玩家怎麼設定（地下城編輯器）

頁籤「🕳️ 地下城」放在「🗺️ 地點」組，和地標、特殊地圖、商店並列。

### 3.1 基本

| 欄位 | 說明 |
|---|---|
| 名稱 | 和其他地點不能同名 |
| 地區 | 六個現有地區之一。決定沒放怪物的層用哪張城郊表、地下城事件的地區篩選、背景圖 |
| 給 AI 的描述 | 每一則日誌的場景都帶上，像特殊地圖的 `desc`。內建地點的設定在世界書，程式不讀地點的 `note`，自建的要靠這一欄 |
| 出現條件 | 共用的劇情條件（`RequiresEditor`）：旗標成立才找得到、才能出發前往，例如「完成某個任務後才找得到的遺跡」 |
| 寶箱的裝備系列 | 選一種材料系列，沒選用第一種 |

### 3.2 路線

- 一列一條：接到哪個**聚落**、天數（最少～最多）、方式（官道、山道、荒野、海路、潛水、地底）、船資（海路才有，空著是 50）。
- 至少一條。只能接內建的聚落，不能接別的地下城；這樣自建地下城之間不會互相依賴。
- 下方即時顯示：「7 天內會發清剿委託的公會：河谷鎮（2 天）、索里耶爾（4 天）……」「會有冒險者出沒：相鄰的 X、Y」，讓玩家知道路線長短的影響。

### 3.3 各層

每座地下城有**周邊、淺層、中層、深層**，可以勾「有底層」變成五層（`dungeonDepth`）。淺層、中層、深層、底層的盡頭各有一位**層主**，周邊沒有。每一層一個區塊：

| 項目 | 說明 |
|---|---|
| 遭遇 | 一或多組，每組 1～4 種怪物、每種 1～6 隻（和怪物編輯器「出現地點」的組一樣）。遭遇時從所有組平均抽一組，要提高某組的機率就多放一組 |
| 層主 | 一組：第一種是層主（戰鬥卡片有金框），其他是護衛；沒設時照強敵的規則（最強的一組多一隻） |
| 光線 | 一直有光／白天有光／黑暗；沒選照共用的預設 |
| 自動算出來的（只顯示） | 這層怪物的等級範圍、建議階級、寶箱等級（最高的怪物等級）、強敵是哪一組 |
| 提醒（不擋儲存） | 這層沒有怪物（會用城郊的表）；等級比上一層低；和同一地區內建地下城同一層的等級差太多（例如中央平原淺層是 1～2） |

### 3.4 快速開始

- **「照內建地下城複製」**：選一座內建地下城，把它各層的遭遇與層主整份抄過來，再自己換怪。
- **「依等級自動填」**：每層給一個等級範圍，從這個地區的怪物（城郊與內建地下城出現過的）挑幾組填上。

### 3.5 用到的地方

編輯器上方照慣例列出 🔗 用到這座地下城的內容（特殊任務、事件、特殊地圖、情報物品，以及目前存檔，第 6 節）；有的話「🗑️ 刪除」停用。

## 4. 怪物與地下城的關聯

**資料只存一份，記在地下城上**（地下城 → 怪物），兩邊的編輯器都改得到：

- **地下城編輯器**：在某一層放怪物，就是改這座地下城的遭遇表。
- **怪物編輯器**：「出現地點」的選單也列出自建地下城的各層與層主。在這裡加一組，改的也是那座地下城的表（同一份）。這和現在「物品編輯器設定的掉落，改的其實是怪物的掉落物」是同一種做法（[CONTENT_EDITOR](../../CONTENT_EDITOR.md) 第 2 節）。
- **怪物這邊看得到**：怪物編輯器列出「出現在：某某洞窟・淺層、中層（層主）」；怪物圖鑑的棲地也會有這座。

這個方向決定了刪除與匯出的規則：

| 動作 | 規則 |
|---|---|
| 刪自建怪物 | 有自建地下城用到它時**擋下**，列出是哪幾座、哪幾層，附「從這些地下城拿掉」的按鈕。這是待決定 1，另一個選項是自動拿掉 |
| 刪自建地下城 | 遭遇表跟著一起刪（是地下城自己的一部分），怪物不受影響 |
| 局部匯出地下城 | 自動帶上用到的自建怪物，以及怪物用到的技能、狀態、掉落物品（現有的閉包規則） |
| 局部匯出怪物 | 不自動帶地下城（反方向），列出「用到它的地下城」，可以一鍵加入（現有的做法） |
| 內建怪物放進自建地下城 | 可以，內建怪物本來就不能刪 |

**和內建地下城的差別**：自建怪物放進**內建**地下城時，仍然照現在的做法記在怪物身上（`spawns`），因為內建的遭遇表是內建資料、不存在世界裡。所以會有兩種存法：

- 內建地下城：關聯記在怪物上（怪物 → 地下城）。
- 自建地下城：關聯記在地下城上（地下城 → 怪物）。

怪物編輯器的「出現地點」把兩種合在一起顯示，玩家感覺不出差別。

## 5. 要做的事

### 5.1 資料、套用與快取（沒有介面，先做）

- **資料**：`ContentMods.dungeons`（舊的自訂內容沒有這一欄，讀取時補上）。
  - id 一律 `loc_` 開頭：`contentRefs.ts` 會把任何字串當 id 比對，要有前綴才不會撞名。
  - 欄位：名稱、地區、描述、出現條件、材料系列、路線、各層的遭遇與層主、光線、有沒有底層。
- **套用**：
  - 把地點加進 `geography.locations`、路線加進 `geography.routes`、遭遇表加進 `dungeonEncounters`、光線加進 `lighting.locations`。
  - 順序：`normalizeMods`、`applyContent`、局部匯入的沙盒（`analyzeSource`、`precheckImport`）都要**最先**套用地下城，再套用特殊地圖、任務、事件、物品，以及怪物的出現地點（`applyPlacements`）。不然這些內容整理時會因為「地點不存在」被拿掉。
- **還原**：`mods.ts` 的 `snapshot` 要補上 `geography.locations`、`geography.routes`、`dungeonEncounters`、`lighting.locations`，以及還原的步驟。
- **要重建的快取**：`data.ts` 的 `locationIndex`，以及 `world.ts` 的路線鄰接表 `adjacency`；兩個現在都只在載入時建一次。聚落用的快取（房子、主人的家、城鎮區塊）地下城用不到。
- **刪地下城時遭遇表一定要一起拿掉**：`guild.ts` 碰到「有遭遇表、沒有這個地點」會丟錯。
- **依賴檢查**：
  - 新寫 `dungeonUsage`（第 2.2 節的表，加上第 6 節的存檔），`stores/content.ts` 的 `usageOf` 加上地下城。
  - 怪物的使用檢查加上「自建地下城用到」。
- **改成擋下**：特殊地圖的所屬地點不見時現在默默改成第一個地點，要改成報錯。
- **局部匯入與匯出**（`contentRefs.ts`）：
  - `REF_SECTIONS` 加上地下城。
  - `scan` 和 `rewriteRefs` 要認得 `dungeon:<地點>:<層>`、`boss:<地點>:<層>`、`dungeon/<地點>`，把它們對應回地下城的 id。
  - 世界包只是帶著 `content`，會跟著走。

### 5.2 編輯器

- 第 3 節的畫面。遭遇組沿用怪物編輯器的元件（`MonsterPick.vue`），光線與出現條件沿用現有的元件。
- 怪物編輯器的「出現地點」（`mods.ts` 的 `tableOptions`）加上自建地下城。
- 其他編輯器的地點選單（特殊任務、事件、特殊地圖、物品的情報）都是直接讀 `geography.locations`，套用之後就有。這些選單是打開編輯器時算一次，換頁回來就會更新。
- 怪物編輯器的篩選「出現地點」加上自建地下城。

### 5.3 存檔的保護

- **刪除前**：**目前的存檔**有下列情況時擋下：
  - 人在這座地下城裡，或正在往返的旅途上
  - 待處理的移動或戰敗指向它
  - 進行中的公會委託以它為目標
  - 有效的情報指向它
- **生成的冒險者的出沒**：不擋，套用時與讀檔時把不存在的地下城從 `haunts` 拿掉。冒險者很多，擋了會讓玩家刪不掉。
- **其他存檔**（讀檔時才知道），新增 `pruneLocations`：
  - 人在不見的地下城裡：送回路線另一頭的聚落，找不到時送回出生地，再不行送回索里耶爾。
  - 地下城探索、旅途、待處理的移動、戰敗：作廢。
  - 以它為目標的委託：中斷（同「放棄」，但不扣聲望）。
  - 情報：拿掉。
  - 各層的地圖：拿掉。
- **顯示用的地方**（日誌、記憶）：改用不會丟錯的查詢，找不到時顯示「（已消失的地點）」。

## 6. 其他要注意的地方

1. **地區要選現有的**：`regionById` 找不到會丟錯；旅行面板依地區分組，地區不在清單裡的地點會直接消失。
2. **建議階級、委託的等級都來自遭遇表裡的怪物等級**，沒有「整座的難度」（[DUNGEON_DESIGN](../../DUNGEON_DESIGN.md) 第 1 節）。等級亂排（淺層比深層強）不會壞，但委託和建議階級會看起來怪，所以給提醒。
3. **公會委託看路線**：只有 7 天內的公會會發這座的清剿與材料委託，情報也是 7 天內。路線太長的地下城不會有委託。
4. **冒險者 NPC 會自動在這裡出沒**（相鄰、沒有出現條件的地下城），所以存檔裡會留下這座的 id；第 5.3 節要清理。
5. **世界地圖畫不到**：世界地圖是固定的一張圖，旅行面板照樣列得出來。
6. **背景圖**：用地區的背景圖；之後要開放上傳，要沿用類別圖示的縮圖與容量警告（世界存在 localStorage）。
7. **不能做成園區**（緋夢樂園的 `park`）：園區有自己的入口廣場、印章與規則。
8. **寫死的地點**（起始地點、預設出生地、預設的「索里耶爾」）都是聚落，地下城不受影響。
9. **套用之後要 `bumpContentRevision()`**，怪物圖鑑的棲地等依內容版本的快取才會重算。

## 8. 之後：自建聚落（盤點結果，先不做）

聚落比地下城多出這些：

- **區塊**：沒有專屬地圖時用類型範本；要自己畫的話沿用特殊地圖的畫筆，改用城鎮圖例。
  - 至少要一個城門，每個區塊連得到城門，貴族區與王城要有勢力。
  - 區塊 id 存檔後不能改。
  - 改區塊前要檢查擺在上面的地標、商店、NPC 固定格子、特殊地圖通道、任務點的格子，以及要公會或情報商開頭的任務。
- **依類型或地點的資料**：
  - 依類型：店的等級與物價、居民人數、房子、打造等級、城鎮事件。
  - 依地點：魅氣、奴隸市場、路人職業、店名的個別設定。
  - 依勢力：通緝、警戒、王城。
- **被引用**：地標、商店、固定 NPC（地點會默默改成索里耶爾，要改成擋下）、特殊地圖的通道、城鎮事件、任務開頭的公會或情報商。
- **存檔**：除了第 2.3 節，還有主人的家、居民名單、在這裡生成的 NPC、房子、出生地、依地點記的酒館、市場、店的庫存、警戒、通行。
- **快取**：`homes.ts` 的 `lotCache`、`manorCache`，`masterHome.ts` 的 `layoutCache`，`grid.ts` 的 `baseBlocks`、`blockKinds`。
- **自建聚落之間的路線**：B 只接在 A 上時，刪掉 A 就到不了 B。
