# 地點編輯器計畫：自建地點、路線與城鎮區塊

> 上層：[ROADMAP](../ROADMAP.md) R16。2026-11-02 盤點。這份計畫只寫還沒做的部分；做完的寫進 [CONTENT_EDITOR](../../CONTENT_EDITOR.md)、[CONTENT_DEPENDENCIES](../../CONTENT_DEPENDENCIES.md)、[WORLD](../../WORLD.md)，從這裡刪掉，最後在[已完成](COMPLETED.md)記一段。
> 相關：[點子庫](../ideas/early-design.md#i12) I12（世界頁籤補上還不能改的資料）、[worldgen/README](../../../worldgen/README.md) 守則 5（現在地點不能新增）、[EAST_CONTINENT_PLAN](EAST_CONTINENT_PLAN.md)（R15）。

## 1. 範圍（使用者的要求）

1. **只能新建地點**：內建的地點、路線、地區不能改。
   - 自建地點和特殊地圖不同的地方在於：它是世界圖上的一個點，**一定要經由旅途到達**（有自己的路線），不是從某個地點的牆走進去。
2. **和其他世界內容連動，功能接近原版地點**：聚落有區塊、設施、居民、近郊；地下城有分層的遭遇。特殊任務、固定 NPC、地標、商店、事件都可以選它。
3. **特殊地圖可以接到它的區塊上**；被接上之後，這個地點就因為有人用到而**不能刪**。

## 2. 世界內容的依賴關係（全部盤點）

箭頭表示「A 用到 B」。分成七層：上層用到下層，**刪除時要由上往下**才不會擋住。★ 是這次新增的地點、路線、區塊。

```
L6 存檔 ─────────── 所在地、地圖格子、隊伍、行囊、委託、情報、主人的家、房子、登場過的 NPC……（幾乎用到下面全部）
                     │
L5 劇情與事件 ─────── 特殊任務 ─┬─ 旅途／城鎮／地下城事件 ── 主奴與娼館的事件 ── 情報物品
                     │         │
L4 人 ────────────── 固定 NPC（出沒地點、固定格子、依旗標改變出沒）、小隊
                     │
L3 疊在地圖上的 ───── 地標（含內部）── 商店（擺放、搬移）── 特殊地圖（所屬地點、通道）── 房子與空地
                     │
L2 地點裡的空間 ───── ★聚落區塊（固定地圖或範本）── 地下城的各層（遭遇表、層主、光線）── 近郊（地區的城郊遭遇表）
                     │
L1 世界骨架 ───────── ★地點 ── ★路線 ── 地區 ── 勢力
                     │
L0 基礎內容（不依地點）─ 怪物 ── 物品 ── 底材、材料 ── 技能 ── 狀態 ── 特質 ── 刺青與印記 ── 劇情計數器、旗標
```

L0 不屬於任何地點，但會被 L2 的遭遇表與 L3～L5 的內容用到。怪物的「出現地點」寫在怪物身上，但寫的是 L2 的遭遇表。

### 2.1 L1 世界骨架：地點用到的東西

| 地點的欄位 | 誰會讀 | 沒有時 |
|---|---|---|
| `region` 地區 | 城郊遭遇、魅氣、曝露名聲（存檔依地區記）、NPC 種族比例、店名風格、地下城與旅途事件的地區篩選、背景圖、給 AI 的報告 | **一定要有**：`regionById` 找不到會丟錯（約 20 處） |
| `type` 類型 | 聚落／地下城是最大的分界；聚落的類型決定區塊範本、店的等級與物價、店主的打造等級、居民人數、冒險者等級、房子的種類與空地數、城鎮事件、每日成人向事件 | **一定要有**，只能是現有的 8 種 |
| `faction` 勢力 | 通緝、警戒、王城的聲望門檻；地標、刺青店、奴隸市場的聲望條件；在這裡出生的主角與生成的 NPC 的勢力；王城區的名稱 | 可以沒有：不會被通緝，王城區叫「王城」 |
| `races` 種族比例 | NPC 生成 | 用地區的預設比例 |
| `requires` 出現條件 | 旅行、任務、情報能不能經過或抵達（`locationOpen`） | 一直開放 |
| `material_series` | 寶箱與人形怪掉的裝備系列 | 用第一種材料 |
| `park` | 緋夢樂園的園區 | 一般地下城 |
| `note` | **程式不讀** | 自建地點要另外有「給 AI 的描述」（第 5 節第 4 點） |
| 路線 `days`、`mode`、`fare` | 最短路徑、旅途天數、船資、每日路費、旅途事件的種類與戰鬥方式 | 地點至少要有一條路線，不然到不了，也不會有委託和情報 |

### 2.2 L2 依地點或地區編號的資料表

新地點沒有這些項目時的行為：

| 資料 | 沒有時 | 編輯器要不要開放 |
|---|---|---|
| `maps.json` 的區塊（`maps[地點]`） | 用類型的範本（`template_by_type`） | **要**：第 4.2 節 |
| `enemies.json` 地下城的遭遇表（`encounters[地點]`） | 每層都用地區的城郊表；但**公會的清剿與材料委託、晉升考核、情報、怪物圖鑑、怪物編輯器的出現地點都不會有這座** | **要**：第 4.3 節 |
| `maps.json` 地下城的光線（`lighting.locations`） | 用共用的各層預設 | 要（簡單） |
| `lewd.json` 魅氣（`charm.locations`） | 用地區的，再沒有是 2 | 要（一個數字） |
| `npc_population.json` 居民人數、路人職業 | 依類型；路人職業沒有 | 可以之後再做 |
| `slavery.json` 奴隸市場與黑市（`markets`） | 沒有市場（也不能雇奴隸） | 可以之後再做 |
| `shops.json` 店名的個別設定（`naming.overrides`） | 照地區的店名風格 | 可以之後再做 |
| `npc_traits.json` 血統的故鄉 | 沒有加權 | 不做 |
| 背景圖 `src/assets/backgrounds/<地點>` | 用地區的背景圖 | 之後可以上傳（注意容量，第 5 節第 9 點） |
| 世界地圖 | 地圖是固定的一張圖，畫不到自建地點 | 不做：旅行面板照樣列得出來 |

### 2.3 L3～L5 引用地點的內容

這些內容寫了地點 id 或區塊 key（`<地點>/<區塊>`）。新地點被它們用到時要**擋刪除**；現在的 `usage.ts` 完全沒有檢查地點的部分，要新寫一個 `locationUsage`。

| 內容 | 欄位 | 地點不見時現在會怎樣 |
|---|---|---|
| 特殊任務 | 開頭 `start.location`（公會、情報商）、任務點 `at.location`、結果 `travel_to` | 整理時拿掉，任務檢查報錯誤 |
| 旅途／城鎮／地下城事件 | 城鎮事件的 `locations`、地下城事件的 `dungeons`、改道 `travel_to` | 篩選掉 |
| 固定 NPC | `location`、`haunts[].location`、`fixed.area`、依旗標的各組 | **`location` 默默改成索里耶爾**（`mods.ts` 的 `cleanNpc`） |
| 地標 | `location`、`at.area`、`interior` | **丟錯「地標要擺在聚落裡」**，地標沒套上，連帶用到它的 NPC 與任務出問題 |
| 商店 | `places[]`、`moves[]` | 拿掉 |
| 特殊地圖 | `location`、通道 `connections[].to.area`（城鎮區塊，或園區的 `dungeon/<地點>`） | **`location` 默默改成第一個地點**（`specialMapMods.ts`）；通道拿掉 |
| 物品 | 情報的 `intel.location` | 拿掉 |
| 怪物 | 出現地點 `dungeon:<地點>:<層>`、`boss:<地點>:<層>` | 拿掉 |
| 其他地點（★） | 自建地點的路線接到另一個自建地點 | 新的：見第 5 節第 3 點 |

不寫地點的：主奴與娼館的事件、劇情計數器、刺青與印記、印記設定、事件設定、雙面效應設定、特質的受訓地點（寫的是格子種類或地標）。

### 2.4 L6 存檔

**存檔完全沒有清理地點的程式**（現在只有 `pruneSpecialMaps` 處理 `sm/`）。`locationById` 找不到會丟錯，全專案約 265 處呼叫，所以地點一不見，用到它的存檔就打不開，或是一打開某個面板就壞掉。

- **讀檔時就壞**：
  - 所在地 `state.location`
  - 主人的家 `masterHome.location`
  - 居民名單 `rosters` 的 key
  - 在這裡生成的 NPC 的 `location`、`haunts`（每個畫面都會查）
  - 特殊地圖的回程 `special.back`
  - 旅途 `road.from/to`
  - 待處理的移動 `pendingMove`
  - 地下城探索 `expedition`
  - 俘虜 `captives`
  - 戰敗 `pendingDefeat`
- **打開某個畫面或組提示詞時才壞**：
  - 委託的委託人與目標
  - 情報
  - 日誌報告的地點
  - 冒險記憶
  - 角色的出生地
  - 住在旅店的 NPC
  - 房子
  - 奴隸契約的主人家
  - 警戒的地點
- **只是留下沒用的資料**：依地點記的酒館、市場、店的庫存、競技場、娼館等級、警戒值、城門與王城的通行、拍賣、足跡、等待、邀約、談判。
- 聲望與通緝依勢力記、曝露名聲依地區記，不受影響。

## 3. 和特殊地圖的差別

| | 特殊地圖 | 自建地點 |
|---|---|---|
| 在世界上 | 屬於某個地點，`state.location` 是所屬地點 | 自己就是一個地點 |
| 怎麼去 | 地標的入口、事件傳送、通道 | **旅途**（路線、天數、船資、旅途事件）；可以設出現條件 |
| 能不能出發旅行 | 不能 | 聚落從城門、地下城從出口 |
| 設施 | 擺在地圖上的商店 | 區塊上的所有設施：旅店、公會（委託、晉升考核）、酒館（雇傭）、神殿、娼館、民宅、待售空地…… |
| 居民 | 只有固定 NPC | 照類型生成居民、冒險者，也有固定 NPC |
| 近郊、地下城的層 | 沒有 | 聚落有近郊；地下城有周邊到底層 |
| 地圖 | 一張 | 聚落可以有好幾個區塊（一般、貴族區、王城） |

## 4. 要做的事

### 4.1 L1：資料、套用與快取（沒有介面，先做）

- **資料**：`ContentMods.locations`（舊的自訂內容沒有這一欄，讀取時補上）。
  - 每一筆：id（一律 `loc_` 開頭，`contentRefs.ts` 的 `byId` 會把任何字串當 id 比對，要有前綴才不會撞名）、名稱、地區（只能選現有的）、類型、勢力、種族比例、出現條件、給 AI 的描述、魅氣、光線。
  - 路線：寫在自建地點身上，可以接內建地點或其他自建地點，內建的路線不動。
  - 聚落另外有區塊；地下城另外有遭遇表。
- **套用的順序**：`normalizeMods`、`applyContent`、局部匯入的沙盒（`analyzeSource`、`precheckImport`）都要**最先**套用地點，再套用地標、商店、特殊地圖、NPC、任務、事件。不然這些內容整理時會因為「地點不存在」被拿掉，或被當成「整理時改了」。遭遇表也要在怪物的出現地點（`applyPlacements`）之前。
- **還原**：`mods.ts` 的 `snapshot` 現在沒有地理和地圖，要補上 `geography.locations`、`geography.routes`、`maps.maps`、`maps.lighting.locations`、`dungeonEncounters`，以及還原的步驟。
- **要重建的快取**：
  - `data.ts` 的 `locationIndex`、`regionIndex`
  - `world.ts` 的路線鄰接表 `adjacency`
  - `homes.ts` 的 `lotCache`、`manorCache`
  - `masterHome.ts` 的 `layoutCache`
  - `grid.ts` 的 `baseBlocks`、`blockKinds`

  後面三組現在從來不清，內建資料不會變所以沒事，自建地點就會用到舊的。
- **依賴檢查**：新寫 `locationUsage`（第 2.3 節的表加上目前存檔，見第 4.5 節），`stores/content.ts` 的 `usageOf` 加上地點。
- **局部匯入與匯出**（`contentRefs.ts`）：
  - `REF_SECTIONS` 加上地點。
  - `scan` 和 `rewriteRefs` 要認得組合的 key，把它們對應回地點 id：`<地點>/<區塊>`、`dungeon/<地點>`、`dungeon:<地點>:<層>`、`boss:<地點>:<層>`、`tavern:<地點>`。
  - 世界包只是帶著 `content`，加了這一欄就會跟著走。

### 4.2 L2：聚落

- **基本欄位**：名稱、地區、類型（村莊、哨站、要塞、城鎮、港口、城市、王都）、勢力、種族比例、出現條件、給 AI 的描述、路線。
- **區塊**：
  - **第一版可以先用範本**（`template_by_type`，沒有專屬地圖的內建聚落本來就這樣），先有能逛的城。
  - 第二版做**區塊編輯**：沿用特殊地圖編輯器的畫筆，圖例改用城鎮的（`maps.json` 的 `legend`：旅店、公會、酒館……城門、民宅）。內建區塊寬 5～11、高 5～7。每個區塊要設：
    - id
    - 名稱（可以寫 `{town}`）
    - 地區（一般、貴族區、王城）
    - 區塊之間的連結（`links`）
- **儲存時的檢查**：
  - 至少一個城門 `E`。
  - 每個區塊都連得到城門。
  - 貴族區、王城要有勢力，不然衛兵沒有聲望可以檢查。
  - **區塊 id 存檔後不能改**：存檔的位置與地圖的 key 是 `<地點>/<區塊 id>`。
- **改區塊會弄壞的東西**：有些內容擺在這個區塊的格子上，改了區塊要先檢查，跟特殊任務的進度檢查一樣：
  - 地標、商店、固定 NPC 的固定格子
  - 特殊地圖的通道（另一頭要是牆或水）
  - 任務點的確切格子
  - 用到公會或情報商開頭的任務（「開頭的城鎮沒有公會」）

  有問題就擋儲存並列出原因。

### 4.3 L2：地下城

- **基本欄位**：同聚落（沒有區塊）。
- **遭遇表**：周邊、淺層、中層、深層，可以多一層底層；每層一或多組怪物，加上各層的層主與護衛。這是同一份 `encounters[地點]`，怪物編輯器的「出現地點」也改得到。
  - 怪物編輯器的選項（`mods.ts` 的 `tableOptions`）只列有遭遇表的地下城，自建地下城建立時就要給一份空的表。
  - **注意**：`guild.ts` 在「有遭遇表、沒有這個地點」時會丟錯，刪掉地下城時遭遇表要一起拿掉。
- **光線**：每層一個設定，沒寫用預設。
- 建議階級、公會委託、材料委託、晉升考核、情報都依遭遇表的怪物等級自動算出來，不用另外設。

### 4.4 L3～L5：連動

- **特殊地圖接到自建聚落的區塊**（要求 3）：
  - 通道的「另一頭」選單（`CellPicker.vue`）列出所有聚落的區塊，自建的也會在裡面。
  - 選單是打開編輯器時算一次（不會即時更新），換頁回來就有。
  - 還沒有專屬區塊、用範本的聚落也接得上，但之後換成自己畫的區塊時，接的那一格可能不見，改區塊的檢查會擋（第 4.2 節）。
- **其他編輯器的地點選單**：
  - 固定 NPC、出沒、事件、特殊任務、任務點、結果、物品、建角的出生地、AI 編排特殊任務，都是直接讀 `geography.locations`，套用之後自動有。
  - 另外要確認旅行面板、出生地依地區分組時，自建地點出現在正確的一組。
- **AI 編排特殊任務**：地點清單（`questCatalog.ts`）會自動列出；要把「給 AI 的描述」一起交給它。

### 4.5 L6：存檔的保護

- **刪除前**：和其他自建內容一樣，**目前的存檔**用到就擋。
  - 要檢查的：所在地、旅途的起點與終點、主人的家、房子、進行中的委託與情報、居民名單、住在這裡的生成 NPC。
- **其他存檔**：要等讀檔時才知道，讀檔時新增 `pruneLocations`：
  - 所在地不見了：送回出生地，出生地也不見時送回起始地點（索里耶爾）。
  - 旅途、地下城探索、待處理的移動、戰敗：作廢。
  - 主人的家：換到主人所在的另一個聚落，或解除。
  - 依地點記的資料：拿掉。
  - 委託、情報：中斷。
  - 生成的 NPC：換到附近的聚落。
- **顯示用的地方**（日誌、記憶、出生地這類只是顯示名字的）：改用不會丟錯的查詢，找不到時顯示「（已消失的地點）」。比一筆筆清理存檔簡單，也不會讓舊的日誌壞掉。

  - 世界檢查（`worldCheck.spec.ts`）認得自建地點。

## 5. 其他要注意的地方

1. **地點編輯器做不出東大陸**：東大陸要新的地區和新的種族（化龍族），這兩樣這次都不開放。如果打算之後用編輯器做東大陸，要再加「自建地區」：至少要有名稱、城郊遭遇表、店名風格、魅氣、NPC 種族比例、背景圖。種族牽涉到建角、數值、外觀、奴隸與娼館，更大，建議另外做。照目前的 R15 計畫，東大陸是直接改內建資料，和這份不衝突。
2. **類型建立後不能在聚落與地下城之間切換**：兩邊的引用完全不同。任務點分聚落、近郊、地下城，NPC 只能住聚落，地標只能擺聚落。聚落之間換類型（城鎮改城市）可以，只會改店的等級與物價。
3. **自建地點之間的路線也是依賴**：B 只接在 A 上時，刪掉 A（或 A 往 B 的路）B 就到不了。
   - 儲存路線與刪除時，要檢查所有地點還連得到內建的地圖。
   - 主角正在這條路上旅行時，不能刪這條路。
4. **AI 不認識自建地點**：內建地點的設定在世界書，程式不讀 `note`。自建地點要有「給 AI 的描述」，像特殊地圖的 `desc` 那樣，放進每一則日誌的場景。也可以提供「寫成世界書條目」的按鈕；世界書在提示詞組裡，不在世界內容。
5. **有幾處現在會默默改掉引用**，要改成擋下或報出來，不然刪了地點也查不到誰壞了：
   - 固定 NPC 的地點不見時改成索里耶爾。
   - 特殊地圖的地點不見時改成第一個地點。
   - 地標丟錯之後整個沒套上。
6. **寫死的地點**：
   - 起始地點、各種族的預設出生地（`state.ts`）。
   - 好幾處預設的「索里耶爾」（`questGen.ts`、`mods.ts`、`storyMods.ts`、任務編輯器）。
   - NPC 種族比例依地區的分支（`npcs.ts`）、天氣特效依地區（`AmbientLayer.vue`）。

   自建地點用現有地區，這些都不用動；之後做自建地區時要一起整理。
7. **地區要選現有的**：`regionById` 找不到會丟錯；旅行面板與出生地是依 `geography.regions` 分組列出，地區不在清單裡的地點會直接消失。
8. **地下城沒有遭遇表也能跑**（用城郊的表），但很多功能會默默沒有，所以建立時就給一份表，編輯器提示「還沒有怪物」。
9. **容量**：世界存在 localStorage。區塊不大，但如果之後開放上傳背景圖，要沿用類別圖示的縮圖與警告。
10. **內容版本**：套用之後要 `bumpContentRevision()`，城鎮區塊的快取（`invalidateBlocks`）才會重建。
11. **出現條件**（`requires`）可以直接開放：內建的高等地下城就是靠它在劇情之後才出現，自建地點可以做成「完成某個任務後才找得到的村子」。

## 6. 分期

| 階段 | 內容 | 做完的狀態 |
|---|---|---|
| L1 骨架 | 第 4.1、4.5 節：資料、套用與還原、快取、依賴檢查、存檔的保護、局部匯入 | 用內容檔就能加地點（沒有編輯器），刪除與讀檔都安全 |
| L2a 聚落 | 第 4.2 節的基本欄位、路線、範本區塊 | 能在編輯器建一座城、旅行過去、用所有設施 |
| L2b 地下城 | 第 4.3 節 | 能建一座地下城、練等、接委託 |
| L3 連動 | 第 4.4 節；特殊地圖接上自建聚落 | 要求 2、3 完成 |
| L4 區塊編輯 | 第 4.2 節的區塊畫筆與改區塊的檢查 | 聚落的樣子可以自己畫 |
| L5 收尾 | 第 4.6 節；第 2.2 節「可以之後再做」的項目 | 文件、測試、世界生成指南 |

L1 是所有後續的前提，也是風險最高的一段（存檔會壞）。建議先做 L1，加上「刪除地點、讀舊檔」的測試，再接介面。

## 7. 待決定

1. **要不要一起做自建地區**（第 5 節第 1 點）：做了才能用編輯器做出東大陸這種新區域。
2. **第一版的區塊**：先用範本（快），還是一開始就要能畫（L4 提前）。
3. **自建地下城的遭遇表算不算「被怪物用到」**：建議算地下城自己的一部分，刪地下城時一起拿掉，不擋刪除。和現在「怪物的掉落跟著物品一起拿掉」的做法一致。
4. **其他存檔的主角站在被刪掉的地點時送回哪裡**：建議是出生地，再不行是索里耶爾。
