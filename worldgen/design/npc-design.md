# 設計固定 NPC

> 目標：玩家給出設定（或直接用世界書），Agent 能為整個世界生成一批有層次、有關係、找得到的固定 NPC。例如替晨曦王國生成國王、替萊茵帝國生成皇帝、替每個特色建築配一位特色人物。
> 格式見 [guides/npcs](../guides/npcs.md)；範例見 [worlds/elondia-plus/npcs.md](../worlds/elondia-plus/npcs.md)（85 位，就是照這份指南做的）。系統規則見 [NPC_SYSTEM](../../docs/NPC_SYSTEM.md)。

## 1. 先讀什麼

| 來源 | 要拿到的東西 |
|---|---|
| 世界書（`data/worldbook/elondia.worldbook.json`）的「區域-…」 | 每個地點的地理、特徵、社會風貌、政治角色、**特色建築** |
| 世界書的「種族-…」「区域地理与势力划分概述」 | 勢力與派系、統治者的稱號、社會結構（誰有權） |
| 世界書的「神祇信仰」 | 神職人員侍奉哪位神 |
| `data/world/geography.json` | 地點 id、類型（capital、city、town、village、port、outpost、fortress） |
| `data/world/landmarks.json`（＋玩家自建的地標） | 地標 id 與所屬地點：每個地標都該有人 |
| `data/world/npcs.json` | 已有的固定 NPC：新角色可以和他們有關係，但不要重複他們的身分 |
| 玩家的設定（[templates/world-template.md](../templates/world-template.md)） | 指定的統治者、主角相關的人、想要的角色 |

**世界書裡已經有名字的人物一定要用那個名字**（例如魔王「赤翼之君」莉莎爾、萊茵帝國皇帝「奧托三世」），性格與事蹟也照世界書寫。

## 2. 依聚落配角色

每個聚落先列出「應該有誰」，再填人。下表是起點，依世界書的社會結構調整（例如阿爾貝納沒有君主、由議會執政；玉璘族由四殿輪理；貓魅族是母系部落）：

| 聚落類型 | 一定要有 | 視情況 |
|---|---|---|
| 主城（capital） | 統治者（國王、皇帝、魔王、議會首席、族長……）、主要宗教的首長、統治者的左右手（宰相、總管、繼承人） | 學院院長、軍隊將領、冒險者公會分會長、反對派 |
| 城市（city）、要塞（fortress） | 當地的實際掌權者（領主、將軍、氏族之主） | 神職者、商會首腦、情報頭子 |
| 城鎮（town）、港口（port） | 一位有影響力的地方人物（旅店老闆、議會代表、碼頭老大） | 密探、公證人、商人 |
| 村莊（village）、哨站（outpost） | 村長或隊長 | 獵人、嚮導、藥婆、想離開村子的年輕人 |
| **每個地標** | 一位和地標的性質相符的人：神殿配祭司、工坊配匠人、議會廳配議員、市集配商人、鬧鬼的地方配守墓人或聽魂者 | |

一個勢力的高層至少兩個人，而且意見不完全一致（統治者與反對派、保守派與改革派）：世界書裡寫到的派系對立，都該有人代表。

## 3. 分層：等級、能不能雇用、在哪裡

| 層 | 誰 | 等級 | 雇用 | 出現的方式 |
|---|---|---|---|---|
| A 統治者與勢力首領 | 國王、皇帝、魔王、族長、議會首席 | 14～18 | `unhireable` | 王座、議會這類地標；沒有地標時活躍地點設王城（`palace`）或貴族區（`noble`） |
| B 機構首長 | 大祭司、院長、將軍、議員、殿主 | 9～13 | `unhireable` | 所屬的地標；沒有時活躍地點設神殿區（`temple`）、貴族區 |
| C 地標與特色人物 | 旅店老闆、交易所主人、守井人、匠人、密探 | 5～10 | 部分可以（`hire_cc` 照同等級的要價） | 地標，或在城裡走動 |
| D 鄉間與基層 | 村長、獵人、嚮導、學徒 | 3～7 | 大多可以 | 聚落裡走動（`town`） |

- **等級要配得上身分**，也要配得上世界書的力量體系：傳奇人物 17～18、一國之主 14～16、一方首長 10～13。等級越高，主角越不可能用武力解決他們，這是對的。
- **職業**照身分挑：統治者不一定是戰士（女王可以是吟遊詩人，議會首席可以是普通人）；神職者是牧師或聖騎士；德魯伊給自然信仰；密探、掮客是遊蕩者。
- **普通人**（`kind: commoner`）沒有職業、不能戰鬥，適合商人、議員、老闆娘；要寫 `occupation`。
- **出現的方式**：A、B 層盡量用地標（玩家找得到、也符合身分）；同一個地標可以有一位就好，不要擠。很少露面的人（間諜、隱士）用好幾個地點的活躍地點，讓他「偶爾出現」。

## 4. 每個人要寫什麼

| 欄位 | 寫法 |
|---|---|
| 名字（12 字內） | 依種族的命名習慣：人類用西式音譯（中央平原的帝國帶「馮」）；精靈用優雅的長名；矮人用「名・氏族」（鐵爐、灰岩、銅鬚、迷石）；魔族用尖銳或古雅的音譯，有稱號的加「」；貓魅族用短而有力的名字；玉璘族用和風、中國風的兩字名（櫻汐、璃月） |
| 性別 | `male`、`female`，少數用 `unknown`（神秘、非人的角色）或其他（見 guides/npcs） |
| `personality`（160 字內） | **三件事**：主要個性、說話或行為的習慣、一個矛盾或弱點。AI 會照這段寫他說話的樣子 |
| `appearance`（240 字內） | 一眼看得出種族與身分的外觀：體型、髮色、服裝、一件標誌性的物品 |
| `background`（400 字內） | 他的位置怎麼來的、現在在煩惱什麼。**最後一句留一個鉤子**（「他說封印之門後面傳來敲擊聲」）：這是之後特殊任務的種子 |
| `faction`、`lineage` | 勢力（世界書的勢力名稱）與出身（氏族、部落、派系、殿） |
| `tags` | `royal`（皇族，只在主城）、`noble`、`bishop`／`priest`、`merchant`、`good`／`villain`、`traveler`、`commoner`。`good` 與 `villain` 不要同時給 |
| `relations` | 和 1～3 個人的關係（新的或內建的 NPC id）。**關係要雙向**：A 寫了 B，B 也寫 A（內容可以不同：「他的利刃」對「他效忠的是教義，不是教皇本人」） |

## 5. 關係網

一批 NPC 寫完之後，畫一張關係圖檢查：

- **每個勢力內部**至少一條張力（統治者 ↔ 反對派、父女意見不合、保守派 ↔ 改革派）。
- **勢力之間**至少一條線（密探、筆友、生意夥伴、政敵）：讓玩家在一個地方聽到另一個地方的人。
- **內建的 NPC**（莉娜、波林、瑟琳、艾爾溫、凱、米菈）至少各有一個新的親戚、上司或冤家，讓舊角色和新世界接起來。
- 沒有任何關係的人只能在 D 層。

## 6. 和特殊任務接起來

設計 NPC 時就標出「會牽動特殊任務的關鍵人物」（範例清單用 ⭐）：

- 統治者與反對派：主線、地區故事線的發起人或對手。
- 背景最後一句的鉤子：角色任務線的起點（[story-design](story-design.md) 第 3 節）。
- 需要在任務進行中搬家或消失的人：用 `stages`（依劇情旗標改變出沒）或 `requires`，在 NPC 這邊先想好。

## 7. 步驟

1. 讀第 1 節的來源，列出所有聚落與地標。
2. 照第 2 節替每個聚落列出角色欄位，世界書有名字的先填。
3. 寫規劃清單（`worlds/<代號>/npcs.md`）：每個地區一張表，欄位照範例（名字、種族性別、職業等級、層、出現、身分與性格、關係），最後一張統計表。**先給玩家看清單**，確認後再做成資料。
4. 做成資料：每個地區一個分檔 `parts/npcs-<地區>.json`，照 [guides/npcs](../guides/npcs.md) 的格式。
5. `node worldgen/tools/build-world.mjs <代號>`，跑世界檢查，修到沒有錯誤與「整理時改了」。
6. 檢查清單：每個地標都有人、每位 A／B 層都 `unhireable`、關係都雙向、沒有和內建 NPC 同名。
