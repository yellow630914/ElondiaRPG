# 設計特殊任務

> 目標：玩家給出設定（或直接用世界書），Agent 能為整個世界生成主線、支線、角色任務線、獨特物品任務……而且每一條都接得起來、找得到、會完成。
> 格式見 [guides/stories](../guides/stories.md)；範例見 [worlds/elondia-plus/stories.md](../worlds/elondia-plus/stories.md)（37 條，就是照這份指南做的）。系統規則見 [STORY_QUESTS](../../docs/STORY_QUESTS.md)。
> **先做固定 NPC**（[npc-design](npc-design.md)）：任務的委託人、對手、同行的夥伴幾乎都是固定 NPC。

## 1. 先讀什麼

| 來源 | 要拿到的東西 |
|---|---|
| 世界書的地區、種族、勢力條目 | **對立**（誰和誰在爭什麼）、**傳說**（地下城的背景、特色建築的傳聞）、**謎團**（神祇、巨龍、創世之戰） |
| 這個世界的固定 NPC 清單（`npcs.md`） | 每個人背景最後一句的**鉤子**，以及 ⭐ 標記的關鍵人物 |
| `data/rules/enemies.json`（＋包裡的怪物） | 每個地下城每一層有什麼怪、幾級：戰鬥任務點要用得上 |
| 地點的設施（[guides/npcs](../guides/npcs.md) 第 3.2 節） | 哪座城有情報商、神殿、鐵匠鋪：`cell` 任務點與情報商開頭要用 |
| 玩家的設定（[templates/world-template.md](../templates/world-template.md)） | 主線的方向、想要的任務種類、獨特物品 |

## 2. 任務的四種骨架

| 種類 | 長度 | 開頭 | 怎麼接 | 範例 |
|---|---|---|---|---|
| **主線** | 每章 3～5 個任務點，4～6 章 | 第一章找固定 NPC（`npc`）或公會；之後的章 `manual` | 每章完成報酬放 `{ "type": "start_story", "story": "<下一章>" }`；階級一章升一級 | 龍影之兆：E → D → C → B → A，走遍五個地區 |
| **地區故事線** | 2～4 個任務點 | 勢力裡的 B／A 層 NPC | 獨立；結局用選擇讓玩家站隊（聲望、親密度不同） | 真理之鏡的裂痕、血角的戰書、大祭禮的繼承 |
| **角色任務線** | 1～3 個任務點 | 那位角色，`min_affinity` 10～20 | 獨立；報酬以親密度、記憶為主，錢少 | 莉娜：回到沙堡、凱：無面的帳 |
| **獨特物品任務** | 2～4 個任務點 | 情報商（`informant`）、旅途（`travel`）或擁有線索的 NPC | 完成報酬給那件獨特物品（`gear` 或包裡的 `items`） | （見第 5 節） |

另外兩種常用的小任務：**人物任務**（D 層 NPC 的鉤子，1～2 個任務點，F～E 級）與**地下城傳說**（地下城背景裡的謎，B 層 NPC 委託，戰鬥在那座地下城的某一層）。

**數量的參考**：每個地區至少 2 條地區故事線；每位 A 層、⭐ 的 B 層 NPC 至少出現在一條任務裡；內建角色各一條；地下城傳說挑背景最有故事的幾座。

## 3. 從鉤子到任務

1. **挑一個鉤子**：NPC 背景的最後一句（「他說封印之門後面傳來敲擊聲」）、世界書裡的傳聞（「傳說只要有足夠金幣，連惡魔契約都能成交」）、地下城的背景。
2. **問三個問題**：誰想要什麼？誰擋在中間？玩家的選擇會讓誰高興、誰不高興？
3. **排任務點**：開頭（委託人說明）→ 調查（判定或到某處看）→ 衝突（戰鬥或交涉）→ 結局（選擇，或回報委託人）。
4. **至少一個選擇**：地區故事線與角色任務線的結局盡量是 `choice`，每個選項的報酬不同（聲望給不同的勢力、親密度給不同的人）。不要做成「對」與「錯」，做成兩種代價。
5. **埋伏筆**：主線的線索可以藏在支線裡（龍影之兆的「七道裂痕的圓環」也出現在礁光柱、瑟琳的任務裡），讓世界感覺是連在一起的。

## 4. 任務點怎麼寫

| 種類 | 什麼時候用 | 注意 |
|---|---|---|
| 劇情（`story`） | 見面、發現、回報 | 一條任務不要連續三個劇情任務點，玩家會覺得只是在跑腿 |
| 判定（`check`） | 調查、說服、技巧 | DC：一般 12～15，困難 16～18（[balance/stories](../balance/stories.md)）；**失敗也要讓任務往前走**（`fail` 設同一個旗標，只是結果差一點），除非你希望玩家重試 |
| 戰鬥（`combat`） | 地下城、伏擊、決鬥 | 怪物等級對上階級（[balance/stories](../balance/stories.md)）；放在地下城的那一層要用那一層有的怪；可以加 `allies` 讓 NPC 一起打。`foes` 被打倒就是**死了**，不要用之後還要出場的人 |
| 選擇（`choice`） | 站隊、結局 | 選項可以有自己的判定；每個選項都要能讓任務往前走或完成 |

- **地點**：委託人用 `at.where: npc`（跟著角色走，最不容易找不到；小隊的隊員不要寫 `at.location`）；有地標的地方用 `cell` 加地標 id；戰鬥用 `dungeon` 加層、或 `outskirts`；固定特殊地圖可以指定格子。`settlement` 一進城就會擋住玩家，只給結局的選擇這種「在哪裡都行」的。
- **緊急**：走到任務點都要先處理；一般的任務點玩家可以「稍候」，`urgent: true` 只能處理或放棄，只給旅途上、臨時地圖裡過了就沒有的場面。
- **臨時地圖**（`side_map`）：裡面的任務點要一次做完，出去就等於放棄；旅途上（`road`）的任務點之後每趟旅途都會觸發，每個結果都要推進旗標。詳細的坑見 [guides/stories](../guides/stories.md) 6.4 節。
- **文字**：`text` 是給玩家與 AI 的場景，寫出看到什麼、誰說了什麼（AI 會照它寫正文）；結果的 `text` 寫發生了什麼與下一步的線索。title 寫出「去哪裡做什麼」，冒險筆記上會顯示。
- **旗標**：`<簡稱>_start`（開頭）→ 每個任務點設一個新的旗標 → 下一個任務點 `requires` 它。簡稱整個世界不重複。

## 5. 獨特物品任務

1. 先在包裡做那件物品（[guides/items-gear](../guides/items-gear.md)：`items` 的獨特物品，或 `gear` 效果的裝備規格），效果照 [balance/items](../balance/items.md)。
2. 物品的來歷寫進任務：誰做的、為什麼失落、現在在哪裡（通常是某座地下城的某一層，或某位 NPC 手上）。
3. 開頭用情報商或旅途事件（「買到一張藏寶圖」），最後一個任務點是戰鬥，完成報酬給物品。
4. 一個世界的獨特物品不要多（每個地區 1～2 件）。

## 6. 報酬

- 照 [balance/economy](../balance/economy.md)：完成報酬的金錢是階級一般委託的 1～3 倍；主線最後一章可以到上限。
- 經驗值參考：E 200～250、D 400～450、C 900、B 1,800～2,000、A 5,000。
- 選擇的分支用聲望（勢力 id 見 `geography.json` 的 `factions`）、親密度與記憶區分；不要讓某個選項明顯「賺最多」。
- 讓 NPC 入隊：任務中用 `join`／`leave`（任務同行，不佔名額，同時最多 2 人）；任務結束後正式入隊用效果 `companion`（冒險者才能戰鬥；普通人入隊只是同行。隊伍滿了就不會入隊；指定小隊的人時整隊一起來）。
- 重要的委託人可能被玩家殺掉（任何冒險者都能偷襲、處決），任務需要的角色死了任務就失敗；不想冒這個險就讓委託人是普通人，或開頭改用公會。

## 7. 步驟

1. 讀第 1 節的來源，列出每個地區的對立、傳說、謎團與 NPC 的鉤子。
2. 決定主線的方向（玩家的設定優先），切成 4～6 章，每章一個地區。
3. 寫規劃清單（`worlds/<代號>/stories.md`）：每條任務的名稱、階級、開頭、任務點、報酬。**先給玩家看清單**，確認後再做成資料。
4. 做成資料（`parts/stories.json`，可以分成好幾個檔），照 [guides/stories](../guides/stories.md)。用腳本產生時，把規劃清單也從同一份資料產生，兩邊才不會不一致。
5. `node worldgen/tools/build-world.mjs <代號>`，跑世界檢查：有錯誤的任務整條不會匯入，一定要修到 0。
6. 檢查清單：每條任務都會完成；開頭旗標不重複；`manual` 的任務都有人開啟；每個 `cell` 任務點的設施在那座城都有；每個 ⭐ NPC 都有任務；再對一次 [guides/stories](../guides/stories.md) 6.4 節的執行時的坑（緊急、`settlement`、旅途與臨時地圖、`foes` 會死、小隊）。
